# CMV9 场景影片：静态底图、创建与段播放

证据仅绑定 `cmvs64.exe` SHA-256 `dc74d2001387ae1aefbdc4204216de5ebb9d3896009280720c4e7a91b42d84f5`。
当前实现静音、24 位 CMV9 的独立帧解码、`0x2308` 创建绑定与 `0x2309` 默认模式的段播放/循环；其他槽控制、播放模式和音轨仍未实现。CMV5..8、带音轨 CMV9 与其他创建变体仍显式报错/未处理。全屏 OP 保留既有 CMV6 路径。

## 容器

前 44 字节沿用 CMV 字段：签名、资源偏移、文件长度、保留字、最大序号、帧率分子/分母、宽、高、位深、音频标志。`max_sequence + 1` 个 20 字节索引项紧随其后，结构为序号、存储长度、解码长度、类型、资源区内偏移。只解码序号小于 max_sequence 的类型 2 项，不能把最后的保留项当作视频帧。

索引之后、资源区之前是静态数据块：u32 总长（含自身）、u16 MCU 列数/行数、`ceil(列×行/8)` 字节位图，再接底图 JBPD。位图按 256×256 纹理块、块内 MCU 行/列的顺序读取，每字节从最高位开始。位为 1 的 16×16 MCU 由底图解码，位为 0 的 MCU 由目标视频帧解码；后者以底图为背景合成。末端 MCU 可以越过名义宽高，输出裁到名义尺寸。

底图 JBPD 的表起点是 +4 字段本身，普通帧则是字段 + 4；普通帧 +44 是纹理块更新位图，独立解码不使用它跳过输出。两者沿用已有频率树、DC 差分、AC 游程、量化、整数 IDCT 与颜色转换。+36 是实际 DC 数量，必须等于本次存在的 MCU 数×6。带 bit 12 的普通帧布局表后有 u16 字节长度及复用位图；独立帧路径跨过它并解码所有动态块，不依赖前一视频帧。

所有文件/像素受既有 64 MiB 研究上限约束，索引另限最多 2^20 项；边界、掩码、网格、DC 数量或位流不符均报错。这不是整个进程的峰值内存保证。`cmv9::Cmv9Index` 为核心入口；当前 `cmvs-cmv` CLI 仍仅接受 CMV6。

## 0x2308 创建与所有权

`0x14007ef20` 读取 SP-4 影片槽、SP-8 场景槽、SP-12 文件名及 SP-20 初始帧，完全不读 SP-16；返回 `0x4014`，不写系统结果寄存器。

- 三个影片槽位于引擎 +4480，场景槽仍在 +1976。原版销毁目标影片槽和目标场景槽，分别创建播放器和场景对象。
- `0x1400390b0` 以模式 2 经 +4824 的四项资源列表打开文件；该列表由 `0x201a / 0x140071c40` 注册，读取见 `0x1400380d0`。Rust 新增独立 SceneMovie 资源族，复用目录/CPZ6 校验与路径约束。
- 播放器构造 `0x1400383c0` 令活动状态 +48 为 0；打开设置 +64=-1，`0x140038f70` 解码指定初始帧，将其绑定为普通不透明图像，并建立全图矩形的默认 DrawState。创建不自动播放。
- `0x230a` 仅销毁播放器，留下场景对象及最后的图像；更换同一播放器的场景绑定也不删除先前绑定的其他场景槽。

原版缺失文件仍留下部分对象，越界影片槽仅写引擎错误位；Rust 对这些分支报错并保留 PC/SP、结果寄存器与旧对象。资源与解码全部成功后才提交。场景槽限 0..255，名称额外限 63 字节（研究工具策略，原版 +300 的 lstrcpy 未检查边界）；跨影片槽覆盖同一对象的悬空绑定风险显式报错。其他命令销毁/重建绑定对象时的完整播放生命周期尚未建模，播放控制仍未接入。

## 证据与验证

`0x140039c90` 读取 CMV9 静态块；`0x1400388c0` / `0x1400b1200` 建立静态图像；`0x140038640` / `0x1400b19c0` 覆盖动态块；`0x140039a90` 取得目标帧数据。相关原版实现只用作语义核对，不复制为运行核心。

真实 `bg620a.cmv`（CPZ6 校验读取）为 1820×1024，75 个视频帧，静态位图有 5436 个置位 MCU，1860 个动态 MCU。第 0、1、37、74 帧 RGBA 与独立 Python/NumPy 的 SSE IDCT 对照逐字节一致；第 0 帧 SHA-256 为 `2fb3d43438a13082965e7c61e594f53e4e4ae163a388309811da7badff0d6633`。原 CMV6 OP 第 0、1000 帧仍与此前 Python 输出一致。

合成测试覆盖静态/动态拼接、非 16 倍数宽度裁边、复用位图、坏索引/掩码、资源族与四槽限制、创建/销毁所有权及失败时的旧状态保留。真实数据、Python 对照、帧和日志均在 Git 忽略目录 local，不进入仓库。

鼠标/Enter 各 241 次点击重放均完成一次 0x2308：影片槽 0 绑定场景槽 28，初始帧 0 的像素与独立对照一致。随后分别在 1692972/1693012 步到 `sn1001.ps3 / PC=0x2bc3c / 0x2049`、SP=36，比旧停点多 41 步。新停点尚在设置绘制属性，不能把初始帧解码成功当作场景影片已开始播放。


## 0x2309 段播放与默认帧更新（2026-10-28）

`0x14007f2c0` 读取 SP-4 影片槽、SP-8 段号、SP-12 起始帧、SP-16 结束帧、SP-20 循环标志，返回 0x4014，不写结果。空影片槽只回收参数（不读取循环值）；越界槽的原版错误位仍以显式错误代替。段号限 0..15，来自 +60 起 208 字节状态中的 16 字节头部与 16×12 字节记录。

`0x1400385a0` 写三字段段记录，结束帧 -1 映射为 max_sequence−1。未活动时设置 current、重置 elapsed、保存当前时钟、清 pending、置 active；活动时仅设置 pending。它既不立即跳到起始帧，也不清除 paused；自然完成之后的再次启动仍需尚未接入的恢复控制。

`0x140039330` 默认模式 0：暂停或不活动时返回。取无符号时差并钳到 1000ms，累加 u32 elapsed；计算 `steps=(elapsed*rate)/1000/rate_time`，再减去 `1000*steps*rate_time/rate`，每个乘积均为 u32 回绕。到段尾时优先切 pending（start=-1 或等于当前帧则递增一帧），其次循环回 start，否则 active=false、paused=true 并保留末帧图像。每次仅解码最终变化目标，不逐帧解码跳过的中间帧。研究工具另限制单次最多 65536 个逻辑帧步；非法目标、解码失败或绑定对象已被删除/替换时显式报错，保留该槽旧图像、帧和播放计时。

主循环 `0x14000e400` 在 VM/场景效果前更新三槽；Rust 两个帧入口同样在序列与场景前推进槽。MovieHost 独立 u32 毫秒时钟供脚本启动和帧更新共用，不使用回调 tick。静态底图在创建时解码并保留，动态帧复用同一底图，不从上一动态帧累积；原始数据不变，目标帧重新构造新图像后再提交。

当前只接入新建播放器默认的模式 0、静音 CMV9 与 0x2309；暂停/恢复、其他控制命令、模式 10/15、音轨仍未接入。移动或替换绑定对象的完整身份生命周期未建模，检测到失效绑定时不会静默覆写别的图像。

新增合成测试覆盖时间余数、末帧停留、循环/延迟换段、无立即跳转、保留暂停状态、空槽、越界/短栈、绑定失效/解码失败重试，以及 u32 时钟回绕和单次时差钳位。实际 bg620a.cmv 的循环参数是 [slot=0,key=0,start=0,end=-1,loop=1]；700 项帧号/elapsed 与独立 Python 完全一致，覆盖两次 75 帧循环。运行时第 0/1/37/74 帧与原独立 Python RGBA 一致。鼠标/Enter 各 384 次点击后到 `sn1001.ps3 / 0x16f1c / 0x2171`，2673865/2673905 步、SP=16。


新增路径呈现验证完成：鼠标重放累计 27,821 个让出帧；本轮对旧停点之后的 8,640 个让出帧逐帧调用核心呈现，并在每次新增消息等待处调用真实桌面 FontRenderer，均无提前错误，到达同一 0x2171。第 37 帧含文字的动态场景已导出目视检查，仍不作为原生窗口实测。
