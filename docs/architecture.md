# cmvs-rs 架构方向

目标是用 Rust 实现 CMVS 全平台兼容。目前有格式库、检查工具和部分单步 VM，播放器尚未实现。

模块按以下顺序建立；前期保留单个 Cargo 包，形成稳定边界后再拆 crate：

1. **格式与资源**：PS2A、CPZ6、PB3、CMV；显式小端字段、有界切片和原始文本字节。
2. **VM**：PC、标签、栈、寄存器、表达式和控制流；不依赖窗口或音频设备。
3. **命令语义**：脚本切换、消息、绘图、计时、声音、输入和状态保存，通过后端接口执行。
4. **平台后端**：图形、字体、音频、输入、时钟和文件服务；具体库尚未定案。
5. **播放器与研究工具**：使用同一核心，先桌面对照，再 Android/iOS；WebAssembly 后续评估。

核心约定：

- 未知指令显式报错，不能静默跳过或按固定两字节盲扫操作数。
- 研究结论标明静态核对、推测和动态验证；地址必须绑定文件哈希。
- 路径规范化、资源覆盖顺序、文本编码必须明确，不直接套用 Windows 行为。
- 原版存档兼容需单独研究，不提前承诺；当前 64 MiB 上限是工具策略，不是格式规定。
- 测试使用合成样本，真实游戏数据通过仓库外路径读取。
