# cmvs-rs 架构

本文描述当前代码的职责、依赖边界与执行方式；截至 2026-10-27，已接入第一话的部分场景、世界坐标动画、换图控制、相机移动、等待/换图序列及条带转场状态。逐条指令、地址与阶段性重放证据见 [VM 语义](vm-semantics.md)，历史停点不作为当前完成度。

## 目标与当前状态

目标是用 Rust 实现 CMVS 全平台支持，从《アマツツミ》的 PC 版本逐步扩展引擎版本与作品。当前已有无第三方依赖的核心、研究 CLI、Windows 原生桌面预览和可选音频后端，可以运行启动、标题、OP 循环及第一话的部分路径，尚不能完整运行剧情或恢复剧情存档。

当前入口和策略必须区分：

| 运行条件 | 当前行为与边界 |
|---|---|
| 默认快照策略 | 准备主脚本后停在引擎快照屏障；不生成不完整的存档镜像 |
| 显式 `--continue-without-snapshot`，使用当前本机系统存档 | 进入主脚本后停于 `main.ps3 / PC=0x395de / 0x22b5`，请求完整恢复 `save870.dat`；该恢复尚未实现 |
| 再显式启用 `--skip-auto-resume` | 保留磁盘存档，绕过本作启动自动恢复条件，进入标题并可开始第一话 |
| 上述预览策略，记录文字/音频、种子 0、16ms 帧增量、218 次点击重放 | 鼠标/Enter 分别在 1534031/1534071 步停于 `sn1001.ps3 / PC=0xd126 / 0x20b7`，SP=8 |
| 模式 2 场景呈现 | 已保存模式、投影参数和浮点 XYZ；相机投影与光栅化尚未接入，软件呈现器显式报错 |

Windows 已实测标题、图标/光标、键鼠交互、OP、部分剧情画面与消息等待；普通桌面权限下的品牌音效和标题 BGM 已验证。最新语音播放、震动、注音和 PB3 type 5/6 后续路径的记录重放或无窗口导出，不代表这些内容已经全部通过原生窗口实测。macOS、Linux、Android、iOS 尚未完成构建与行为验证。

## Workspace 与依赖方向

| 包 | 职责 | 依赖边界 |
|---|---|---|
| `crates/cmvs-core` | 格式、资源读取、VM、命令语义、场景状态、软件呈现、动作输入与后端契约 | 无第三方依赖；包含基于 `std` 的只读文件适配器，不调用原生窗口或设备 API |
| `crates/cmvs-audio` | Vorbis 解码、原生音频输出、源消费时钟 | 依赖 core、lewton、rodio |
| `crates/cmvs-desktop` | 窗口、物理输入、字体光栅化、帧显示与桌面运行入口 | 依赖 core、winit、softbuffer、ico、encoding_rs、ab_glyph；可选依赖 audio |
| 根包 `cmvs-rs` | 检查 CLI、`cmvs_rs` 兼容重导出、集成测试 | 默认仅依赖 core；通过 `desktop`、`audio-output` 选择后端 |

依赖方向为 `desktop → core`、`desktop → audio → core`。格式、VM 和软件呈现目前保持为 core 内部模块，不新增 C++ 运行核心。后续平台应复用核心语义，通过后端接入系统服务。

默认 workspace 成员仅为根包；全 workspace 构建会额外选择桌面和音频成员。所有项目包继承 `unsafe_code = forbid` 和严格 Clippy 约定。feature 转发、固定依赖及拆包回归证据见 [workspace](workspace.md)，参考项目提交与许可见 [references](references.md)。

## 核心职责

### 格式与资源

`ps3`、`lzss`、`cpz`、`pb3`、`jbp1`、`jbpd`、`cmv`、`cursor` 负责有界解析或解码；输出保留原始文本字节或明确的像素格式。格式层不依赖窗口和音频设备。

- PS2A 支持分段、字节变换、解压、标签与脚本装载。
- CPZ6 支持当前模式 1 的索引与文件读取；公共资源读取验证资源数据校验值，头部/索引摘要尚未核对实现。
- PB3 支持 type 1、type 3/JBP1、type 5，以及需要参考底图的 type 6；其他分支显式报错。type 5/6 已有 23 个不同真实输出与独立 Python 逐字节对照，未宣称全包覆盖。
- CMV6 与 JBPD 支持已核对的影片容器和帧解码；影片计时、画面解码和设备音轨播放分开。

`resources::ResourceArchives` 按资源族和注册槽号查找首个命中项：图像十槽，SE/BGM/语音各四槽。归档惰性打开，注册路径变化时重开；缓存键包含资源族与槽号。缺失返回 miss，坏归档、校验失败、路径逃逸明确报错。名称规则和覆盖顺序按证据实现，不套用宿主文件系统的隐式行为。

`image` 在共享读取层之上负责图像来源与解码分派，供场景、消息窗口和遮罩共同使用：

- `pb3::decode` 无 I/O；type 6 通过 `decode_with_base` 或 `image::load` 获得参考上下文，不猜底图路径。
- `image::load` 经同一 `ImageSource` 与注册源递归读取底图，拒绝循环，限制最多 16 个活动文件及累计原始/RGBA 声明长度 64 MiB。
- `image/cache.rs` 保存 `0x203f` 的下一次读取提示与原始字节 LRU，当前留存上限 32 MiB/1024 项；启动容量配置尚未接入。它与 CPZ 索引缓存及已解码 RGBA 分开。
- `ImageRead` 延迟提交 token 使底图原始字节先于外层提交；解码失败也完成该缓存提交，但不提交 VM 命令或替换旧图像。直接 raw read 在返回前提交。

上述容量是研究工具策略，不是整个进程峰值内存保证，也不应推断为格式限制。细节见 [PB3](pb3-format.md)、[JBPD](jbpd-format.md)。

### VM 与脚本控制

`bytecode` 结构化解码指令、嵌套表达式及控制流，并检查标签与直接跳转边界。`evaluate`、`vm`、`machine` 分别承担表达式状态、参数栈/调用帧和单步执行。

- `State` 保存整数、位、字符串、浮点变量与独立系统结果寄存器；未知值保持未知。原版写入但尚未核对的结果可用 `forget_system_integer` 标记，读取时显式报错。
- 表达式修改使用共享撤销日志，失败逆序恢复；不为每次求值整体克隆状态。
- `ParameterStack` 逐字节记录已知状态；栈预留不补零，读取未写入字节报错，不模拟原版残留内存。帧偏移按已核对的 i32 运算处理。
- 运行时 `Image` 持有从 PS2A 数据段初始化的独立可变数据；数据操作数和字符串引用访问同一视图，不修改原 `Script` 或代码。
- `Machine` 装载时缓存标签表，以 `Rc` 共享已解码指令；遇到未处理系统命令保留待处理状态。

`bootstrap` 应用已核对的配置、变量初始化和路径登记；`script_control` 处理公共脚本槽、初始化返回、跨脚本调用、核心切换及显式回调登记/调用。自动回调调度尚未完成。`text` 提供已核对的字符串操作及受限格式化；`random` 使用显式种子的 MSVC CRT 随机数模型。

### 场景状态与软件呈现

`scene::SceneHost` 保存清屏色、深度清除标志及 256 个对象槽；`SceneObject` 包含最多 768 个子对象槽、`ObjectImage`、绘制字段、继承标志和已实现的效果轨道。核心状态不持有图形设备。

`DrawState` 区分二维位置、世界 XYZ、投影参数和绘制模式。`0x2042` 只把已有绘制状态的模式设为 2；`0x2070/0x2071` 写投影参数，`0x2072..0x2074` 写 XYZ 原始浮点位，均保留其他属性和效果。保存这些字段并不完成模式 2 绘制。

`scene_render` 是平台无关的有界软件呈现器，支持已核对的二维裁切、原点、位置、层次、普通 alpha 合成及父/子对象排序与继承。`render_with_objects` 接收桌面生成的字形等附加对象，使场景槽、文字、可见消息窗口和 fade 按已核对的顺序进入稳定图层队列。未知变换、混合方式与尚未支持的组合显式报错。

`fade::FadeHost` 管理独立覆盖层；`scene/mask.rs` 管理两条目标槽遮罩转场通道（+4632 的 0x222a..0x222d 与 +4648 的 0x2234..0x2237，着色器路径相同，每个对象最多一条）；`scene/quake.rs` 管理已实现的震动波形；`scene/strip.rs` 管理引擎 +4640 的条带转场（0x222f..0x2233）。对象销毁不隐式清空独立覆盖层。帧推进按对象效果、对象回收、纯色 fade、条带、遮罩、震动的顺序执行。遮罩当前只作用于支持的目标图像层，CPU 改写 alpha 路径未建模；震动也只覆盖已核对的波形与队列选择；条带以 `SceneObject`/`DrawState` 保存每条纯色附属对象及结束后的全屏遮盖，只支持模式 0/2/10/12，其纯色绘制未核对，存在时软件呈现器显式报错。

`scene/world_motion.rs` 处理 `0x21f9..0x21fd` 的浮点世界 XYZ 轨道：重建、八条关键帧、播放/停止/查询，按帧推进并在负 next 结束，-2 另销毁对象。当前覆盖线性（含相对分支）与绝对二次缓出，其他插值模式显式报错。未播放轨道的未初始化头部用 `MotionPlayback::None` 表示；播放时从当前 XYZ 取基点，0x22c4 换图时转移同一轨道。

`scene/change.rs` 保存 `0x22c4` 换图转场的无着色器分支状态：新对象继承绘制字段与效果轨道，旧对象及水平居中的公共不透明区域暂时保留，按帧时间推进 fade factor，完成后释放；重复替换先取消旧转场。`0x22c5/0x22c6` 提供取消/查询，`0x22c7` 按 SkipGate 与动作输入等待或跳过；查询/重试不推进时间，取消保留新图和动画轨道。当前只支持主图像源和已有图像/绘制状态，缺失资源或未建模分支显式报错并保留命令。活动换图转场的入队/合成尚未接入，软件呈现器保留显式错误；保存转场状态不代表画面已呈现。

`camera` 保存已核对的镜头参数，并通过 `0x2056` 查询转换后的整数 XYZ（系统结果 1..3）；查询不修改相机。`0x2068..0x206d` 接入相机 0 的 XYZ/XZ/Y 移动启动、取消/结束、查询和等待，支持线性/二次缓出；帧末按原始 delta 推进相机，不使用对象轨道的 200ms 上限，其他曲线仍显式报错。当前二维软件呈现不消费模式 2 投影。`raster` 提供 RGBA、比例适配、alpha 合成与 PNG 导出；1280×720 是本作研究视口，窗口缩放与留边由后端处理。

### 消息、输入与音频

| 模块 | 核心负责 | 后端负责或当前限制 |
|---|---|---|
| `message`、`message_flags` | 八个窗口槽、十二项文字对象、样式/布局、字形记录、逐字计时、换行/注音、手动等待与跳过状态 | `--record-text` 只记录；桌面 `--font` 光栅化。转义、其他输出变体、自动送页等仍有显式屏障 |
| `history` | 有界原始文本历史记录 | 历史 UI、快照序列化未实现 |
| `buttons` | 按钮记录、显示状态、命中、导航与动作消费 | 桌面转换指针坐标并应用移动系统光标请求；选择分支尚未完整覆盖 |
| `input` | 只读 key.cfg 解析、输入码历史、24 个动作的按下/按住/松开与消费、0x21a0 族与 0x2344..0x234b 的动作查询/消费 | 桌面转换真实键鼠；动作 21 的 0x2348/0x2349 及其帧更新消费分支、手柄、注册表覆盖及其他绑定组未实现 |
| `gesture` | 指针手势配置 | 完整输入识别尚未接入 |
| `audio` | SE/BGM/语音状态、音量设置、播放/启动/停止/淡出契约 | `RecordingAudio` 只记录；可选原生后端真正解码并输出。语音长度结果 4 的单位仍未知 |
| `movie`、`sequence`、`timers` | 影片生命周期、等待/换图序列的追加、启停、执行与计时、十槽 VM 计时器 | 部分影片槽创建、其他动作序列条目及其执行仍未实现 |

`sequence::SequenceHost` 接受最多 16 项等待与换图条目；满容量仍回收参数。换图在入队时捕获名称，到执行时读取资源。启动/停止/快速结束保留已核对语义，快速结束仅执行活动序列余项并令换图时长为零。显式 u32 毫秒时钟独立于回调 tick；在对象更新前处理等待与剩余时间，不截断到 200ms。换图复用 `scene/change` 的准备/提交逻辑，失败保留旧对象及当前项，前缀成功项和时钟不回滚。重置保留 typed 不活动条目，不构建原版记录镜像；其他动作和快照序列化尚未实现。

`Startup::advance_frame` 和 `advance_decoded_frame` 均返回 Result，传播延迟加载错误，执行顺序为序列→场景；CLI trace 的帧边界同样推进序列。无资源上下文的 SequenceHost 入口遇到换图显式报错。正常真实重放已在脚本的序列等待轮询中执行两段序列（含三次换图）并自然完成；换图画面合成仍未验证。

字体文件、编码转换、OpenType 解析、字形 mask 与缓存留在 `cmvs-desktop::font`，不进入 core。当前字体后端有字号、字形数、视口、缩放及样式限制；不承诺逐像素复刻原版 GDI。输入绑定、等待边沿及音频源时钟的具体边界见 [input](input.md)、[font-output](font-output.md)、[audio-output](audio-output.md)。

### 存档与平台契约

`save_menu::SaveSource` 提供只读槽前缀；`DirectorySaves` 支持槽号 0..999，菜单扫描仍最多 256 槽。`0x22bb` 只识别 `CSV2`..`CSV9` 签名，不要求有效正文，也不代表该格式已可完整解码或恢复。

`save` 负责已核对模式的 CSV2 容器、校验、逆变换和三段解压，返回尚未恢复的快照、辅助图像与脚本内存字节。`snapshot` 能遍历第 0 段记录帧，但尚未构建完整存档镜像或恢复引擎状态。`SaveImage` 区分原版缓冲为空的 `Absent` 与本应生成但 Rust 未构建的 `Unavailable`；后续写入必须拒绝后者。

`system_save` 独立处理 CSS1：只恢复经核对的持久变量和文件名列表；候选状态完成验证后才提交。缺失稀疏变量不隐式初始化。`0x22b5` 完整剧情恢复保持未实现。格式与限制见 [save](save-format.md)、[system-save](system-save-format.md)、[snapshot](snapshot-format.md)。

`platform::PlatformHost` 解码已验证的标题、图标、光标等请求，通过 `PlatformBackend::apply` 应用；后端成功后才完成 VM 命令并提交宿主状态。`RecordingBackend` 保留请求，不能证明原生 API 已执行。`PlatformAssets`/`DirectoryAssets` 提供显式游戏根目录下的只读素材，CUR 核心保留 AND/XOR 平面与热点，原生光标转换由桌面完成。见 [platform-host](platform-host.md)。

## 运行编排与时间

`runner::Startup` 是当前《アマツツミ》研究入口的编排器：组合 `Machine`、命令宿主、只读来源和后端，借用外部 `Script`，不通过泄漏生命周期构造自引用对象。它仍含本作布局、ID 与预览策略，尚不是所有 CMVS 版本的通用播放器。

一次运行循环的职责如下：

1. 宿主在帧边界采样物理输入，转换为核心动作状态；记录输入模式不注入 VM 动作。
2. 宿主提供显式帧增量，推进场景效果、消息、影片与相机运动。原生音频模式还更新设备后端并查询源消费时钟。
3. VM 执行普通指令；系统命令由对应宿主处理，等待命令可返回 Yield，未知命令或错误保留可定位的断点。
4. 后端读取当前状态生成画面、输出声音并处理窗口事件；进入下一帧。

VM 运行、帧时间和协作预算分别管理。计时器只在首次运行或让出后恢复的入口消费一次帧增量；普通指令、预算切片续跑和未知命令重试不重复累加。桌面通常约 16ms 调度，使用实际经过毫秒；trace 通过显式 `--frame-ms` 推进。约 8ms 的桌面协作预算用于保持窗口响应，不是 VM 时间，也不保证单条指令耗时上限。回调登记 tick 是独立研究时钟。`Startup` 另有让出看门狗：自上次让出起连续执行 100 万步（可由 `set_yield_watchdog` 调整）时 tick 不执行指令并报错，桌面随即按 VM 错误关闭；累计步数不受限。它是宿主诊断策略，不是原版限制；默认值约为真实路径实测最长不让出段（9970 步）的 100 倍。

输入每帧采样，跨协作预算切片保留已消费状态；失焦清理、短按锁存、视口映射均由桌面适配处理。影片可使用原生音频源消费位置推进，它不是 DAC 硬件时间戳。

## 错误、提交与预览策略

命令宿主先验证参数、目标、资源及后端结果，再回收参数、前进 PC 并提交命令状态。表达式使用撤销日志；资源或后端错误保留待处理命令及相关旧状态，不能静默跳过未知语义或补造结果。资源缓存存在独立副作用：一次读取会消费缓存提示，解码失败也可能完成原始字节缓存提交，不把 VM 事务描述成整个进程的回滚。

`AudioBackend` 的 `Ok(true/false)` 对应已核对的装载/播放结果，`Err` 保留命令状态供重试；原生系统副作用的失败边界需由具体后端保证。`start`、`stop` 与淡出各有独立语义；例如同步停止并释放不能用清空核心通道名代替。

两项显式预览策略由 runner 管理，默认关闭：

- `SnapshotPolicy::ContinueWithoutImage`（CLI `--continue-without-snapshot`）只应用已核对的实时快照影响、清除位变量 0 并记录来源，标记镜像不可用后继续主脚本。默认 `Barrier` 保持粘性停点。
- `--skip-auto-resume` 仅在首次系统存档读取成功后清零内存整数 2198；只接受已核对的本作 ID，必须在 tick 前配置。缺失不生成变量，读取失败不消费策略，首次成功或缺失后不再干预后续加载。不修改系统存档解码语义或磁盘文件，也不伪造签名查询结果。

`--font` 与 `--record-text` 是不同显示模式；默认无字体且未启用记录时，保留 `0x2152` 输出断点。显式素材预览不修改 VM，也不作为脚本驱动画面或存档镜像。
