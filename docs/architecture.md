# cmvs-rs 架构方向

目标是用 Rust 实现 CMVS 全平台兼容。目前有格式库、检查工具、部分单步 VM 和可选桌面预览，剧情播放器尚未实现。

当前正常入口在显式继续快照、记录音频和 16ms 帧推进下完成 logo 淡入、3500ms 停留、淡出、效果音通道停止及全部对象销毁，切换到 menu.ps3 并设置标题菜单标题；完成标题淡入并经过 30 秒无输入的按钮空闲循环、BGM 淡出与停止、OP 前的清理与镜头重置后切换到 op.ps3，第 42990 次 step 以 0x20c0 计时播放 op.cmv（trace 为计时模式，桌面另解码 JBPD 帧），第 141423 次 step 播完，经 1500ms 可跳过等待回到 main.ps3 与标题，无输入时循环往复。原停点记录：op.ps3 / 0x36278 / 0x20c0（播放 op.cmv，需 --steps 400000）。

现已建立 workspace：`cmvs-core` 保存下列前三层及宿主接口，`cmvs-audio` 和 `cmvs-desktop` 保存具体后端；根 `cmvs-rs` 保留 CLI 和兼容重导出。core 无依赖，后端单向依赖 core。目录、功能转发及检查方式见 [workspace](workspace.md)。核心内部模块继续按以下层次组织：

1. **格式与资源**：PS2A、CPZ6、PB3、CMV；显式小端字段、有界切片和原始文本字节。
2. **VM**：PC、标签、栈、寄存器、表达式和控制流；不依赖窗口或音频设备。
3. **命令语义**：脚本切换、消息、绘图、计时、声音、输入和状态保存，通过后端接口执行。
4. **平台后端**：图形、字体、音频、输入、时钟和文件服务；具体库尚未定案。
5. **播放器与研究工具**：使用同一核心，先桌面对照，再 Android/iOS；WebAssembly 后续评估。

核心约定：

- 未知指令显式报错，不能静默跳过或按固定两字节盲扫操作数。
- 研究结论标明静态核对、推测和动态验证；地址必须绑定文件哈希。
- 路径规范化、资源覆盖顺序、文本编码必须明确，不直接套用 Windows 行为。
- 原版存档兼容需单独研究，不提前承诺；当前 64 MiB 上限是工具策略，不是格式规定。
- 测试使用合成样本，真实游戏数据通过仓库外路径读取。

`save_menu::SaveSource` 将只读槽头来源与 VM 命令分开；`DirectorySaves` 是使用标准文件接口的适配器。
`SaveMenuHost` 仅在读取成功并完成参数回收后替换菜单模型，I/O 失败保留待处理命令供重试。
未启用 `--save-dir` 时 CLI 不推测空存档目录，仍停于 0x22b3。
菜单头部识别与完整引擎存档兼容是两个阶段；后者仍受画面、音频和其他未实现状态影响。

`save::Csv2Layout` 只需固定头和文件总长即可先验证段范围与分配限制；
`Csv2Save` 负责校验第一段磁盘字节和解压三段，返回不解释的快照、辅助图像数据及脚本内存图像。
它不修改 `Machine`，不将缺失的引擎对象补成默认值，也不替代主切换的快照步骤。
光标名暂保存在 `Bootstrap`，显示/切换仍需单独后端。系统结果寄存器放在 `State`，与表达式结果分开。

`system_save` 独立于 CSV2：1024 字节窗口 LZSS、CSS1 头部和字节逆变换、有界字符串与列表。
`Css1Save::applied` 返回候选 State，`SystemSaveHost` 在普通命令完成后一次提交；校验或容量错误保留原状态。
来源通过 `SystemSaveSource` 注入，CLI 仅在显式 `--system-save` 时启用。
默认位容量根据已核对的 CSS1 范围改为 262144；稀疏存储中缺失值仍未知，不隐式初始化。

`PlatformHost` 解码已验证的窗口请求并调用 `PlatformBackend::apply`；后端成功后才消费 VM 参数与提交宿主状态。
`RecordingBackend` 是显式选择的研究后端，保留请求数据，不能用于证明平台 API 已执行。
原生后端必须在 Ok 时已应用请求，出错时保持状态以供重试；异步窗口循环需要自行满足这个确认契约。
`PlatformAssets` 独立提供只读资源；`DirectoryAssets` 将明确游戏根目录下的 ASCII 相对路径映射为文件。
`CursorBitmap` 保留顶向下 RGB XOR 平面和 AND 位，CPU 合成用于验证像素语义；可选原生后端将可表示的光标转换为 RGBA 显示。

`runner::Startup` 将已验证的启动处理组合为有步数上限的 tick；主快照断点是粘性的，重复 tick 不执行 main。
它借用外部 Script 并持有只读文件来源，不用自引用结构、不泄漏 Script 生命周期来绕过借用规则。
`desktop` 功能使用 winit 事件循环、softbuffer 测试画面，核心默认仍无依赖。
NativeBackend 在活动事件循环中应用窗口请求，先解码/验证数据再提交；真实窗口输入保存在有界 DesktopInput 中。
每次启动调度设约 8ms 的协作预算，单条指令耗时不保证低于预算；不与虚拟 tick、CMVS 输入或回调调度混淆。

`pb3` 负责有界头部变换、type 1 分块与分离 LZSS 流，输出经尺寸校验的 `raster::RgbaImage`。
`raster` 提供显式素材预览的最近邻比例适配与直通 alpha 合成，不承担 VM 场景图、图层或原版混合模式。
桌面 `--image-archive/--preview-image` 使用既有 CPZ6 阅读器读取唯一 basename，输出仅保留内存，不写游戏目录。
没有将预览图写入引擎快照，也没有将其伪装成脚本请求的当前场景。

`image` 是 0x2030 的图像资源视图与解码分派层（共享 I/O 已迁至 `resources`）：`ImageSource` 抽象“按名取首个命中”，`ImageArchives` 按 0x2011 注册顺序
查找目录与 CPZ6 归档（惰性打开、按槽缓存），`decode` 按魔数分派。路径校验与平台素材共用 `platform::resolve_under`。

`State` 的表达式事务使用撤销日志：写入前记录旧值，失败逆序恢复，不再整体克隆状态；嵌套求值共享外层日志。
`Machine` 在装载脚本时缓存标签表，并以 `Rc` 共享已解码指令。

`gesture` 保存 +4664 拖拽/轻扫识别对象的脚本配置，从 `PlatformHost` 迁出，因为它不涉及平台窗口请求；
原生输入尚未接入识别逻辑。

`audio` 定义 `AudioBackend`：Ok(true/false) 对应原版播放成功/失败，Err 保持状态供重试；
`RecordingAudio` 只记录请求并报告未播放。可选 audio-output 已实现原生 Ogg 后端，默认仍只记录；源消费时钟与设备延迟限制见 audio-output.md。

`snapshot` 只遍历 CSV2 第 0 段的记录帧，不解释负载，也不恢复状态。`SaveImage` 区分原版缓冲为空（`Absent`）
与原版会生成但 Rust 未构建（`Unavailable`）；后者只能由显式 `SnapshotPolicy::ContinueWithoutImage` 产生。
`Startup` 默认仍在主快照断点粘性停止；显式策略下只清除位变量 0、记录来源，然后继续执行主脚本。
将来的存档写入必须拒绝 `Unavailable`，不得写出不完整镜像。

`scene` 保存由已核对命令设置、供渲染器每帧读取的显示状态：清屏色、深度清除标志和对象槽；
0x2030 加载的图像以 `ObjectImage`（文件名、RGBA、alpha 标志）挂在对象上。
它不持有设备、不绘制；具体渲染后端读取 `ClearState` 自行实现清屏。

`scene::SceneObject` 现保留 768 槽子对象、图像、绘制字段和继承标志；0x2040/0x2050 重建绘制字段，0x2022 重建子对象，0x2038 加载子图像。
属性命令在验证完参数/对象存在性后才消费 VM 参数并更新状态。
`scene_render` 为平台无关的有界软件呈现器，当前仅支持顶层普通混合静态 2D 图像；子对象和未知呈现模式显式报错。
桌面读取这一场景输出，1280×720 为本作研究视口，窗口比例适配属于后端显示策略。默认快照断点仍保留。
首个脚本画面已在 Windows 验证：显式继续后由脚本显示品牌 logo；音频仍只记录，剧情尚未运行。

`fade::FadeHost` 保存引擎 +4616 的覆盖层生命周期，以显式 delta 推进，不绑定系统时间。
场景呈现将纯色覆盖层按原版插入顺序加入普通图像队列。`Startup::advance_frame` 和 VM tick 分离，等待返回 Yield 保留 PC/SP，完成后才回收参数。
桌面采用约 16ms 调度与实际经过毫秒；trace 只有指定 --frame-ms 才推进时间，回调登记 tick 仍独立。
当前可执行 logo 的 2000ms 黑色淡入，再通过 0x20b1 登记声音启动请求，完成计时停留和淡出、经 0x20b3 停止通道、0x202f 销毁对象后切换到 menu.ps3；输入跳过、其余音频命令和动态效果仍需逐项核对。
0x202f 只清空 `SceneHost` 对象表；`FadeHost` 的覆盖层在原版中不属于 +1976 槽表，保持独立。

`ParameterStack` 逐字节记录是否已写入：0x0440/0x442 预留的未写入字节为未知，读取即报错，不补零也不模拟原版残留旧值。
这样 Rust 能成功执行的路径都与原版一致；依赖残留值的脚本会在具体 PC 停下，届时再据证据决定是否建模。撤销日志保留被覆盖字的已知状态。
帧偏移统一经 `vm::frame_offset` 按原版的 i32 加减计算。

`message_flags::MessageFlags` 保存设置块中的跳过（+1520）与自动送页（+1552）标志，构造均为 false。跳过标志没有配置或菜单来源；自动送页还可由宿主的「自動送りの設定」对话框修改，尚未接入。
消息对象、0x2224 输入跳过与 0x22ef 将来读取它们，0x2003 复位与读档需清零。

`buttons::ButtonHost` 保存 +4504 的 6 个按钮组：每组绑定场景槽号，按钮含 ID、启用、命中矩形、导航 ID 与 4 个状态记录（子对象、裁切、原点）。
0x2215 经 `SceneHost::object_mut` 改写子对象裁切、原点与 `shown`，先校验全部目标再写入；输入命中将接入宿主输入，屏幕尺寸届时由宿主提供。
`input::ActionInput` 表示输入对象的 24 个动作标志与脚本坐标指针（键盘导航可请求移动系统光标）；按钮交互只通过它读取输入。
物理键到动作的绑定未核对前，宿主只能提供“无输入”，不得猜测映射。
`raster::RgbaImage::to_png` 以存储块 deflate 写出 RGBA PNG，供桌面导出脚本坐标下的渲染帧。
BGM 与 SE 共用 `AudioHost`/`AudioBackend`：`BgmState` 保存 +4464 对象的名称、通道与播放标志；未启用 BGM 时不访问后端。
`scene_render` 构建主队列与子列表：子对象按 0x14003de80 的规则挂在父项下或独立排序，并按 0x14003b420 的规则借用父图像、叠加父位置与不透明度。

`timers::VmTimers` 保存十槽累计值，构造为零，0x200b 只清零指定槽、0x200c 返回原始 u32。
`Startup` 在首次运行/让出后恢复的入口消费一次显式帧增量；普通单步、未知命令重试和桌面协作预算切片不再次累加。
帧增量消费后清零，未提供新帧时重复调用宿主不会复用旧时间；该计时域与回调登记 tick 保持独立。

`AudioBackend::start` 表达对已准备设备通道的条件启动；成功时可为无声音对象/已播放的无操作，失败时不提交 VM 或通道记录。
0x20b0 第五参数已确认为立即启动标志；返回值表示声音装载是否成功，不单指已经发声。

`AudioBackend::stop` 表达原版同步的“停止并释放”：返回 Ok 时该通道声音已释放，空通道为无操作，不做淡出；失败时不提交 VM 或通道记录。
与 play/start 不同，`AudioHost` 在 SE 关闭时也会发出停止请求，与原版不检查 SE_USE 一致；真实后端须容忍对空通道的停止。
