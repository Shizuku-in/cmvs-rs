## 0x23ac：字体cell前进宽度开关

case `0x14008b975` 尾跳 `0x140086ee0`：SP-4读取u32，非零归一为1，经 `0x14000a6d0` 写全局 `0x14010accc`，返回 `0x4004`，不改系统结果。该全局初值为PE零填充的0；getter为 `0x14000a6e0`。

基准构建同号case是 `0x4000` 空桩，不能登记为与根等价的 `Reviewed`。Aoitori仍为 `Unreviewed`，需要研究放行；通过稀疏表选择独立处理器，不把这项命令加入公共 `MessageHost::try_handle`。

读取影响：

- 字体缓存/光栅化 `0x14005df60`、`0x14005e020`、`0x14005e800`：开启时以GDI `gmCellIncX` 提供前进量；关闭时保留原固定cell/单字节墨迹范围规则。
- 即时输出 `0x140060a00`、渐显输出 `0x1400611f0`、辅助输出 `0x140032700`：使用该前进量；`0x814a` 浊点的特殊偏移与前进保持原分支。
- 比例模式的ruby注音存在独立分支：普通注音按实测总宽居中；等长中点串有逐个对齐分支。研究处理器现已实现，规则与边界见下节；不提升档案证据状态。

Rust新增字体cell advance接口，与墨迹宽度分开；OpenType后端取 `h_advance` 并四舍五入，字形回退与已有字体库一致。这是宿主预览策略，未证明GDI像素、粗体metrics、负bearing或缓存裁剪一致。普通输出、即时输出与辅助输出的差异代码隔离在 `message/font_cells.rs`，公共输出算法恢复基准公式，仅共享无构建判断的命令调度和叶子操作。

## 0x211d：文字像素宽度查询

case `0x140089dda` 尾跳 `0x140079950`：SP-4为文字槽，SP-8解析字符串；有效槽调用 `0x140062aa0`，系统结果0=1、1=最大行像素宽、2=行数、4=末行宽，返回 `0x4008`。基准同号命令同样为空桩，保持研究状态。

查询临时推进画笔、使用字体缓存测量，每字加水平间距；行末测试仍使用字号cell阈值，并保留原换行分支的计数重置差异。ruby只测双字节base、跳过注音。测量结束恢复原画笔，但清零ruby行标志并提交换行scratch。坏索引、缺失字体度量、畸形字符串和短栈在Rust中明确报错，保持待处理命令、参数及文字状态。比例模式使用cell advance；固定模式的单字节测量使用墨迹范围。

### 排版规则

`0x1400611f0` 的 `{base/ruby}` 分支保存每个双字节base的起点和cell advance，画笔按advance加水平间距前进；base最多32字，超出原版固定数组范围时Rust明确拒绝，候选状态不提交。单字节不绘制，仍按原循环重计最后字形的渐显时间。

比例模式先按ruby字号测量注音cell advance，不计ruby额外间距。普通注音以含末尾水平间距的base总宽居中；22.10无符号运算分别右移base总宽和注音总宽后相减，再按各注音advance前进。注音比base宽且越过零点时保留原无符号环绕，不改为有符号坐标。只有全部注音为 `0x8145` 中点且双字节数量与base相等时，改为每个base起点 + (base advance >> 1) − (中点advance >> 1)，各项独立取整。比例分支允许没有双字节注音的组，不复用固定模式的除零规则。

base与ruby使用独立的渐显延迟起点，ruby不延长后续正文的base延迟。实现仅在已选择的研究处理器中生效；根处理器的固定字号布局不变。五项合成测试覆盖居中、中点条件、无符号环绕、空注音、时序与完成重试、32字边界和度量失败原子性。证据来自前述 `semantics-x64.json`；OpenType advance仍是宿主近似，未验证GDI像素一致性。

### 粒子初始化与帧推进

下游 `0x14004f230` 经图像管理器读取效果资源；`0x14004fe20` 保存参数、按48字节记录分配粒子数组，再调 `0x14004f2a0` 初始化。每个粒子从独立对象池取得图像对象，按MSVC rand生成位置、速度、角度、十进制小数截断后的世界坐标及三种精灵列选择；精灵格为20×20、原点10×10、十格各100ms，最后回到第0格。该随机序列须与运行时CRT生成器共享，不能独立补种子或跳过初始化。

逐帧入口 `0x140043b10` 在类型5分支调用 `0x14004fab0`：无符号时钟差上限500ms，位于模式高字节的低四位选择随机范围；按角度的cos/sin推进X/Y，各增量先截断到百分之一；Y低于0时消耗新随机数重置X/Z和Y=100，再把XYZ写入图像对象并推进动画。它使用自己的对象池与时钟，不可将空的effect_objects宿主直接视作完整效果执行。

只读导出 `local/aoitori/particle-22a5-x64.json` SHA-256 `e64cc9780abca4a52774b9fa54f9d28350e53dd57111195624fb2fd662395808`，身份同文首。调用点反汇编已核对浮点寄存器参数，Hex-Rays中的无参setter不能作为真实函数原型。

SP-12为模式，SP-16/20/24/28依次为f32的基准X、基准Z、角度和速度，SP-32为数量。先读参数、解析名称，再判断槽；无效槽只回收32字节，不加载图像或推进随机数。图像经注册的 `0x2011` 图像源解码，池持有一份共享纹理，独立粒子不占用256个普通场景槽或768个固定子槽。每粒子初始化恰好消耗8次共享CRT rand，包括两个保留的初始位置；落出下边界时再消耗2次。

汇编中模式最高半字节还选择投影尺寸：4/5/6/7/8对应60/50/40/30/20，其余为基准Z+5；这是反编译伪代码省略的分支。粒子按模式2、独立XYZ投影，源图格20×20、原点10×10。十格动画使用公共动画实现，动画delta上限200ms，与位移的500ms上限分开。`0x1400187a0 → 0x140043e80 → 0x14004ffd0 → 0x1400425d0` 的入队顺序是普通槽、四个效果槽、文字窗口；软件及设备后端共用的帧准备已包含池粒子。

创建按候选状态提交；资源/参数失败保留旧池、VM pending/栈及随机数。`0x22a0` 释放相应池，RESET清空，后续帧不再消耗该池随机数。未核对粒子存档记录，活动池的保存/加载明确拒绝。Rust另设每池16,384粒子的研究分配上限，并拒绝非有限参数或非正速度；使用现有研究帧时钟，不据此宣称真实墙钟、失焦恢复或原生像素一致。
