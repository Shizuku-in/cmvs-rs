# PURIRING 实现依据

地址仅适用于 `cmvs-20070119`、x86 `cmvs.exe` SHA-256 `5ce421db393cbc5ca443fa405c5a9e31c348416109cb1279d91718f490c0e602`。

## 构建与命令对照

以下地址只绑定上表 x86 `5ce421db393cbc5ca443fa405c5a9e31c348416109cb1279d91718f490c0e602`。PE 时间戳 `0x45b04545`，链接器 8.0；switch `0x43ee05`、表 `0x43fe60`、default `0x43ee37`；800 项中 480 个处理命令保持 Unreviewed，320 个为空操作。`0x201d` 是空操作，启动脚本不提供游戏 ID，记录中的零只是占位。

与 Asukimi 同号的 480 个处理函数返回标志集合一致。以下变体基于递归调用图形状一致性绑定：`se-restart` `0x20b4`，`polar-point` `0x20d8`，`audio-preload` `0x2248`、`0x2249`、`0x224a`、`0x224b`、`0x224f`，`input-press` `0x219c`、`0x219e`、`0x21a0`、`0x21a2`、`0x21a4`、`0x21a6`、`0x21a8`、`0x21aa`、`0x21ac`、`0x21ae`、`0x21b0`、`0x21b2`、`0x21b4`、`0x21b6`、`0x21b8`、`0x21ba`、`0x21bc`、`0x22f0`、`0x22f1`、`0x22f2`、`0x22f3`、`0x22f4`、`0x22f5`，`text-dialog` `0x22bc`。`0x213c → 0x43ed20` 与 Asukimi `0x44d890` 反编译结构相同（6 个参数、返回 `0x4018`，结果写系统结果），仅下层对话框实现规模不同，也绑定 `text-dialog`。这些绑定属于形状比对依据，未提升为严格指纹继承。

Asukimi 的构建门控按该构建逐项核验：画布、256 子槽、文字创建、旧版轨道与独立快照布局已接通；滤镜模式 1 仍未开放。

### 构建变体

- `mixer-gain` `0x20a5 → 0x434aa0 → 0x4427e0`：SP−4 按无符号截到 256 写设备 `+0x904`；混音 `0x441b50` 对每个通道样本再乘该值 `>> 8`（`0x441910`/`0x441940` 的语音、SE 路径同样使用）。返回 `0x4004`，不写系统结果。启动脚本设为 128。原生后端在每个流的输出样本上乘该增益，记录后端只记录请求；浏览器后端尚未实现。
- `image-tables` `0x2017 → 0x4359d0`、`0x2018 → 0x435a50`：与 `0x2011`（`0x435950`）代码相同，但分别写入独立的封包表 `+0xC28`（stand.cpz，`0x414080` 上限检查 `> 10`、查找 10 槽）和 `+0xC2C`（up.cpz，`0x4108d0` 上限 7 槽）；SP−4 槽、SP−8 路径，返回 `0x4008`。`0x2032 → 0x4329b0` 先对 `+0xC28` 表置下一次读取缓存标志（`0x414030`，`+5651`，由 `0x414700` 消费，等同现代 `0x203f`），再按 `0x2030` 加载对象图像；返回 `0x400c`，SP−12 未读取。实现上把 `0x2017` 表追加在 `0x2011` 表之后共同查找：仅 `st-cp00.pb3` 同时存在于 chip.cpz 与 stand.cpz，两份 SHA-256 均为 `5976edb871d7fc049b8830a7c4a4cf487b9a29ebbb74903cf193c7d9101a58b0`，因此成功加载结果与原版分表查找一致。`+0xC2C` 表除注册与析构（`0x408273`）外未见读取者，只保存路径。
- `window-scale-motion` `0x21c0 → 0x438af0`、`0x21c1 → 0x438b70`、`0x21c2 → 0x438c20`：消息窗口（原版 `< 4` 槽）对象或子对象（`0x429070`，负数为窗口本体）绘制状态 `+88` 的缩放轨道，0xb8 字节结构、参数顺序与现代场景 `0x21e0`–`0x21e2` 相同（创建 `0x40ef10` 记录基准 X/Y，键 `0x40f010` 写 next/X/Y/模式/时长，启动 `0x40b930`）；帧更新 `0x40f080` 与现有缩放插值一致（增量截到 200ms，模式 0 线性、1 为截到百分位的四分之一正弦）。返回 `0x4010`/`0x4020`/`0x400c`。缺窗口、子对象或绘制状态在原版只置 `+8108` 位 `0x10000`，此处报错。
- `view-motion` `0x2270`–`0x2274`：设备视图（engine `+1900 → +12`，即 `0x2260`–`0x2264` 写的 `DeviceView` 位置 XYZ、三角度、视场角）的过渡。`0x2273 → 0x43d190 → 0x423240`：SP−4 模式、SP−8..SP−16 目标位置、SP−20 时长，返回 `0x4014`；`0x2274 → 0x43d200 → 0x4232a0`：SP−4 模式、SP−8/SP−12 目标 X/Y 角度、SP−16 时长，返回 `0x4010`；起点为开始时的当前值，只移动所选一组。帧更新 `0x4233b0`：时长内模式 0 为截到百分位的线性、1 为正弦缓出、2 为截到百分位角度的余弦缓入（`0x422170` 将 cos/sin 结果截到百分位），其他模式保持不变直到结束；到时跳到目标并结束。`0x2270 → 0x43d070` SP−4 非零时跳到目标后停止，返回 `0x4004`；`0x2272 → 0x43d160` 系统结果为是否运动中，返回 `0x4000`；`0x2271 → 0x43d0a0` 等待，跳过条件（效果关闭、跳读、跳过标志、可跳过时的按键释放与消费）、`0x4004`/`0xa000`/`0xc004` 返回标志均与现有 `0x2069` 一致。视图快照恢复时清除运动。

### 激活与光盘校验

`protect.ps2` 通过两条命令执行激活检查，`cmvs.exe` 本身未导入 `GetDriveType`/`GetVolumeInformation` 等驱动器接口（附带的 `userid.exe` 有这些导入）：

- `0x22c1 → 0x43d3a0 → 0x453030`、`0x22c0 → 0x43d310 → 0x452fd0`：SP−4 为 1 时检查游戏目录的 `comap.dat`（`0x452f50`：首字为固定签名、并与 `0x452db0` 由系统环境生成的值比对），`0x22c0` 在失败时先 `WinExec("reg.exe")` 再轮询 10 秒。系统结果为 `SP−4 == 1 && 检查通过`，均返回 `0x4004`。
- `protect.ps2 / 0x1f580` 先调用 `0x22c1`，失败则显示说明并在 `0x1f63c` 调用 `0x22c0`，仍失败则显示错误并退出（`0x213b`、`0x2001`）。

重实现不加入这部分校验逻辑：新增 `activation-pass` 变体只读取并回收 SP−4，按原版的参数条件把系统结果设为 `SP−4 == 1`，即视为校验通过；不读取 `comap.dat`、不启动 `reg.exe`、不访问注册表或驱动器。该变体只绑定上表哈希。

### 变量区与启动

`.data` 文件长度在 `0x4ae000` 结束，之后由加载器零填充。系统存档写入 `0x408b00` 使用的变量区：整数 `0x4b6708`（4096 个）、字符串 `0x4ba710`（128 × 1024 字节）、浮点 `0x4da710`（2048 个）、位 `0x4dc710`（0x8000 字节，`0x440be0`/`0x440b60` 按 `n / 8` 字节、`1 << (n % 8)` 打包，即 262144 位），首尾相接，因此按 `[4096, 262144, 2048, 128]` 零初始化。CSS1 载荷布局（位从第 2048 位起 32512 字节、整数 2048 起、浮点 1024 起、字符串 64 起）与现有编码一致；`0x408b00` 先清零 360 字节头再写偏移 72，偏移 68 保持零，因此与 Asukimi 一样按固定零标识写入，不表示恢复了作品 ID。全新安装没有 `system.dat` 时，启动脚本在 `0x2128` 后读取整数 2190，原先因变量未知而停止。

### 画布、子槽与系统存档

- `0x403f60` 依 `CMVS_SYSTEM_MAIN/WINDOW_SIZE` 选择逻辑画布，分支与 Asukimi `0x404e00` 相同（0 → 640×480，2 → 1024×768，9 → `RESOLVING_POWER_INFO/WINDOW_WIDTH,WINDOW_HEIGHT`，其他 → 800×600）；该构建为 9，即 1024×614。3D 投影 `0x422f60` 的宽高比常量 1.6677524 与 1024/614 相同。
- 对象 `0x415af0` 固定 256 个子对象指针，`0x415df0` 检查 `< 0x100`，因此使用 256 项子槽表。
- 视图方向 `0x422cb0` 与现有 `DeviceView` 相同：向量 (0,0,1) 经俯仰、偏航旋转后截到千分位，上向量只受滚转影响；`0x422f60` 为 LookAtLH 与 PerspectiveFovLH（近 0.1、远 100）。

### 场景与窗口命令

- `screen-coordinates` `0x204e → 0x433210`：父槽 < 256、子槽（负数为本体，≥ 256 只置错误位）、SP−12 零/非零经 `0x416070`/`0x416060` 写绘制字 0 为 0/1，返回 `0x400c`；与 Harouse 已验证语义相同，并对本构建开放坐标模式 1 的绘制。
- `draw-query` `0x204f → 0x432d20`：父槽 < 256、子槽（负数为本体）；系统结果 0..3 为绘制字 17、8、9、10，浮点结果 8/9 为字 18/19，返回 `0x4008`，与现有窗口版 `0x218d` 映射相同。
- `window-child-image` `0x2176 → 0x438670`：SP−4 窗口（< 4）、SP−8 子对象（`0x429070`，负数为窗口本体）、SP−12 图名；先释放（`0x4163e0`）再从 `0x2011` 表加载（`0x416590`），解码失败只置 `+8108` 位 `0x80`，返回 `0x400c`。
- `camera-move-x` `0x206e → 0x434960 → 0x422780`：SP−4 模式、SP−8 目标 X（截到百分位）、SP−12 时长，Y/Z 目标为当前值，与现有 `0x206b`–`0x206d` 共用移动逻辑；剧本只用模式 0，模式 2 仍拒绝。

- `0x2225 → 0x43a560`，帧更新 `0x42b9d0`：波形高位非零时一律走三角波（相位每周期翻转、`2A·t/T` 往返、完成判断在计数前），与 Harouse 已验证的三角波公式相同；本构建内存储为 `0x100`。阶跃波与随机波（`0x20`）照旧。

### 影片

`op.cmv` 签名为 `CMV4`，头部、20 字节索引及资源区布局与 CMV6 相同（1024×614、24fps、2712 帧加 1 项 Ogg 音轨）；帧为 JBP1（标志 `0x58c00002`，与 PB3 类型 2/3 相同）。本构建的播放器不检查签名，因此 CMV4 解析为 JBP1 编码的不透明帧。

### 特效层（engine `+2928`，4 槽）

本构建的特效槽在粒子类型 1–3 之外还有写死在 exe 里的场景类型 0x50–0x57（`0x2290`–`0x2297` 创建）。逐帧逻辑 `0x417e70` 由帧更新 `0x407810` 在视图运动之后调用；绘制提交 `0x418060` 由 `0x407b10` 调用，经 `0x417350` 进入旧版绘制队列。队列执行 `0x407c90`：0、2 →（3D 状态 `0x40cae0`、视图投影 `0x422f60`）1 → 5 → 3（普通 2D 对象），每个队列按键值降序插入（`0x417290`），3D 网格的键值为到视点的距离（`0x422f20`）。网格（`0x416c10`，FVF `0x142` 三角带四边形）世界矩阵 `0x410c30` 为缩放 × 绕 Y、X、Z 旋转（角度为零时跳过）× 平移；`0x411630` 无剔除，网格 `+52` 为零且透明度 255 时不混合，否则 SRCALPHA/INVSRCALPHA（`+8` 为 1 时加法）；`+56`（`0x409ba0`）选择队列 5。

重实现把每块网格在世界空间细分成小格（屏幕尺寸不超过 48 像素且深度比不超过 1.08，近平面附近继续细分、最终丢弃跨越近平面的小格），各自输出为现有的旋转四边形图层，因此 CPU、wgpu 与 deko3d 后端无需改动；透视误差在亚像素级，纹理寻址为夹取而原版 3D 阶段为环绕，仅影响纹理边缘一像素。

- `0x22a2 → 0x43ccb0 → 0x418310`（类型 2）：飘雪 billboard，参数布局、`0x421cf0` 生成时随机数顺序（X、Z、Y、速度）与 `0x421eb0` 的下落、环绕、按距离淡出公式均与现有 `falling-billboards` 相同，直接绑定。原版用实时时钟（`0x402940`）计时，重实现用帧时钟。
- `0x2290 → 0x43c410`（类型 0x50）：两张图（SP−8 地面、SP−12 覆盖）；3 块 10×10 地面（y = −0.1）位于 z = 0/10/20，覆盖层为 30×30（y = 0、`+52` 混合）。`0x420530` 每帧把覆盖层放到视点 X/Z，视点 Z 超过已推进距离 + 10 时把下一块地面移到 +30。
- `0x2291 → 0x43c500`（类型 0x51）：视图置于 (0, 1.5, 0)、X 角度 35、Y 角度 0，从 SE 表预载声槽 16/17/20（`se001d.wav`、`se001e.wav`、`se003c.wav`）。`0x4211b0` 状态 1/2 为慢步/快步（1.5s/0.9s，前进 0.2/0.4，先半正弦起伏、后下沉回弹，到时播放 16/17），状态 1 结束进入 90（等待 600ms 后再走），状态 3 为 2 秒的最后一步（X 角度 35→60、结束时 80，1.8s 播放 20 并停止设备声道 10），之后空闲。音量为 master × SE >> 8，不检查 SE 开关，混音增益另由后端施加。
- `0x2292 → 0x43c5d0`（类型 0x52）：固定的 9 张 `try002*.pb3`；背景墙、立板、6 + 18 块 6×6 环片与竖板，环片每 5 秒一圈按图正/反向绕 Y 轴旋转。状态 1（`0x41be30`）播放 `SE006.ogg`，12 组环片每隔 300ms 用 3 秒淡入，6.5 秒结束；状态 2（`0x41bf10`）播放 `SE006c.wav`，竖板 1 秒内升起 32，各组自 1.5 秒起每隔 300ms 用 2 秒淡出，7 秒结束并停止该声音。

## 轨道与极坐标

### 百分之一度极坐标

`0x20d9` 分发表 `0x43f25a → 0x437280 → 0x40cf00`：SP−4 为有符号百分之一度角度，SP−8 为有符号半径；系统整数 1/2 写 cos/sin 乘半径的向零取整值，系统结果 0 不变，返回 `0x4008`。与 `0x20d8 → 0x437240` 的唯一区别是后者先将角度有符号环绕乘 100。原版常量 `0x48f670` 为 double 18000，`0x48ff00` 为 f32 PI 提升为 double。复用 polar-point 变体并仅在本构建绑定新增命令；

### 旋转保持

`0x40ba70 → 0x410040` 写旋转键，帧更新 `0x4100a0` 在 `0x4100dd` 提取模式低字节，仅 0/1 插值，其余在时长内直接返回；段末 `0x410200` 无条件把目标角度写入输出和基准，然后推进键。因而 0xff 是保持后跳到目标，不能直接套用现代轨道的高位模式段末跳过赋值规则。

`cmvs-20070119` 的场景旋转键支持低字节 `0xff`：时长内不修改角度，段末无条件写入目标并以该目标作为下一段基准。场景与三精灵共用该轨道，恢复保留构建门控。其他构建的命令入口继续拒绝此模式。

### 世界移动

`0x40bf00 → 0x40f690` 设置键，`0x40f710` 更新：模式 0 为线性；模式 1 为四分之一正弦缓出（不是现代构建的二次曲线），二者的 `0x8000` 位表示以目标 XYZ 为相对增量。模式 `0x10` 先线性插值 XYZ，再将周期 2000ms、幅度 0.2 的正弦值加到 X；设 `0x8000` 时跳过 XYZ 插值，直接累加到当前 X，保持 Y/Z。增量截到 200ms，插值与正弦输出截到百分位；段末直接写键目标 XYZ，包括相对模式。

本作场景与三精灵的轨道使用独立 `legacy_20070119` 语义，命令入口只开放本作已证实的 0/1/0x10。`TextV1SceneLegacy` 保存并恢复这些旧版轨道语义。

## 特效实现补充

### 类型 1：雨丝

`0x22a1 → 0x43cb70 → 0x418230` 为类型 1 雨丝，八参数布局与后期雨丝相同，返回 `0x4020`。初始化 `0x4213c0`、生成 `0x421440`、更新 `0x421630`：最多 1024 粒子、每次两个 CRT 随机数，X ∈ [−5,5]、Z ∈ [0,10]、Y=6；每粒 6×112、中心 (3,112)，相机类型 1 投影参数为 `3+(mode&3)` 和 3。发射时间积累最多 1000ms，严格大于间隔才发射一次，不使用后期翻倍发射位；速度按 Δt·speed/1000，非零角按 angle+90 度分解，Y≤0 释放。

实现复用雨丝池但保留独立旧版参数分支；后期类型 4 不变。类型 1 的 60 字节快照保存创建参数，读档重建空粒子池，与 `0x417950`/`0x4179f0` 一致。

### 类型 3：飘落粒子

只绑定本构建 `cmvs-20070119` / `5ce421db…e602` 的 `legacy-effects` 变体：`0x22a3 → 0x43cdf0 → 0x4183f0`，SP−4 槽号、SP−8 图名、SP−12 模式、SP−16 基准 Z（float）、SP−20 下落时长（float）、SP−24 数量；返回 `0x4018`，回收 24 字节，不写系统结果。槽号无符号大于 3 时忽略创建，合法槽替换原特效。

`0x421840` 加载池图像；`0x421880` 初始化独立链表子对象，未使用固定的 256 子槽表。因此实际资源请求的 1024 粒子不能按普通子槽上限截断。每粒依次消耗 4 个 CRT 随机数：X=`rand/32767*10−5`、Z=`rand/32767*10+baseZ`、Y=`rand/32767*10`、时长=`duration + (rand/32767*spread−spread/2)`，其中 spread=`duration/5`，按原版显式 float 存储位置舍入。图像区域固定 32×32、中心 (16,16)，坐标模式 2，投影参数 `3+(mode&3)`、3，模式高位不参与。

逐帧 `0x421af0` 将帧增量截到 500ms，先将 `delta*10/粒子时长` 存为 float，再从 Y 减去该值；严格 Y<0 时只加一次 10，恰为零不回绕，X/Z 不变，更新不再消耗随机数。通过现有父池纹理与投影对象绘制队列接入 CPU/wgpu；覆盖槽、释放、场景重置均清除该池。实现使用 f64 中间值及显式 f32 落点，不宣称任意输入的 x87 80 位逐位一致。

存档写入器 `0x417950` 对类型 3 写版本 1、类型 3、4 个参数字及 32 字节 NUL 图名，共 52 字节；`0x4179f0` 用这些参数重新创建粒子，消耗当前 RNG，不恢复旧粒子位置。`SavedEffect::LegacyFlakes`，保留名称字段填充；运行器仅允许已核验本构建加载此类型。合法数量上限 16,384 为研究实现的分配边界，时长要求有限正值，Z 要求有限；无效参数或资源读取失败保持 VM、原槽和 RNG 不变。

### 类型 0x53：双片遮罩显现

`0x2293 → 0x43c6a0 → 0x4186f0`，读取槽号并返回 `0x4004`。`0x41c810` 加载 `try007c3/c4.pb3`，宽度不为 512 时退回 `try007c1/c2.pb3`；显现遮罩相应为 `try007d3/d4` 或 `try007d1/d2`。`__try007a.pb3` 是 1024×614、屏幕坐标模式 1、顺序 64 的背景。`0x41ceb0` 建立左右两片 20×20 网格，位置 (−0.3,0,28)/(0.1,0,28)，进入混合队列 5，并将设备视图置为 (0,3.2,0)、俯仰/偏航 0。

`0x41c900` 请求 1–5；`0x41cbb0`：1 开始显现并进入状态 10，2 隐藏，3 显示，4 在 800ms 内以正弦缓出将附加 Y 角移至 5 度，5 在 500ms 内淡出并隐藏。左右片在 2 秒摆动和严格超过 200ms 的停顿间循环，角度为附加角 ± 摆动量。状态查询在无待处理请求时返回状态，否则 −1。

显现 `0x42b670/0x42b400/0x42b880` 用灰度遮罩（彩色取绿色通道）×4000/255 作为像素启动延迟，再用 1000ms 将原始 alpha 线性显现；总长 5000ms。更新顺序是状态逻辑之后更新遮罩，下一帧才报告状态 0。实现逐帧更新网格图像 alpha，复用各后端已有图层渲染。遮罩资源在创建时预载；原版在请求 1 时加载。快照仅写类型头、读档清除。

### 类型 0x54：五层魔法图形与上升光点

`0x2294 → 0x43c770 → 0x4187a0`，槽号参数，返回 `0x4004`。`0x41ddc0` 用 `try008a`–`try008e.pb3` 创建五个 2×2 平面，局部 Y 为 0/0.1/0.3/0.4/0.5，世界位置 (−0.16,0.97,2)、X 角 −90；混合队列 5，初始透明度零。设备视图为 (0,1,0)、俯仰/偏航零；预载声槽 16=`st03_magic1b.wav`，析构释放该槽。

图形每 6 秒一圈交替旋转。状态 <10 自启动后 1500ms 延迟显现；请求 10 停在原时钟，11 恢复分层显现（五层从后向前每隔 200ms、各用 500/550/600/650/700ms 缩放与淡入），全部完成为状态 12，首层启动播放声槽 16。20 将图形与光点用 1000ms 淡出到状态 21；22 只淡出光点到状态 23；50 替换光点纹理为 `try008z2.pb3`。时钟不因请求重置。

实现将备用光点纹理在创建时预载（原版请求 50 时加载）。光点复用现有投影加法混合图层，纹理寻址目前夹取，原版环绕。快照仅写类型头、读档清除。

### 类型 0x55：三精灵

## 相机与剧情快照

## 渲染规则

震屏叠加淡入淡出使用屏幕大小的纯色矩形，按 slot 层偏移并保留裁切、颜色、透明度与排序。原版 `0x42ab20` 创建遮罩，`0x415af0` 设置震屏标志；`0x407b10` 入队，`0x407c90` / `0x42bb90` 选择偏移。CPU/GPU 共用 Solid 图层。

旧版世界网格在透视除法和细分前，按视野侧面剔除完全不可见的单元；跨边界单元保留。该规则限制屏幕外网格的递归细分开销。
