## 构建与命令对照

以下地址只绑定上表 x86 `5ce421db393cbc5ca443fa405c5a9e31c348416109cb1279d91718f490c0e602`。PE 时间戳 `0x45b04545`，链接器 8.0；switch `0x43ee05`、表 `0x43fe60`、default `0x43ee37`；800 项中 480 个处理命令保持 Unreviewed，320 个为空操作。`0x201d` 是空操作，启动脚本不提供游戏 ID，记录中的零只是占位。

用 `tools/ida_export_commands.py` 导出本构建与《明日の君と逢うために》（`cmvs-20071117`）的命令图后比较：严格指纹因对象偏移不同全部不继承；但 480 个处理函数的返回标志集合与 Asukimi 同号命令全部一致，说明命令编号未错位。递归调用图形状（逐层指令数与调用结构）比对后，以下 Asukimi 变体在本构建结构完全一致，按同一语义绑定：`se-restart` `0x20b4`，`polar-point` `0x20d8`，`audio-preload` `0x2248`、`0x2249`、`0x224a`、`0x224b`、`0x224f`，`input-press` `0x219c`、`0x219e`、`0x21a0`、`0x21a2`、`0x21a4`、`0x21a6`、`0x21a8`、`0x21aa`、`0x21ac`、`0x21ae`、`0x21b0`、`0x21b2`、`0x21b4`、`0x21b6`、`0x21b8`、`0x21ba`、`0x21bc`、`0x22f0`、`0x22f1`、`0x22f2`、`0x22f3`、`0x22f4`、`0x22f5`，`text-dialog` `0x22bc`。`0x213c → 0x43ed20` 与 Asukimi `0x44d890` 反编译结构相同（6 个参数、返回 `0x4018`，结果写系统结果），仅下层对话框实现规模不同，也绑定 `text-dialog`。这是形状比对，不是指纹继承或人工逐条复核。

Asukimi 中以 `is_inspected_20071117` 绑定的其他行为（800×600 画布选择、旧版文字创建、256 子槽、滤镜模式 1、旧版正弦模式、快照布局）尚未对本构建复核，因此不启用；`0x2022`/`0x2023`/`0x2178`/`0x2179` 的调用图与 Asukimi 不同，子槽上限待确认。

### 新增变体

- `mixer-gain` `0x20a5 → 0x434aa0 → 0x4427e0`：SP−4 按无符号截到 256 写设备 `+0x904`；混音 `0x441b50` 对每个通道样本再乘该值 `>> 8`（`0x441910`/`0x441940` 的语音、SE 路径同样使用）。返回 `0x4004`，不写系统结果。启动脚本设为 128。原生后端在每个流的输出样本上乘该增益，记录后端只记录请求；浏览器后端尚未实现。
- `image-tables` `0x2017 → 0x4359d0`、`0x2018 → 0x435a50`：与 `0x2011`（`0x435950`）代码相同，但分别写入独立的封包表 `+0xC28`（stand.cpz，`0x414080` 上限检查 `> 10`、查找 10 槽）和 `+0xC2C`（up.cpz，`0x4108d0` 上限 7 槽）；SP−4 槽、SP−8 路径，返回 `0x4008`。`0x2032 → 0x4329b0` 先对 `+0xC28` 表置下一次读取缓存标志（`0x414030`，`+5651`，由 `0x414700` 消费，等同现代 `0x203f`），再按 `0x2030` 加载对象图像；返回 `0x400c`，SP−12 未读取。实现上把 `0x2017` 表追加在 `0x2011` 表之后共同查找：仅 `st-cp00.pb3` 同时存在于 chip.cpz 与 stand.cpz，两份 SHA-256 均为 `5976edb871d7fc049b8830a7c4a4cf487b9a29ebbb74903cf193c7d9101a58b0`，因此成功加载结果与原版分表查找一致。`+0xC2C` 表除注册与析构（`0x408273`）外未见读取者，只保存路径。
- `window-scale-motion` `0x21c0 → 0x438af0`、`0x21c1 → 0x438b70`、`0x21c2 → 0x438c20`：消息窗口（原版 `< 4` 槽）对象或子对象（`0x429070`，负数为窗口本体）绘制状态 `+88` 的缩放轨道，0xb8 字节结构、参数顺序与现代场景 `0x21e0`–`0x21e2` 相同（创建 `0x40ef10` 记录基准 X/Y，键 `0x40f010` 写 next/X/Y/模式/时长，启动 `0x40b930`）；帧更新 `0x40f080` 与现有缩放插值一致（增量截到 200ms，模式 0 线性、1 为截到百分位的四分之一正弦）。返回 `0x4010`/`0x4020`/`0x400c`。缺窗口、子对象或绘制状态在原版只置 `+8108` 位 `0x10000`，此处报错。
- `view-motion` `0x2270`–`0x2274`：设备视图（engine `+1900 → +12`，即 `0x2260`–`0x2264` 写的 `DeviceView` 位置 XYZ、三角度、视场角）的过渡。`0x2273 → 0x43d190 → 0x423240`：SP−4 模式、SP−8..SP−16 目标位置、SP−20 时长，返回 `0x4014`；`0x2274 → 0x43d200 → 0x4232a0`：SP−4 模式、SP−8/SP−12 目标 X/Y 角度、SP−16 时长，返回 `0x4010`；起点为开始时的当前值，只移动所选一组。帧更新 `0x4233b0`：时长内模式 0 为截到百分位的线性、1 为正弦缓出、2 为截到百分位角度的余弦缓入（`0x422170` 将 cos/sin 结果截到百分位），其他模式保持不变直到结束；到时跳到目标并结束。`0x2270 → 0x43d070` SP−4 非零时跳到目标后停止，返回 `0x4004`；`0x2272 → 0x43d160` 系统结果为是否运动中，返回 `0x4000`；`0x2271 → 0x43d0a0` 等待，跳过条件（效果关闭、跳读、跳过标志、可跳过时的按键释放与消费）、`0x4004`/`0xa000`/`0xc004` 返回标志均与现有 `0x2069` 一致。视图快照恢复时清除运动。

### 激活与光盘校验

样本目录名中的 DVD 校验在 `cmvs.exe` 中表现为 `protect.ps2` 调用的两条命令，`cmvs.exe` 本身未导入 `GetDriveType`/`GetVolumeInformation` 等驱动器接口（附带的 `userid.exe` 有这些导入）：

- `0x22c1 → 0x43d3a0 → 0x453030`、`0x22c0 → 0x43d310 → 0x452fd0`：SP−4 为 1 时检查游戏目录的 `comap.dat`（`0x452f50`：首字为固定签名、并与 `0x452db0` 由用户名、计算机名和 OS 版本拼出的值比对），`0x22c0` 在失败时先 `WinExec("reg.exe")` 再轮询 10 秒。系统结果为 `SP−4 == 1 && 检查通过`，均返回 `0x4004`。
- `protect.ps2 / 0x1f580` 先调用 `0x22c1`，失败则显示说明并在 `0x1f63c` 调用 `0x22c0`，仍失败则显示错误并退出（`0x213b`、`0x2001`）。

重实现不加入这部分校验逻辑：新增 `activation-pass` 变体只读取并回收 SP−4，按原版的参数条件把系统结果设为 `SP−4 == 1`，即视为校验通过；不读取 `comap.dat`、不启动 `reg.exe`、不访问注册表或驱动器。该变体只绑定上表哈希。

### 变量区与启动

`.data` 文件长度在 `0x4ae000` 结束，之后由加载器零填充。系统存档写入 `0x408b00` 使用的变量区：整数 `0x4b6708`（4096 个）、字符串 `0x4ba710`（128 × 1024 字节）、浮点 `0x4da710`（2048 个）、位 `0x4dc710`（0x8000 字节，`0x440be0`/`0x440b60` 按 `n / 8` 字节、`1 << (n % 8)` 打包，即 262144 位），首尾相接，因此按 `[4096, 262144, 2048, 128]` 零初始化。CSS1 载荷布局（位从第 2048 位起 32512 字节、整数 2048 起、浮点 1024 起、字符串 64 起）与现有编码一致；`0x408b00` 先清零 360 字节头再写偏移 72，偏移 68 保持零，因此与 Asukimi 一样按固定零标识写入，不表示恢复了作品 ID。全新安装没有 `system.dat` 时，启动脚本在 `0x2128` 后读取整数 2190，原先因变量未知而停止。

### 画布、子槽与系统存档

- `0x403f60` 依 `CMVS_SYSTEM_MAIN/WINDOW_SIZE` 选择逻辑画布，分支与 Asukimi `0x404e00` 相同（0 → 640×480，2 → 1024×768，9 → `RESOLVING_POWER_INFO/WINDOW_WIDTH,WINDOW_HEIGHT`，其他 → 800×600）；本样本为 9，即 1024×614。3D 投影 `0x422f60` 的宽高比常量 1.6677524 与 1024/614 相同。
- 对象 `0x415af0` 固定 256 个子对象指针，`0x415df0` 检查 `< 0x100`，因此使用 256 项子槽表。
- 视图方向 `0x422cb0` 与现有 `DeviceView` 相同：向量 (0,0,1) 经俯仰、偏航旋转后截到千分位，上向量只受滚转影响；`0x422f60` 为 LookAtLH 与 PerspectiveFovLH（近 0.1、远 100）。

- `window-child-image` `0x2176 → 0x438670`：SP−4 窗口（< 4）、SP−8 子对象（`0x429070`，负数为窗口本体）、SP−12 图名；先释放（`0x4163e0`）再从 `0x2011` 表加载（`0x416590`），解码失败只置 `+8108` 位 `0x80`，返回 `0x400c`。

### 影片

`op.cmv` 签名为 `CMV4`，头部、20 字节索引及资源区布局与 CMV6 相同（1024×614、24fps、2712 帧加 1 项 Ogg 音轨）；帧为 JBP1（标志 `0x58c00002`，与 PB3 类型 2/3 相同）。本构建的播放器不检查签名，因此 CMV4 解析为 JBP1 编码的不透明帧。

### 特效层（engine `+2928`，4 槽）

本构建的特效槽在粒子类型 1–3 之外还有写死在 exe 里的场景类型 0x50–0x57（`0x2290`–`0x2297` 创建）。逐帧逻辑 `0x417e70` 由帧更新 `0x407810` 在视图运动之后调用；绘制提交 `0x418060` 由 `0x407b10` 调用，经 `0x417350` 进入旧版绘制队列。队列执行 `0x407c90`：0、2 →（3D 状态 `0x40cae0`、视图投影 `0x422f60`）1 → 5 → 3（普通 2D 对象），每个队列按键值降序插入（`0x417290`），3D 网格的键值为到视点的距离（`0x422f20`）。网格（`0x416c10`，FVF `0x142` 三角带四边形）世界矩阵 `0x410c30` 为缩放 × 绕 Y、X、Z 旋转（角度为零时跳过）× 平移；`0x411630` 无剔除，网格 `+52` 为零且透明度 255 时不混合，否则 SRCALPHA/INVSRCALPHA（`+8` 为 1 时加法）；`+56`（`0x409ba0`）选择队列 5。

重实现把每块网格在世界空间细分成小格（屏幕尺寸不超过 48 像素且深度比不超过 1.08，近平面附近继续细分、最终丢弃跨越近平面的小格），各自输出为现有的旋转四边形图层，因此 CPU、wgpu 与 deko3d 后端无需改动；透视误差在亚像素级，纹理寻址为夹取而原版 3D 阶段为环绕，仅影响纹理边缘一像素。
