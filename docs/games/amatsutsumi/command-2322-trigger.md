## 样本与静态条件

绑定本档案 `cmvs64.exe` SHA-256 `dc74d2001387ae1aefbdc4204216de5ebb9d3896009280720c4e7a91b42d84f5`、image base `0x140000000`，以及 `script.cpz` SHA-256 `92b367e8c3d2791f1dd2ca8426581974fbb640d2766f2e82ab12383d2f5359e4`。后文PC为解码脚本内偏移。

`intproc.ps3` 的标签158位于 `0x2bea0`，接收一个整数参数，函数结尾 `0x2c134` 以 `0x0411(pop 4)` 返回。它使用脚本整数55保存当前模式；整数110控制是否立即操作当前对象。简化语义：

```text
toggle(value):
    if integer[110] == 0:
        if integer[55] != value:
            对已存在的对象28、29、17..19、20..27:
                0x2322(object, -1, value)
            integer[55] = value
    else:
        integer[55] = value
```

- `0x2bec6` 比较整数55与帧参数（frame−8），相等时不重复设置。
- `0x2bf3a` / `0x2bf98` 对应对象28/29，先通过 `0x2027` 检查对象存在。
- `0x2c030` 对应17..19循环，`0x2c0da` 对应20..27循环。
- `0x2c0f4` 写整数55；整数110非零则从另一分支 `0x2c118` 只写模式，不更新已有对象。整数110的完整业务名称尚未确认，不能将其命名为某个菜单设置。

因此可用参数1开启、0关闭。脚本保存原始整数，最终 `0x2322` 将非零归一为开启。多个后续图像/影片创建路径还会检查整数55，例如标签34在 `0x82a2` 判断其非零后，于 `0x82e4` 执行 `0x2322(15,-1,1)`。这使该模式也能影响后续创建的对象；本轮未动态验证所有创建分支。

现有渲染实现将已核对纹理路径的颜色减法应用到图像，保留alpha和混合行为；默认不透明纹理会变黑。这里将它描述为黑化/黑影效果是行为解释，不是已恢复出的原始函数名。加法混合等状态的结果仍依赖原绘制状态，详见[指令语义](vm-semantics.md#纹理颜色减法-0x23222026-10-31)。

## 为什么路线重放没碰到

对87个包内脚本及包外启动脚本共88个来源进行静态扫描：没有发现标签158的 `0x0410` 调用、`0x0405` 跳转、递归表达式中的 `0x010e` 标签地址引用，或指向该标签入口的立即地址跳转。直接引用整数55的赋值共681处，其中511处写0，其余170处为85份公共库中标签158的参数赋值。

这支持“本作保留了一个未见直接调用的公共库接口”的判断，能够解释上一轮未命中，但不是完整不可达证明：动态构造的地址、间接变量写入、外部调用等未被这一静态扫描穷尽。尚不能给出一个已经确认的普通菜单点击或剧情选择链来触发它。
