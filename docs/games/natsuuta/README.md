## 构建与语义证据（2026-11-07）

本轮为浅层接入：没有逐条 IDA 复核，而是以 objdump 文本做函数级对照。对照把调用目标、映像内绝对地址和内存位移归一化后比较函数体；脚本与输出在忽略目录 `local/natsuuta/compare/`。结论只说明两份代码结构一致，不等于独立语义复核。

### 与 MEMORIA 一致的部分

MEMORIA（`cmvs-20090815`）已绑定变体的 36 个命令中，`0x204e`、`0x20a5`、`0x20b4`、`0x219c`、`0x219e`、`0x21a0`、`0x21a2`、`0x21a4`、`0x21a6`、`0x21a8`、`0x21aa`、`0x21ac`、`0x21ae`、`0x21b0`、`0x21b2`、`0x21b4`、`0x21b6`、`0x21b8`、`0x21ba`、`0x21bc`、`0x22bc`、`0x22f0`、`0x22f1`、`0x22f2`、`0x22f3`、`0x22f4`、`0x22f5`、`0x2330`、`0x2332` 三层调用图归一化后完全一致；`0x213c`、`0x22a2`、`0x22a6`、`0x22a7`、`0x2331` 仅有函数尾部布局跳转与一处对象分配大小（`0x1484 → 0x2494`，与 HASSAKU x86 相同）不同。上述命令以同名变体绑定本构建。

MEMORIA 档案引用的 46 个函数在本构建有唯一同构函数，包括子槽查找、滤镜模式 1、屏幕坐标、相机构造/投影/快照 v3、震动三角波、碰撞与淡变粒子、下落广告牌、输入更新、draw v4、图像 v3、影片 v4 及效果模板写入/读取。据此为本构建开放 MEMORIA 的运行时分支：256 子槽、x87 碰撞算术、滤镜模式 1、屏幕坐标模式 1、三角波震动、旧版正弦模式、相机类型 1/2/3 投影，以及 `CMVS_SYSTEM_MAIN/WINDOW_SIZE` 画布（`0x409c45` 起的 switch 与 MEMORIA 同构，仅 0 档多一次设置调用；本样本为 800×600）。文字创建 `0x2100 → 0x44f610` 仍为 8 槽，但在 MEMORIA 之外读取四项共享字体属性；沿用旧版文字创建及显式字体。

### 快照布局 `TextV2WindowV2`

`0x2080 → 0x459350`、`0x22b2 → 0x456100` 调用捕获器 `0x448300`，与 MEMORIA `0x445380` 只差一处结构偏移，记录标签集合相同（无 `0x6e0`、`0x8c8`）。差异在被调序列化器：文字 v2（`0x43ce40`）、窗口 v2（`0x43d0f0`：文字槽、版本 2、逻辑尺寸，再接 v1 的 1280 字节/16 按钮正文）、场景 v3（`0x423dd0`，八字头、含 `0x749` 碰撞块）、按钮 v2（`0x43eaa0`，头部写设备尺寸 +0xc/+0x10）。图像 v3、draw v4、影片 v4、相机 v3/视图 v2 与 MEMORIA 同构。

新增布局 `TextV2WindowV2`：文字与场景按 v2/v3 路径编解码，对象表沿用 MEMORIA（8 文字、4 窗口、无 `0x6e0`/`0x8c8`、256 子槽），draw 动画 v1 与旧版正弦模式，效果模板沿用 MEMORIA 的类型 2/6/7 规则。样本自带 `save000.dat` 按此布局解码，快照重新编码后与原 75,967 字节文件中的快照节逐字节一致（1 文字、1 窗口、1 场景对象）；这是唯一的原版存档对照。

### 新实现的变体

- `0x2176 → 0x452290`：窗口子对象换图，与 PURIRING `window-child-image` 同构（仅析构调用方式不同），绑定同名变体。
- `0x21c0`/`0x21c1`/`0x21c2 → 0x452860`/`0x4528f0`/`0x4529a0`：与 PURIRING `window-scale-motion` 同构，绑定同名变体。
- `0x21d4`/`0x21d5`/`0x21d6 → 0x452fb0`/`0x453010`/`0x4530c0`（`window-position-motion`）：场景 `0x21f4..0x21f6`（`0x44c980..0x44cad0`）的窗口形式。SP−4 窗口 <4，SP−8 子对象经 `0x43d1a0`（负值取窗口本体），其余参数以相同顺序传给相同的 draw `+0x80` 函数（`0x4128e0` 建立、`0x4129f0` 设键）；返回 `0x4008`/`0x4020`/`0x400c`。窗口或子对象缺失时原版只置 `+0x2860` 位 `0x10000`，Rust 显式报错。复用场景位置运动的校验与写入；`0x21d7` 未被脚本使用，保持未处理。
- `0x21ca`/`0x21cb`/`0x21cc → 0x452c10`/`0x452c70`/`0x452d00`（`window-opacity-track`）：场景 `0x21ea..0x21ec`（`0x44c3d0..0x44c510`）的窗口形式，同样调用 `0x4126a0`/`0x412780`/`0x412770`，返回 `0x400c`/`0x401c`/`0x400c`；复用场景透明度轨道。
- `0x211c → 0x44f7a0`（`logical-text`）：与 `0x2100`（`0x44f610`）相同的文字创建，SP−16/SP−20 作为构造器度量中的逻辑宽高替换设备尺寸，返回 `0x4014`，系统结果 0 为创建标志。字体预览层把这类文字的锚点与缩放乘以“设备宽/逻辑宽”（与场景逻辑缩放一样只用宽度比例；本样本 1280×960 对 800×600，两轴比例相同）。
- `0x230d`、`0x230f`、`0x231d`：与 HAROUSE `movie-control` 同构，绑定同名变体。本构建另开放播放模式 15：更新 `0x422fc0` 中帧号取音频通道 `0xb` 的位置（`0x45dd40`），取不到时用“当前时刻 − 起始时刻（`+0x104`，此模式不推进）”，按 `rate_time × max_sequence × 1000 / rate` 的整段时长取模，不看片段表。存档读取 `0x423260` 恢复模式 15，并在第 0 帧重开、以读档时刻为起点。Rust 只实现无音频的退回路径，音频同步未建模；其他构建继续拒绝模式 15。

### 按钮组指针缩放与逻辑画布

`0x221b → 0x453d90` 以 SP−12/SP−16 作为组度量的末两项（`0x2210 → 0x453c40` 用设备尺寸）。更新 `0x43efa0` 的命中测试把指针换算为 `缩放 × p / 设备`，导航跳转以 `设备 × c / 缩放` 换回，均为 32 位有符号乘除；读档 `0x449ef2` 用设备尺寸重建组，缩放丢失，按钮记录也只写设备尺寸。Rust 为本构建保存该缩放并在命中、导航及 `0x221a` 中换算，读档后清除；其他构建仍拒绝非设备尺寸。

`0x202a → 0x44ade0 → 0x424ad0` 写逻辑宽高（`+0x444/+0x448`）。`0x424a00` 沿继承位 0 查找父对象缓存比例，否则以 `0x43f2b0` 设备宽除以逻辑宽（逻辑宽为 0 时用画布宽），不读逻辑高度，与 HASSAKU 档案描述的算法一致；为本构建开放既有逻辑画布缩放。顶点生成阶段未逐条对照。

## 当前验证

- 静态 S1–S5 通过：137 个脚本、3,726,670 条指令、345 种系统命令；10 个资源包、22,477 项资源头（PB3 7,439、Ogg 14,964、CMV 71、O2 3）；样本自带 CSV2/CSS1 存档解码通过。
- 16ms、种子 0、Noto Sans CJK 字体的 R1/D1、I1–I5、V1–V5、C1/C2 通过。标题位于 `menu.ps2`，4 个可用按钮，10,866 步 / 624 帧。P3 未找到退出或返回标题控件（inconclusive）。
- 首选路线 `0.0.0.0.0.0.0` 经 7 个选择点，于 39,003,785 步 / 120,653 帧回到 `menu.ps2`，启用按钮由 4 个变为 5 个；无引擎停点。R2 因剩余 18 个分支前缀为 inconclusive；R3 覆盖 591,561 / 3,726,670 个静态位置（约 15.9%），触及 70 / 137 个脚本。
- D1 起初因影片帧在进程内的缓存身份进入状态摘要而误报；`RgbaImage` 的调试输出现不含该身份及延迟摘要缓存。
- 未进行画面抽查、原生窗口、听感或完整路线逐帧绘制验证；模式 15 影片与音频的同步、逻辑尺寸文字的绘制位置均未与原版对照。
