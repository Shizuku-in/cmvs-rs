### 命令差异与证据

- `0x2187 → 0x446ea0 → 0x420c60`：SP−4 窗口、SP−8 子槽（负数取本体）、SP−12 混合模式；draw `words[1]` 写入 0–3，其他值保持原值，返回 `0x400c`。窗口/子对象缺失时原版设置错误位，Rust 保留错误且不消耗栈；缺失 draw 时也明确拒绝。
- `0x2022 → 0x43ff50 → 0x421080`、`0x2023 → 0x43ff90 → 0x420720`：子槽上限为无符号 256，越界创建/删除忽略。窗口 `0x2178 → 0x446ab0 → 0x435b20`、`0x2179 → 0x446af0 → 0x435bf0` 复用同一表；无效窗口子对象仍报错。仅对该 profile 和哈希选择 256 项运行时表。

### 结构检查与限制

固定种子 0、16ms 帧、鼠标、Shift-JIS 字体，复制原有 CSS1 系统档到隔离用户目录；原游戏只读。

`probe-baseline` 的 S1/S3/S4/S5、R1、D1 通过：8 个资源包、27,323 项资源（2,624 PB3、24,659 Ogg、38 CMV、2 O2）；标题 `menu.ps2` 4 个按钮，10,619 步/637 帧到达，启动重放一致。

S2 普查 126 个脚本，其中 `snsy13.ps2 / 0x2937a` 遇到空表达式。原版整数求值 `0x43af80` 在立即遇到 `0x020f` 时仍读取未初始化的栈上操作数，不能合理补成零或跳过。现保留结构错误和运行时拒绝；其余脚本的结构通过不代表完整游戏兼容。

### 画布、抓图与后续停点

`0x404e00` 依据 `CMVS_SYSTEM_MAIN/WINDOW_SIZE` 选择旧版逻辑画布：0 为 640×480，2 为 1024×768，9 读取 `RESOLVING_POWER_INFO/WINDOW_WIDTH,WINDOW_HEIGHT`（默认 800×600），其余值为 800×600，并调用 `0x403430`。该逻辑仅绑定本 profile 和已核对哈希；现代构建仍读取 `WINDOW_RESOLVING/BASE`。本样本为 9、800×600。未知哈希和非法尺寸由合成回归验证。

`0x203d → 0x440390 → 0x4215c0 → 0x41c2b0` 从当前完成的设备帧构建对象图像，SP−4 现有父槽、SP−8 必须为负，返回 `0x4008`，系统结果 0 为成功。经 `0x40e640` 读取，失败时回退 `0x40e3a0`；常规 32-bit 输出强制不透明。接入现有设备帧接口，不消费暂存屏幕抓图；后端失败保持 VM/旧对象可重试。已有抓图回归增加该入口并检查像素、对象状态和栈。

- `probe-input`：I1/L0、I2/I3/I4/L1 通过。I5 在 `snky00.ps2 / 0x117ea` 停于 `0x2248`；只读核对 `0x442fb0 → 0x4523a0 → 0x4500d0` 为 0–23 音频槽的预加载，尚未实现。P3/C1 进入字体设置后触发 `0x2100` 非空字体选择，仍明确拒绝；C2 因旧版没有 `0x201d` 而在 CSS1 写入时报缺少标识，未放宽现代写入校验。
- `probe-capture-route`：接入 `0x203d` 后路线运行 138,061 步/1,124 帧，在剧情开头抓图时停于 `recording device has no completed frame`。这是 headless 探针未提供完成设备帧的限制；不能记为路线完成。R3 记录 10,984 个静态位置、8 个脚本，仅约 0.3%，且静态基数不包含结构失败脚本。
- `probe-final-start`：修正 800×600 画布后，S1/R1/D1/I1/I2/I3/I4 再次通过，启动步数/帧数不变。`scenario-frame-800/frame.png` 抽查 `snky00.ps2 / 0x7232` 第 6 个消息等待，背景/气泡/文字位于 800×600 画布内；未作原版逐像素对照。
- `desktop-readonly.log`：CPU 桌面窗口、无快照、原生音频启动 8 秒正常退出，9,243 步，保存的画面为 800×600。后端提交 `bgm35.ogg` 44.1kHz 双声道，未做听感或手动完整游玩。此前使用独立用户目录的运行在退出写 CSS1 时失败，故目前不给出可保存的启动承诺。
