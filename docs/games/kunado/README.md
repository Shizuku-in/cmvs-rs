## 相机画面旋转（2026-11-03）

修复 CPU 呈现对相机 +48/+52/+56 一律报 `camera rotation is not modeled` 的限制。证据绑定上表 x64 SHA-256：`0x140061130` 的 type 3 分支投影位置与缩放后，将 +56 乘 100、截断为 i32 并对 36000 取余；`0x140032b10` 把角度、屏幕宽高一半传给 `0x140036200`。后者先应用对象局部旋转、缩放与投影位置，再在角度为正时对每个屏幕坐标 `floor(v+0.5)`，绕相机屏幕中心按 `(360-angle/100)*0.017453292` 旋转，分量截断到百分之一后加回中心。设备半像素偏移在这之后应用。+52 仍用于投影水平偏移；复制出的 +48/+52 角度并未被该顶点变换读取，不额外施加三维旋转。证据 `local/kunado/camera-rotation-evidence.json`，SHA-256 `2d9ad598f85ed04885e2c375f64461052886be73f486d334a9dab190bdb6e4d7`。

原先失败的 I5（种子 0、鼠标、16ms、MS Gothic、无快照）现跑满 3000 帧并通过 L0；默认快照与微软雅黑同样通过，报告 `local/kunado/rotation-fixed-{01,02}/summary.json`。这修复了上述历史随机输入失败；用户报告的 `sn1010.ps3/0x32d14` CPU 停点使用同一被修复路径，但未重放其完整手动输入序列。合成回归验证 45°/90°、坐标取整、对象角度组合、负角度/多圈 setter 归一化，以及非有限位置仍拒绝；投影与软件呈现回归、Clippy、格式检查通过。桌面 release（含音频）已重建；未核对原 GPU 逐像素输出，投影旋转父对象的子图、遮罩和相机特效目标等既有未支持分支仍明确报错。
