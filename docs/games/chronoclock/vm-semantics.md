# CHRONOCLOCK VM 语义证据

## 剧情快照文字v2布局（2026-11-01）

在 `0x2080` 复核记录的三个差异基础上，独立核对本作快照构造 `0x140065fa0`、文字写入 `0x140059970`、读取 `0x140059ab0` 及公共图像写入 `0x14002a7c0`。样本身份同本页。本节取代此前“全部派生快照拒绝”的当前支持结论，保留旧记录作为历史。

文字写入依次为u16版本2、u32容量（原对象+324）、NUL字体名（+44）、两项逻辑尺寸（+344/+348）、156字节块（+8）、148字节注音块（+176）、u16字形数、每项44字节描述。与基准v3相比仅省略+328起208字节块，后续字段相应前移；字形格式不变。读取器对版本>=2跳过头部逻辑尺寸，恢复两个公共块，清空旧字形并以区域原点重置光标，再从44字节描述重建字形。当前只支持精确版本2，不扩展至未验证的旧版本。

新增显式 `SnapshotLayout::TextV2/TextV3` 选择，默认API仍用v3；runner将 `cmvs-20150405` 且基准为 `cmvs-20160201` 绑定v2，未知派生布局仍拒绝。v2读取后的禁则与布局scratch为缺省零；编码不写该块，存在扩展禁则时明确拒绝。原有公共图像特殊记录、活动场景效果等支持边界不扩大：本作8槽与基准16槽、效果类型9差异不以根格式代替，相关未实现子记录仍报错。注册表读取和原生字形像素对照不在本节范围。

原始伪代码 `local/chronoclock/snapshot-layout-chrono.json` SHA-256 `e8ad30cb6e08440c6282286e7a18970dee2680a2ea7df489b465c3302c1d33e2`。复用现有字形记录测试验证v2/v3的字节往返、布局不匹配拒绝；未知派生快照屏障测试保留。真实剧情存读档与基准回归见[研究记录](research.md#2026-11-01剧情存档v2与恢复流程)。

## 0x22ff：其他显示器使用设置查询（2026-11-01）

本作 x64 样本身份同下文。case `0x140080c44` 尾调用 `0x140078400`，通过 VM +0x7b0 的设备管理器与 `0x140003070` 取得设备；getter `0x14001c2c0` 读取设备 +0x90，将非零归一为1写入系统整数0（VM +0x14380），返回 `0x4000`。无参数、无等待、无设备修改；其他系统整数保持。IDA 把这个共用两指令 getter 命名为 `Concurrency::details::WorkQueue::Id`，不能据此解释设备字段。

初始化函数 `0x140010320` 在 `0x140011873` 调用 setter `0x14001c2b0`：输入来自 `WINDOW_RESOLVING / OTHERS_DISPLAY_USE`（缺省0），或注册表 `CR_OthersDisplayUse`，并归一为布尔。窗口移动处理 `0x140017690` 读取同一字段，非零时按窗口中心重新选择显示器并更新设备。Rust 查询使用当前加载的配置，同步支持隔离用户配置覆盖；不实现原版注册表读取，也不因此宣称已支持随窗口移动切换显示器。

本轮仅实现查询，不升级命令档案状态，仍须显式研究放行。原始反汇编、伪代码与初始化片段保存在忽略的 `local/chronoclock/other-display-chrono.json`，SHA-256 `a412b8c57615a9b07d71f1cd6f508f713ba3c0b8b17f9c71df7386f7a2f3d0a9`。一个合成测试覆盖缺省/零/正负非零、配置替换、栈和其他结果槽保留及无设备请求；流程验证另见研究记录。

本页 CHRONOCLOCK 地址绑定 x86-64 `cmvs64.exe`、image base `0x140000000`、SHA-256 `d1c4ade9551b827b8e401fc10f68a73e2525a67a217b63747898f5797894911d`。2026-10-31 已通过 IDA 输入哈希重新确认。x86 未逐条复核。

## 对象可见性 0x2026（2026-10-31）

switch case `0x14007ed2f` 尾跳到 `0x140068aa0`。参数从 SP 向下依次为：对象槽 i32、子对象 i32、可见标志 u32，共 12 字节。

- 槽号按有符号值比较 `<256`，再取 VM `+1976` 的对象指针。槽号 ≥256 或槽为空时给 VM `+12056` 置位 `0x10`；负槽可能访问表前内存，不能作为有效对象槽。
- 对象存在时，任意负子编号选择对象本身；非负编号经 `0x140038b60` 查找 `<768` 的子对象。缺失或越界子对象会得到 NULL，但调用方仍写入，不能把它解释为空操作。
- `0x140038b00` 把标志 `!=0` 的布尔值写入对象 `+6244`（`0x1864`），不要求图像或 DrawState，不改子树、绘制参数、图像或效果。
- 构造函数 `0x1400387d0` 将该字段初始化为 1。读取函数 `0x140038af0` 被绘制队列构建函数 `0x14003bfe0` 调用；后者入口在该值为 0 时立即返回，子对象入队前也检查它。静态证据支持把字段解释为可见性；尚未做原版画面对照。
- 两条正常返回路径均为 `0x400c`：前进 PC、回收 12 字节、不让出，不写系统结果寄存器。

Rust `SceneHost::set_shown` 复用 `SceneObject::shown`，现有 CPU/共享绘制队列和快照继续消费同一状态。非法槽、空对象和缺失子对象显式报错并保留 PC、参数和原对象；未建模 VM `+12056`，不伪造原版错误分支成功。参数不完整也保留挂起状态。

合成测试覆盖负子编号的 self 选择、边界槽255/子767、零/非零布尔值、保留其他状态和系统结果、栈回收、非法目标及截断参数重试；另验证隐藏子对象显示父图、隐藏父对象同时隐藏子图、恢复后像素不变。

### 与基准构建核对

基准 `cmvs-20160201` x64 的 SHA-256 为 `dc74d2001387ae1aefbdc4204216de5ebb9d3896009280720c4e7a91b42d84f5`，image base 同为 `0x140000000`。只读 PE/Capstone 核对完整处理函数 `0x14006bd70..0x14006bdf8`：case `0x14008267c`、三个栈参数、对象表、子选择、布尔归一化、错误位和返回值一致；setter `0x14003a6f0` 写 `+6244`，child getter `0x14003a760` 仅接受 `<768`。因此同一核心实现可供基准使用。此处是人工语义核对，不是通用指纹继承结果。

本节语义研究时档案仍有712条`Unreviewed`，通过显式`--allow-unreviewed`抵达。随后P2的完整指纹将387条登记为`Inherited`（含`0x2026`），另325条保持未复核；默认仍在启动`0x201f`停止。继承与人工语义/运行验证是不同证据，见[研究记录](research.md)。

## 世界坐标运动模式 0x41（2026-10-31）

### 半波模式 0x22 / 0x31（2026-11-01）

研究放行路线的新停点为 `snky24b.ps3 / 0x1e8f0 / 0x21fa`。脚本在 `0x1e7c0` 将 `34 + (参数12 << 16)` 写入局部12，随后用作运动模式。原版 `0x14002494e..0x140024964` 是模式34与49共用分支：逻辑右移16位，零扩展转f32，除100得到振幅，跳入 `0x1400248f4`。不读取周期数，也不解释 `0x8000`。共享链以 `elapsed % duration`、f32 `*180 / duration` 得角度，复用下文正弦百分位 helper，原样保留基准 X/Z，将偏移加到基准 Y。目标位置只在键边界吸附。因此这是半波模式，与 `0x41` 的360度完整周期不同；高16位全部参与振幅。

基准构建对应 `0x140025b2e..0x140025b44` 与 `0x140025ad4..0x140025b19` 的运算及控制流一致（地址、helper与常量重定位）。复用现有轨道时间、换键、结束和错误处理；未将其他未知模式降级为线性。原有运动测试表补入半周期峰值、相对位无影响、别名与高4位仍为振幅的参数，没有新增测试套件。两侧原始证据留在忽略的 `local/chronoclock/half-sine-{base,chrono}.json`，SHA-256 分别为 `bd58522e2afe9f1870d58969b5a6469a8bc9a03efdb6318b5527a66f7405d4ac` 与 `c62821e4f21fcaeebc2c22fe9224645791069b56568dc3db5d0ff0ecd8506b76`；真实路线运行结果见研究记录。

原停点为 `cdemo.ps3 / 0x1ef16 / 0x21fa`，参数前六字 `[20, 0xffffffff, 0, 1, 0x00140041, 5000]`。现已核对并实现该模式；它不是未知模式的放行或线性替代。

`0x21fa` case `0x140080251` → `0x14006b710` → DrawState `+152` 的 `0x14001f050` → 键写入 `0x140024300`。SP 向下九字依次为对象、子对象、键号、next、mode、duration、XYZ 原始位。返回 `0x4024`，回收36字节，不让出、不写系统结果。轨道不存在时 setter 不写任何内容；无效槽/子编号涉及原版错误位或空指针，Rust 继续使用显式错误策略。

帧推进 `0x140024390` 对 delta 限200ms，以u32回绕累计 elapsed；仅 elapsed < duration 时插值。模式低字节65进入 `0x140024a7d..0x140024aad`：

- 振幅为 `f32(mode >> 16) / 100`，使用完整高16位，不屏蔽高4位，也不从中提取周期数。`0x8000` 相对标志不参与该分支。
- phase = elapsed % duration；依次以 f32 求 `phase * 360 / duration`。常量 `0x1400d4d60/68/70` 分别为100、180、360。
- 经 `0x14002490e` 调用 `0x14004c690`：角度除180、乘f32 π，再转f64调用sin；与转为f64的振幅相乘后转f32，乘100、截断到i32、转f32除100，得到百分位偏移。
- 原样保留基准 X/Z，以 f32 `offset + base_y` 写 Y。即一个完整正弦周期，后半段有负偏移。目标 XYZ 不参与插值；到键边界仍吸附目标、扣时换键或返回负next，下一段不在同一帧插值。

基准构建身份见上节。只读反汇编核对其 `0x140025c5d..0x140025c8d`、共享Y写入 `0x140025aee..0x140025b19` 与 helper `0x140025310`：完整高16位振幅、360度、百分位正弦与基准Y相加一致。因此复用同一核心分支；尚不表示其他未复核模式兼容。

核心合成测试覆盖四分之一/半/四分之三周期、相对位无影响、高4位仍计入振幅、X/Z 的NaN/负零原始位保留、终点吸附；命令测试覆盖安装/启动/清栈及现有200ms限幅。真实运行在下一未实现命令前仅采到1个活动帧，与独立Python逐位一致，不能据此宣称整段动画或原版画面已验证。

## 显示字节计数 0x2119（2026-10-31）

`0x14006f9f0`：SP-4文字对象号，SP-8字符串引用，经 `0x140068580` 解析。有效对象范围0..11，表位于VM `+4128`；空对象/槽≥12置错误位 `+12056 |=0x1000`，负槽可能访问表前内存。有效对象调用 `0x14002db90`，结果写系统整数0（VM `+82816`）。正常返回 `0x4008`，不让出，不改变文字布局、光标或字形。

计数函数只读字符串：普通单字节计1，双字节计2（lead范围81..9f、e0..fc，`0x140007070`）；`\\c`、`\\n`、`\\t`跳过2字节，`\\w`连同任意非零selector跳过3字节。`{base/ruby}` 仅计base中的双字节对，base中的ASCII不计，ruby全部不计。未知转义在原版不推进，会死循环；缺少分隔符/尾字节则越界。Rust 复用有界注音解析并明确报错，保留PC、参数、文字状态和结果，不模拟这些未定义行为。

基准 x64 对应 `0x140072f90` → `0x14005b280` 的完整函数亦已只读核对：参数、字节/注音计数、结果0、错误位及返回码一致。合成测试覆盖空串、ASCII/半角/双字节混合、全部控制码、混合注音、双字节尾部为反斜杠，以及非法对象和截断/未知转义的可重试错误。真实 `cdemo.ps3 / 0x10396` 返回22。

## 归档类型 0x201f（2026-10-31 复核）

档案状态 `reviewed`（[分派层设计 4.2](../../design/dispatch.md#42-复核记录)）。指纹工具因可写全局依赖未继承，本节为人工复核记录。默认 trace 在 `start.ps3 / 0x1a` 执行它，栈顶为 10。

| | CHRONOCLOCK x64 | 基准 `cmvs-20160201` x64 |
|---|---|---|
| exe SHA-256 | `d1c4ade9…911d`（见页首） | `dc74d2001387ae1aefbdc4204216de5ebb9d3896009280720c4e7a91b42d84f5` |
| case 入口 | `0x14007ecd9` | `0x140082619` |
| 写入函数 → 全局 | `0x140007030` → `0x1400fb3dc` | `0x140008040` → `0x14010143c` |
| 唯一读取函数 | `0x140007040` | `0x140008050` |
| 读取函数的调用者 | `0x140026300`、`0x1400273d0`、`0x140034260`、`0x1400362f0` | `0x140027730`、`0x1400285b0`、`0x140035b00`、`0x140037e90` |

**处理函数相同。** 两边都从 VM `+0x14268/+0x14270` 取 SP-4 的 32 位值，调用写入函数存入全局，返回 `0x4004`：前进 PC、回收 4 字节、不让出、不写系统结果。写入与读取函数各只有一条 `mov`，全局除这两个函数外没有其他引用。

**读取方是归档类工厂，取值 10 的结果一致。** 四个调用者都按该值构造归档对象（各自用于不同的资源注册路径）。第一个是 if 链，只区分 3/5/6/10，其余走默认，两边结构相同；其余三个是 switch：

| 取值 | CHRONOCLOCK 构造函数 | 基准构造函数 |
|---|---|---|
| 1 | 默认（`0x14005d960`，0xA0 字节） | `0x1400011e0`（0xA0 字节） |
| 2 | 默认（同上） | `0x140001730`（0xA0 字节） |
| 3 | `0x14005d960` | `0x140060c30` |
| 5–9 | `0x14005e420`、`0x14005f270`、`0x14005fac0`、`0x140060590`、`0x140060fe0` | `0x1400617a0`、`0x140062590`、`0x140063160`、`0x140063870`、`0x1400642b0` |
| 10 | `0x140001420`（0x1C8 字节） | `0x140001fb0`（0x1C8 字节，CPZ6，见[《アマツツミ》VM 语义](../amatsutsumi/vm-semantics.md)） |
| 其他 | `0x14005d960` | `0x140060c30` |

差异只在取值 1、2：基准新增了两个归档类，CHRONOCLOCK 对它们走默认分支。本作脚本传入 10。归档类内部（查找、解密、校验）不在本条复核范围内，它们由资源注册与加载命令及 CPZ6 格式层分别覆盖；本作 86 个来源已通过现有 CPZ6 解码与结构检查。

**Rust 实现不读取该值。** `BootstrapHost` 只把原始值记入设置表，没有代码读取 `0x201f` 的设置；封包格式按文件签名识别（[档案设计第 8 节](../../design/engine-profiles.md#8-格式层)）。因此取值 1、2 的差异不会影响 Rust 行为，本条按根语义执行。将来若 Rust 开始解释这个值，1、2 的含义因构建而异，必须改为 `Variant`。

方法：CHRONOCLOCK 在当前 IDA 会话中只读查询（未改名、未注释、未保存），输入哈希已确认；基准用 IDA 9.4 `idat` 批处理读取本地分析库 `local/chronoclock/p2-amatsu-x64.i64` 的临时副本，输入哈希同上表。x86（CHRONOCLOCK `0x70d92`、基准 `0x74012`）未单独复核，依据同构建判定。

## 位变量范围初始化 0x2091（2026-10-31 复核）

档案状态 `reviewed`。两个构建的 x64 身份分别为页首 CHRONOCLOCK SHA-256 `d1c4ade9551b827b8e401fc10f68a73e2525a67a217b63747898f5797894911d` 和基准 `cmvs-20160201` SHA-256 `dc74d2001387ae1aefbdc4204216de5ebb9d3896009280720c4e7a91b42d84f5`，image base 均为 `0x140000000`。

| 位置 | CHRONOCLOCK x64 | 基准 x64 |
|---|---|---|
| case → 处理函数 | `0x14007f1fa` → `0x14006eb60` | `0x140082b61` → `0x140072100` |
| 单位写入函数 | `0x140082330` | `0x140085ce0` |
| 位区 / 校验副本 | `0x140129ea0` / `0x140131eb0` | `0x14012ff00` / `0x140137f10` |
| 错误标志指针 / setter | `0x140131ea0` / `0x140082320` | `0x140137f00` / `0x140085cd0` |
| setter 唯一调用者（构造函数） | `0x140015e20` | `0x140016e20` |

**完整处理函数和单位写入函数语义相同。** VM `+82544/+82536` 为 SP 和栈基址，SP-4 是有符号起点，SP-8 是有符号数量，SP-12 以非零归一为 true。以 32 位加法求 end，按有符号比较从 start 逐位写到 end（不含），正常返回 `0x400c`：前进 PC、回收 12 字节、不让出，不写系统结果。start ≥ end 时原版不写位区。原版不检查负数、越界或加法回绕，不把这些情况视为安全输入。

单位函数对非负索引用 `index / 8` 定位字节、`1 << (index % 8)` 定位位，只修改该位，随后把整字节同步到校验副本。修改前若两个字节不等，给错误标志指针所指 dword 置位 `2`。两个构造函数均把该指针绑定到 VM `+12056` 并清零该字段；这不是初始化值来源。指纹未继承的原因是可写指针与内嵌数组地址、映像基址 LEA 位移，不能直接忽略这些操作数推断相等。

Rust `Bootstrap::try_handle` 复用 `State::fill_bits`：在已支持的非负且不溢出容量范围内，逐位布尔值与原版一致，范围外位仍保持原状态或未知。Rust 不模拟原版冗余校验副本及其不一致错误位；该处理与根构建相同，不新增本作专用初值。负参数、超出研究容量及加法溢出继续显式报错，保留 PC、栈与变量，而不模拟原版无界内存行为。现有合成初始化测试覆盖非零布尔化、清栈和范围外未知值；真实默认启动传入 start=0、count=65536、value=0。
