### 字段依据

这些映射按各字的写入、重置与查询角色建立，不只按相同布局配对。下表均为32位全局单元，地址为 RVA；逻辑区域沿用 IR 的 `object`，物理根为 `image`。

| 逻辑字段 | 基准 RVA | 目标 RVA | 交叉证据 |
|---|---|---|---|
| `clock.current_tick` | `0x101430` | `0xfb3d0` | 重置把时钟源结果写入此字；`0x2008` 模式0读它，`0x2009` 用它减前一时刻 |
| `clock.previous_tick` | `0x10142c` | `0xfb3cc` | 重置写与当前时刻相同的值；增量查询的减数 |
| `clock.accumulated_tick` | `0x101434` | `0xfb3d4` | 重置清零；模式非零的时刻查询读它 |
| `clock.frame_delta` | `0x1013f8` | `0xfb398` | 重置清零；模式非零的增量查询读它 |
| `clock.mode` | `0x101438` | `0xfb3d8` | 模式 setter 保存 `ecx` 后重置上述四字；两个查询均用它与0比较 |
| `button_layout.shifted_layout` | `0x101448` | `0xfb3e8` | `0x2087` 写参数非零归一化值；getter 供按钮状态布局函数读取 |

时钟重置函数基准 `0x140008cb0` / 目标 `0x140007ca0`，模式 setter 为 `0x140008cf0` / `0x140007ce0`。两边分别在指令序号7/8、10/11写当前/前一时刻、清增量/累计时刻；模式 setter 在序号2写模式。逐指令核对两侧重置及 setter 的全局引用和源值流，得到表中配对。基准查询角色亦见[已有语义记录](../amatsutsumi/vm-semantics.md)的 `0x2008` / `0x2009`；目标 IDA 只读查询确认重置、帧更新、查询的读写关系。基准与目标四个独立证据函数（重置、模式 setter、布局 setter、getter）各33条指令另经原 exe 核对全部字节和引用目标。

布局 setter 为基准 `0x140008060` / 目标 `0x140007050`，getter 为 `0x140008070` / `0x140007060`；getter 的调用者是按钮布局函数 `0x14005f180` / `0x14005be30` 的指令9。基准角色另有[按钮组数据层记录](../amatsutsumi/research.md#按钮组数据层)。两边原 PE 的这些地址均位于可写节的零填充尾部；IDA 显示的 `ffffffff` 不作为初值证据，提取器仍使用共享的任意逻辑初态。

### 误接受与未知项审计

- 独立参考公式核对两侧共10,374组共享输入（20,748次契约执行）：时钟 mode 取0、1、2、`0xffffffff`，另四字各取0、1、2、`0x7fffffff`、`0x80000000`、`0xffffffff`；布局参数取同组六值。核对全部最终状态、读取顺序、唯一写入、返回和回收量，包含32位回绕；没有发现误接受。这是补充检查，等价结论仍来自完整规范形式一致。
- 在目标导出的副本中分别反转时刻条件、替换时刻字段、反转增量条件、减法改加法、反转布尔条件、修改回收量：六项均为 `different`，且原 exe 绑定均拒绝修改后的导出。把布局写入改到未映射字时为 `unknown`，不进入证据接受。
- 复核三条接受命令之外的时钟重置、模式切换仍为 `unknown`；增加查询映射没有消除外部时钟、其他全局量和复杂计算的阻断。主要剩余分布与 M2a/M2b 一致，窗口/场景内部指针没有仅凭候选登记。
