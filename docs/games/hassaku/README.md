## 构建与语义证据（2026-11-07）

两架构均有 864 个分派项，597 个处理命令保持 Unreviewed、267 个 NoOp；游戏 ID `0x17300001` 来自启动脚本 `0x201d` 的常量实参。x64 PE 时间戳 `0x4d03477d`，链接器 9.0，switch `0x14007466c`、表 `0x140076864`、default `0x1400746ba`；x86 对应 `0x4d0347c7`、`0x460f55`、`0x462288`、`0x460f89`。默认放行未复核命令，运行通过不提升证据等级。

以下语义证据只绑定上表 x64 SHA-256；x86 仅登记分派与身份。原游戏只读，分析副本和测试输出保存在忽略目录 `local/hassaku/`，不提交真实素材、脚本、存档或 IDA 数据库。

- 子槽：`0x1400332a0` 查找及场景写入 `0x140033000` 均限制 256 项；运行时与剧情恢复均应用该上限。
- `0x204e → 0x140074a94 → 0x140062b40` 读取父槽、子槽、模式，负子槽取本体；`0x140033b20/0x140033b30` 将 draw 坐标模式写为 1/0，返回 `0x400c`。仅绑定 `screen-coordinates` 变体。
- `0x218b → 0x140075788 → 0x14006b700 → 0x140033b00 → 0x14001ad60`：窗口槽、子槽、两个浮点缩放值；后两项经 xmm1/xmm2 原位写入 draw `+72/+76`，返回 `0x4010`，保留系统结果。负子槽取窗口本体；缺失窗口、子对象或 draw 在 Rust 中显式报错并保留参数。仅绑定 `window-draw-scale` 变体。

## PB3 type 7/8

本构建 x64 分发 `0x14002f3d0` 的 type 7 调用 `0x140091f00`：偏移 52/56 是相对 60 的标记/字节流起点；使用既有 2048 字节字典、起始写入 2014、MSB 优先 split LZSS，一次解出宽×高×4 字节交错 BGRA，不进行通道差分。type 8 在 `0x14002f60b` 解出与 type 6 相同的 32 字节参考名，二者共用 `0x140092040` 的 8×8 块替换；复用既有参考读取、循环/深度/累计预算和缓存提交规则。type 7/8 仅接受已验证的 32 位输入；type 4 继续拒绝。

`balloon.cpz` 的 `fk2-as_c202.pb3`（type 8）及底图 `fk2-as_c201.pb3`（type 7）均为 512×512。独立 Python 使用 BGRA 字节流解码和逐行块复制，最终输出与 Rust RGBA 逐字节一致：

## 逻辑画布缩放修复（2026-11-07）

桌面实测在 `snpr01.ps2 / 0x14d2e` 报 `logical screen scaling is not modeled`。扩大序章逐帧绘制后，于同脚本 `0x292cc` 复现同类错误：槽 29 的逻辑尺寸与源矩形均为 1920×1080，实际画布为 1280×720，并带有遮罩转场。

上述 x64 样本的 `0x140033d40` 沿父对象继承位 0 查找逻辑宽度，以设备宽度除以该宽度；宽度为零时采用画布宽度，逻辑高度不参与计算。`0x140033e10 → 0x14001bc10` 将比例传给顶点生成器，纹理 `0x14001dba0` 与纯色 `0x14001eb60` 都在局部变换、位置相加后对两个轴应用同一比例，再减半像素偏移。实现仅对已绑定身份的 HASSAKU profile 开放，并在场景恢复后保留；其他 profile 继续维持原有限制。

CPU 与共享 GPU 绘制命令现支持相应 2D 图像、纯色及继承子对象的逻辑缩放；遮罩仍按源纹理坐标取样，不随目标几何改变。合成回归覆盖宽度比例、忽略逻辑高度、变换顺序、半像素位置、子对象继承、恢复与身份边界，以及缩放遮罩的 CPU 输出和共享 shader 参数。相机投影的非单位逻辑比例、旋转遮罩及缩放对象的第二纹理仍显式拒绝。

`render-scale-mask-fixed.log` 在隔离用户目录中推进 500 次消息等待，完成 334 帧非单位逻辑尺寸场景的 CPU 合成，随后存读档成功；`scaled-mask.png` 已查看。该复测覆盖实际序章素材和转场，不代表完整路线绘制或原生输出逐像素对比。
