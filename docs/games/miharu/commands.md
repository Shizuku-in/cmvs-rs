# 《みはる》命令映射

CVNS 系统命令到运行时命令的翻译记录，机制见[引擎档案层第 16 节](../../design/engine-profiles.md#16-cvns-家族与命令翻译2026-11-14)。地址绑定 `cvns.exe` SHA-256 `8e6044466b928d77f0a94a0d0f32fe48190596bf628115598881c2aa3a4885aa`（x86，image base 0x400000）。

每条映射单独一节，标题以 CVNS 命令号开头（档案的 `review=` 指向本文件，测试会检查标题存在），内容包括：

- CVNS 处理函数 RVA；
- 参数个数、顺序和类型，返回标志（低字节是弹出的参数字节数）；
- 行为摘要；
- 对应的运行时命令，以及与 CMVS 实现的差异和依据。参数顺序或语义不同的命令不能直接映射到 CMVS，改为 `0x2400` 起的 CVNS 专有命令。

约定：参数按被调方顺序写，SP-4 是最后压栈的一个。处理函数都先把参数读到引擎 `+0x69d4` 起的暂存字段，这些字段脚本读不到，下文不再重复。CVNS 专有命令的运行时编号是 `0x2400 + CVNS 命令号的低位`，例如 `0x2002 → 0x2402`。

## 启动：引擎设置

### 0x2002 → 0x2402 帧间隔

`0x454080`：SP-4 交给 `0x473b50`，写入帧计时器（全局 `0x51b424`）`+0x74`，原值保存到 `+0xb0`；返回 0x4004。主循环 `0x473a10` 每次把下一帧时刻加上这个间隔并计数，`0x473ae0` 初始化时同样设置它，每秒的帧数统计另在 `+0x1c/+0x2c`。启动脚本传 17（约 60 帧/秒）。CMVS 的 `0x2002` 不取参数、只把引擎 `+0x3c` 写进系统结果，不是同一条命令，所以改为 CVNS 专有。运行时只记录这个值（`Bootstrap::settings`），帧节奏仍由宿主决定。

### 0x202d → 0x242d 未读取的设置

`0x4694e0`：SP-4 写入引擎 `+0x6060`，返回 0x4004。这个字段只在复位函数 `0x41f3c0` 中清零，没有找到按位移读取它的代码。CMVS 的 `0x202d` 是另一条命令。运行时只记录参数。

### 0x202f → 0x242f 封包读取器版本

`0x469530`：SP-4 交给 `0x472b60` 写入全局 `0x51b418`，返回 0x4004。资源注册 `0x412230`/`0x43c480` 据此创建读取器：1 为 `CPackCode1024V2`（CPZ2），其他值为 `CPackCode1024`（CPZ1），类名来自 RTTI。启动脚本传 1。cmvs-rs 按封包签名识别 CPZ1/CPZ2，所以运行时只记录参数。

### 0x20ac → 0x24ac 混音总音量

`0x4597e0`：SP-4 截到 100 后调用 `CDvSound` 虚表 +0x54（`0x412820`），写入声音对象 `+0xa4`（构造时为 100）；返回 0x4004。软件混音 `0x412bf0` 用它乘以各声道的音量。启动脚本传 50。PURIRING 的 `0x20a5` 是同类的设备增益，但刻度是 /256，所以这里是 CVNS 专有命令，换算成 /256 交给后端的 `set_mixer_gain`；25 的倍数以外会向下取整。

## 启动：变量区

位区（`0x501d20`，0x8000 字节）、整数区（`0x4bdd18`，4096 个）都有镜像区（`0x509d20`、`0x511d20`），写入函数 `0x469ac0`/`0x469c40` 同时写镜像，镜像不一致时置篡改标志。字符串区 `0x4c1d20` 有 256 个、每个 1024 字节，写入 `0x469cd0` 忽略 256 以上的槽，读取 `0x469d00` 把 256 以上映射到 0。布局与 CMVS 根档案一致，只有字符串槽数不同（CMVS 128 个）。

### 0x210e → 0x2090 变量篡改检查开关

`0x45fab0`：引擎 `+0x6034` 置 1，返回 0x4000。主循环 `0x405b5f` 在它非零时每帧调用 `0x469e40`，轮流比较位区、整数区与镜像。CMVS 根档案 `0x2090` 写 `+0x2f34`，主循环 `0x14000e55a` 同样据此调用 `0x140086010`，两个检查函数的逻辑相同。

### 0x2108 → 0x2091 位区初始化

`0x45fad0`：SP-4 起点、SP-8 个数、SP-12 初值，逐位调用 `0x469ac0(i, 初值 != 0)`；返回 0x400c。与 CMVS `0x2091` 的参数布局和语义相同。

### 0x2109 → 0x2092 整数区初始化

`0x45fb90`：同上，逐个调用 `0x469c40(i, 初值)`；返回 0x400c。与 CMVS `0x2092` 相同。

### 0x210a → 0x2094 字符串区初始化

`0x45fc50`：SP-12 是字符串引用，经 `0x453f90` 解析（编码与 CMVS 相同：高两位 0 文本段、1 脚本数据、2 字符串变量、3 栈帧），逐槽 `lstrcpyA`；返回 0x400c。与 CMVS `0x2094` 相同。启动脚本初始化 0–127，128–255 是持久区（见 `0x210d`），尚未建模。

### 0x210b → 0x250b 持久位区起点

`0x45fd20`：SP-4 写引擎 `+0x5b78`（构造默认 0x1000），返回 0x4004。系统存档写入 `0x420460`（CSS0，`save000.dat`）保存从这里（按字节，`>> 3`）到位区末尾的内容。启动脚本传 2048。CMVS 的持久范围是固定的，没有对应命令。

### 0x210c → 0x250c 持久整数区起点

`0x45fd70`：SP-4 写 `+0x5b7c`（默认 0x400），返回 0x4004；系统存档保存该起点到 4096。启动脚本传 1024，CMVS 固定从 2048 开始。

### 0x210d → 0x250d 持久字符串区起点

`0x45fdc0`：SP-4 写 `+0x5b80`（默认 0x20），返回 0x4004；系统存档保存该起点到 256。启动脚本传 128。

## 启动：资源路径

注册函数先用 `0x41f600` 取游戏根目录再拼上路径，然后交给资源表。

### 0x2020 → 0x2010 脚本包

`0x458ec0`：SP-4 槽号、SP-8 路径，写入资源表 `+0x3668`（`0x412230`，槽号大于 4 时忽略）；返回 0x4008。CMVS `0x2010` 参数相同，5 个槽；越界槽 CMVS 实现报错，原程序忽略。

### 0x2021 → 0x2011 图像包

`0x458fa0`：同上，资源表 `+0x3664`（`0x43c480`，槽号大于 10 时忽略，11 个槽）。启动脚本注册 chip、bg、stand、event 到 0–3。CMVS `0x2011` 有 10 个槽，比这里少一个。

### 0x2022 → 0x2012 音效包

`0x459080`：资源表 `+0x366c`（5 个槽）。

### 0x2023 → 0x2013 音乐目录

`0x459160`：资源表 `+0x3670`（5 个槽）。

### 0x2024 → 0x2014 语音包

`0x459240`：资源表 `+0x3674`（5 个槽）。

### 0x2025 → 0x2425 视频目录

`0x459320`：SP-8 是路径，SP-4 读入后不再使用；拼上根目录后写引擎 `+0x3678`，返回 0x4008。语义同 CMVS `0x2015`，但 CMVS 只有一个参数（SP-4 路径，返回 0x4004），所以作为 CVNS 专有命令，路径写入与 `0x2015` 相同的表。

### 0x2026 → 0x2426 存档目录

`0x4593b0`：SP-8 路径、SP-4 不用，写引擎 `+0x3e78` 并调用 `0x41fab0`；返回 0x4008。对应 CMVS `0x2016`，处理方式同上。

## 启动：存档菜单

### 0x21a1 → 0x25a1 存档菜单扫描

`0x467a20`：SP-4 按无符号截到 256，写引擎 `+0x5c28`；先用 `0x46d570` 删掉多余的菜单项，再由 `0x46d5f0` 逐槽读取 `%ssave%z3.dat`（文件号是槽号 +1）的头部，签名 `CSP1`..`CSP9` 的槽启用读取菜单项并显示偏移 16 的标签，最后 `0x46d490` 勾选最新的槽；返回 0x4004。排序键 `0x46d9e0` 与 CMVS `0x140093070` 相同，严格大于才更新最新槽。与 CMVS `0x22b3` 的差别：签名是 `CSP`、文件号从 1 开始（`save000.dat` 是 CSS0 系统存档）、负数不按 10 处理。所以作为 CVNS 专有命令，复用 `SaveMenu` 的扫描逻辑（`SaveMenu::scan_cvns`）。启动脚本传 180（`cvns.cfg` 的 `SAVE_COUNT`）。

### 0x21a2 → 0x22b4 第二组菜单开关

`0x467b10`：SP-4 规范为布尔值，`0x46d400` 无条件启用子菜单位置 0、按该值设置位置 1，并写引擎 `+0x7140`；返回 0x4004。与 CMVS `0x22b4` 相同。

## 启动：窗口与光标

### 0x21d4 → 0x2098 登记光标

`0x469300`：SP-4 字符串引用，`0x470950` 把名称复制进 0x84 字节的链表节点（名称最多 127 字节）并追加到表尾，返回从 1 开始的编号，写入系统结果 0（引擎 `+0x17398`，表达式标签 0x10f 槽 0..6 读 `+0x17398..+0x173b0`）；返回 0x4004。与 CMVS `0x2098` 相同。

### 0x21d5 → 0x2099 选用光标

`0x469370`：SP-4 编号交给 `0x4709e0`：与当前编号相同时不做事；否则恢复窗口类原光标并销毁旧光标，非零编号沿链表找到名称，拼上路径后 `LoadImageA` 并 `SetClassLongA`；返回 0x4004。编号不存在时原程序不改光标，CMVS 实现报错。与 CMVS `0x2099` 相同。

### 0x2178 → 0x2160 窗口标题

`0x464bf0`：SP-4 字符串引用交给 `0x40d6a0`，复制到窗口对象 `+0x120` 后 `SetWindowTextA`；返回 0x4004。与 CMVS `0x2160` 相同。

### 0x21a6 → 0x22b0 缩略图尺寸

`0x467970`：SP-4 宽写 `+0x5b8c`、SP-8 高写 `+0x5b90`，两者都非零时 `+0x5b88` 置 1；返回 0x4008。与 CMVS `0x22b0` 相同。启动脚本传 80×60（CMVS PURIRING 是 150×90）。

### 0x2168 → 0x208f 窗口图标

`0x464b20`：SP-4 名称拼上游戏根目录，`LoadImageA(IMAGE_ICON)` 成功时向主窗口发 `WM_SETICON`；返回 0x4004。与 CMVS `0x208f` 相同。

## 启动：系统存档与脚本

### 0x21c0 → 0x25c0 读取系统存档（CSS0）

`0x465240` 调用 `0x4208e0`，无参数，返回 0x4000。读取存档目录（`0x2026` 注册的 `+0x3e78`）下的 `save000.dat`：头部 600 字节，签名 `CSS0`、`+4` 为 600、`+540` 为数据结束位置（600 + 压缩长度）、`+544` 模式 1、`+546`/`+548` 两个随机密钥字节、`+552`/`+556` 两个名称列表的条数、`+560` 压缩长度、`+580` 解压长度；数据后跟 u16 字节和。记录的结束位置加 2 等于文件长度时校验字节和，不符则整个跳过读取。解密为 `((h[546] + key[i]) ^ (b - h[548])) - 64`，密钥 `PURPLE YUKO KAWAI ARC CHECK`；解压 `0x46fe40` 与 CSS1 的 LZSS 相同。内容依次是位区从 `0x210b` 起点（按字节）到末尾、整数区从 `0x210c` 起点到 4096、字符串区从 `0x210d` 起点到 256（各以 NUL 结尾），再是两个名称列表（`0x4217c0` 清空、`0x4218d0` 追加；条数为 0 时不动原列表）。写入端是 `0x420460`。CMVS 的系统存档是 CSS1，范围和布局都不同，所以作为 CVNS 专有命令实现（`system_save::Css0Save`）；Rust 对长度不符、校验和不符和尾部多余数据一律报错，不按原程序静默跳过。样本目录中的 `save/save000.dat`（2697 字节）解码与写回变量区通过。

### 0x2014 → 0x2083 存档版本字段

`0x45fa40`：`(SP-4 << 16) | SP-8` 写入引擎 `+0x6030`（构造默认 0x10000），返回 0x4008。快照构建 `0x44ebf0` 把它写进 `CSP1` 头的偏移 8。CMVS 根档案 `0x2083` 同样把两个参数打包写入 `+0x2f30`（构造默认 0x10000），供快照使用；两者的字段还都紧挨着 `0x2090`/`0x210e` 的检查开关。

### 0x2012 → 0x2412 进入公共脚本

`0x45f980`：SP-4 名称交给 `0x44dfc0(名称, 4)`，返回 0。载入脚本到唯一的公共槽（引擎 `+0x7148`），弹掉 4 字节参数后依次压入重复计数、`pc + 2` 和当前槽号，跳到公共脚本入口，槽号设为 1；脚本用 0x414 返回。栈帧与 CMVS `0x2081` 的 `Machine::transfer_stack` 完全一致，但 CVNS 只有名称一个参数、没有槽号，所以作为 CVNS 专有命令实现：固定使用公共槽 0，参数字节数为 4（`Machine::enter_common_with`）。原程序会直接替换正在运行的公共脚本，Rust 实现与 CMVS 一样报错。

### 0x2010 → 0x2080 替换主脚本

`0x45f920`：SP-4 名称交给 `0x44de50`，随后 `0x44ebf0` 构建快照，返回 0。`0x44de50` 停用 64 个回调中属于槽 0 的项（目标置 -1），把名称追加到名称列表 1，载入新的主脚本（`0x44e1b0` 清空栈并从入口执行）。快照构建 `0x44ebf0` 对 VM 唯一可见的影响是位变量 0 先置 1、最终清零，与 CMVS `0x2080`（`0x140080530` 停用槽 0 的回调，快照见 `snapshot-format.md`）一致。名称列表 1 的追加在 CMVS 实现中同样未建模。
