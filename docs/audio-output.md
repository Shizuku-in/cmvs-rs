# 可选原生 Ogg 音频与影片时钟

默认核心仍无第三方依赖，默认桌面仍使用记录后端。
`audio-output` 功能引入固定版本 lewton 0.10.2（Vorbis）、rodio 0.21.1（混音/播放）及 cpal 0.16.0（原生设备）。
项目自身禁止 unsafe，没有新增 C++ 运行核心，没有调用原游戏 DLL。

```powershell
cargo run --offline --release --features desktop,audio-output --bin cmvs-desktop -- "E:/Download/AMATSUTSUMI" --encoding shift-jis --continue-without-snapshot --audio native
```

`--audio record` 或不提供该参数继续记录请求，不打开音频设备。
不含 `audio-output` 功能时请求 `native` 明确报错；设备打开失败也报错，不自动伪装成成功播放。
Windows 已完成原生运行检查；其他系统的音频设备、构建和延迟尚未验证。

## 通道与资源

- 六个 SE 通道：0x20b0 准备，可选立即启动；0x20b1 启动已准备但未播放的声音，启动时应用循环标志；0x20b3 停止并释放。
- 两个 BGM 通道：0x20a0/0x20a4 新/旧通道切换、无淡变时先停止两通道、淡入/淡出和同步音量；0x20a2 淡出结束后释放，0x20a1 立即停止。
- 影片音频使用单独的通道，读取 CMV 索引指定的 Ogg 范围；播放器销毁、影片结束或到达帧上限时释放。

SE 按 0x2012、BGM 按 0x2013 注册的四个槽依序查找，复用既有目录/CPZ6 只读读取器，归档资源验证校验和。
只接受已核对的 `.ogg` / Vorbis、单声道或双声道、8..192 kHz；其他编码显式报错。
原版通过路径对象 +8224 对外部文件的备用打开方式未实现，缺失 BGM 明确报错，不任意扫描其他目录。
语音命令尚未实现；当前品牌和标题语音是经 SE 命令播放的声音。

输入压缩字节（双文件合计）上限为 64 MiB，单个 PCM 包上限为 65536 个样本。
只保留压缩字节和当前解码包，不缓冲整段 PCM；循环时重新建立解码器。
拒绝中途改变声道/采样率的串联流。初次解码失败发生在修改活动通道之前；后续解码和设备错误由每帧 update 报告并停止桌面运行。
输出在音量应用前转换为原版使用的饱和 i16 PCM 精度；检查工具保留原始浮点解码值。

## 双文件 BGM 证据

`cmvs64.exe` SHA-256 仍为 `dc74d2001387ae1aefbdc4204216de5ebb9d3896009280720c4e7a91b42d84f5`。
`0x140088b00` 经 MOG 对象 vtable+40（`0x14008c590` → `0x14008c1d0`）将两个文件交给 `MOG_InputMemory2`。
`0x14008c2f0` 在当前段结束且循环参数非零时调用 `MOG_Replay`。

只读反汇编本作 `mog2x64.dll`，SHA-256 `c51ba0c33e0153492b6cb2688701b35f0ddae309828fc21a7631ac54abb5b205`，image base `0x180000000`：

- `MOG_InputMemory2` / `0x180001b60`：开启双文件标志 +0x104，当前段 +0x108 = 0，初始化两段状态。
- `0x1800013e0` 按 +0x108 选择读取第一或第二个文件。
- `MOG_Replay` / `0x180002770`，尤其 `0x1800027b8` 后：双文件时置 +0x108 = 1 并复位第二段；单文件复位第一段。

因此开启循环时先播第一段一次，再循环第二段；关闭循环时只播第一段。
标题使用 `bgm41v.ogg` → `bgm41.ogg`。这里没有将两段混合，也没有在每轮循环重播前奏。
DLL 仅作静态行为证据，不运行、不分发其源码或反汇编结果。

## 音频时钟与误差边界

原版 `0x140037bb0` 从设备通道 2 的 `0x140087870` / `0x1400877b0` 获取毫秒位置，负值表示通道不再活动。
新 `AudioBackend::movie_clock` 区分虚拟时钟（None）、正在播放的绝对毫秒位置和结束。
记录后端保留显式 delta；原生后端使用 rodio `Sink::get_pos`，不再向影片额外累加墙钟 delta。
时钟短暂滞后不回退画面；同一目标帧不重复解码；音频结束立即销毁影片，解码失败保留旧时间/帧/图像。

`get_pos` 是混音器消费源的进度，并非声卡 DAC 的硬件时间戳，rodio 内部约每 5ms 更新。
设备排队和驱动缓冲带来的音画偏差尚未测量或校准，不宣称采样级同步。
BGM 淡变按宿主帧更新线性增益；停止后设备已排队的短缓冲可能仍需时间排空。

## 验证

`cmvs-audio` 不打开设备，逐包解码 Ogg 或 CMV 的音轨，报告格式/计数/峰值；可创建新的交错小端 f32 PCM 文件，拒绝覆盖：

```powershell
cargo run --offline --release --features audio-output --bin cmvs-audio -- "E:/Download/AMATSUTSUMI/data/video/op.cmv"
cargo run --offline --release --features audio-output --bin cmvs-audio -- "E:/Download/AMATSUTSUMI/data/music/bgm41v.ogg" --pcm <新文件.f32>
```

Python 调用本机 FFmpeg，比较四份真实输入的完整交错 f32 PCM，样本数全部相同：

| 输入 | 声道 / Hz | 样本数（含所有声道） | 最大绝对误差 |
|---|---|---:|---:|
| bgm41v.ogg | 2 / 44100 | 759098 | 5.96e-7 |
| bgm41.ogg | 2 / 44100 | 8154886 | 6.56e-7 |
| sys301.ogg | 1 / 44100 | 66760 | 5.96e-7 |
| op.cmv 的 Ogg | 2 / 44100 | 10683648 | 6.56e-7 |

浮点解码不是逐字节相同；四份 RMSE 均低于 8.74e-8，未与原版 mog2x64 的 PCM 做逐样本对照。
OP 解码输出约 121129ms，CMV 帧上限约 121125ms；结束由音轨状态或帧上限决定。

Windows 原生设备报告 192000 Hz / 双声道，由后端重采样。175 秒有界运行完成品牌 SE、标题两段 BGM、淡出、完整 OP 音轨与返回标题，退出码 0。
日志记录 OP 源位置从 10002ms 持续推进到 120087ms，随后结束；第 140408 步进入 main.ps3、第 140737 步进入 menu.ps3，到期共 152856 步。
导出结束画面为完整标题；日志证明设备源在消费，不代表已经人工听音确认音质或测量延迟。
最终构建另以 24 秒检查品牌 SE 和标题前奏/循环切换，正常退出（22386 步）。
沙箱内原生音频曾以 Windows 0xC0000008 无效句柄异常退出；正常桌面权限运行通过，这是当前测试环境限制。

新增一个无依赖的影片绝对时钟/结束/失败回滚测试，以及五个可选音频测试：合成 Vorbis 包、双文件切换、单文件循环、畸形输入、淡变端点。
测试仅包含生成的 440/880 Hz 合成音频，来源与命令见 tests/fixtures/audio/README.md；真实素材和 PCM 输出不受 Git 跟踪。
默认 269 项、desktop 274 项、desktop+audio-output 279 项测试，三套严格 all-targets Clippy 及 cargo fmt --check 通过。

当前仍没有剧情文字、真实动作输入、完整存档镜像、其他音频编码及其他平台验证。

## 语音停止契约（2026-10-27）

0x20a8 已接入独立 stop_voice：逻辑 0..3 对应原版设备 5..8，停止并释放，空槽为无操作；原生后端的四个语音槽与 SE/BGM/影片分开。当前没有语音加载/播放指令填充语音槽，本轮仅新增停止接口与编译回归，没有新增真实语音播放验证。现有 SE/BGM/影片输出能力不变，详见 vm-semantics.md。

## 效果音淡出契约（2026-10-27）

0x20b6 接入 `fade_out_se`：逻辑通道 0..5 对应设备 9..14，与 BGM 淡出共用原版 0x1400882d0 的语义，即在给定毫秒内淡到 0 后释放，空槽或正在淡出的槽不变。原生后端对 SE 槽复用已有包络，`update` 每帧推进并在结束时释放；淡出时长为 0 时在下一次更新释放。记录后端只记录 FadeOutSe。本轮只新增接口与编译回归，没有打开音频设备做真实效果音淡出检查，详见 vm-semantics.md。

## 语音播放契约（2026-10-27）

0x20a6 接入 `play_voice`：逻辑通道 0..3 对应设备 5..8，从 0x2014 注册的语音根（本作为 voice3/voice/voice2.cpz）读取 Ogg，不循环、不淡入，按请求立即开始或只准备。原生后端先释放该槽再装载，读取失败返回未装载，Err 时不改设备；`update` 推进语音槽，播放完毕后释放。音量为 (主音量 × 语音音量) >> 8，再按脚本音量缩放。真实路径的 cosn1001001.ogg 能经 `ResourceKind::Voice` 找到并通过校验；本轮没有打开音频设备做真实语音播放检查。
