# 引擎存档快照

证据限于 research.md 中 SHA-256 标识的 cmvs64.exe。写入函数 0x140069270，读取恢复函数 0x140069fd0。

## 何时生成、由谁消费

- 0x2080 / `0x1400810f0`：先由 `0x140080530` 装载主脚本，再调用 0x140069270，返回 0（不前进 PC、不回收参数）。
- 0x22b2 / `0x14007c9a0`：+14740 临时加 2、+14744 置 0 后调用 0x140069270，再把 +14740 减回，返回 0x4000。
- 快照写入引擎 +11176 的 3 MiB（0x300000）缓冲，长度存 +11184；同时填写 +11204 起的 600 字节 CSV2 头。
- 读取缓冲的只有存档写入 `0x140080b20`：0x22b6 / `0x1400812f0`（槽号 ≤999）及 `0x1400818e0`（槽 998）。
  缓冲为空时写入函数直接返回 0、不写文件；否则把这块缓冲作为 CSV2 第 0 段压缩写出。
- 0x2003 / `0x140080700` 及析构函数释放缓冲；读档 `0x140081960` 用存档第 0 段替换缓冲，再交给 0x140069fd0 恢复。
- 以上基于直接位移引用扫描与调用关系，不是动态执行对照。

## 对实时状态的影响

拷贝浮点区之后，0x140069270 调用 `0x140085ce0(0, 1)` 把位变量 0 置 1，拷贝位变量区，再 `0x140085ce0(0, 0)` 清除。
因此快照里的位变量 0 为 1，而实时位变量 0 结束时为 0。三份真实存档的 0x282 记录首字节 bit0 均为 1，与此一致。
`0x140085ce0` 是赋值 `0x1400657b0` 使用的位变量写入函数；它在值与镜像区不同时给变更标志置位 2，Rust 未建模该追踪。
其余写入只涉及快照缓冲和 +11204 头部字段；常驻序列化函数（如 0x1400142b0、0x14004e7f0、0x1400501d0、0x140086b50）只拷贝数据。
对象存在时才调用的序列化函数没有逐个核对，研究模型也没有这些对象。

## 记录帧

记录按顺序拼接，每条以 u16 标签开头，所有整数小端。帧格式由标签决定，读取函数对同一标签使用相同布局：

| 帧 | 标签 | 布局 |
|---|---|---|
| Short | 0x100–0x10b、0x112–0x115、0x200–0x203、0x240、0x241、0x248 | u16 长度，负载 |
| Long | 0x242、0x243、0x280–0x283、0x310、0x318、0x540、0x600、0x610、0x620、0x630、0x6e0、0x880–0x883、0x900 | u32 长度，负载 |
| Indexed | 0x380、0x400、0x6a0、0x700、0x800、0x8c0、0x8c8、0x8e8 | u16 对象序号，u32 长度，负载 |
| StringPair | 0x304 | 两段 u16 长度加字符串 |

写入顺序及已核对来源：

| 标签 | 来源 |
|---|---|
| 0x100–0x105 | +11840 存档标题（0x2162）、+14336 场景标题（0x2161）；+14592 主脚本名；+14624/+14656/+14688 公共脚本名 |
| 0x112–0x115 | +14720..+14732；0x112 等于 CSV2 第 2 段（脚本内存图像）长度 |
| 0x106–0x10b | +14736、+14740、+14744、+14748 起 40 字节、+16584、+14788 起 1796 字节 |
| 0x200–0x203 | CD3DDevice +84 清屏色（0x22cb）、+11144、+12092、CD3DDevice +80 深度清除标志（0x2250） |
| 0x240–0x243 | +82544、+82804、+82548 起 256 字节、+16740 起 64 KiB |
| 0x248 | +82816..+82856，即整数系统结果槽 0..10 |
| 0x280–0x283 | 整数变量 0..2047、浮点 0..1023、位变量 0..2047、字符串变量 0..63（每个 1024 字节） |
| 0x6a0、0x380、0x400、0x700、0x800、0x8c0、0x8c8、0x540、0x8e8、0x600–0x630 | 对应引擎对象存在时才写 |
| 0x6e0、0x880–0x883、0x900、0x304、0x310、0x318 | 每次都写；0x900 拷贝 +16592 当前脚本内存图像的“未知段”（PS2A 头第 6 个 u32 给出长度） |

整数、位、字符串变量区经 VM 读写函数的引用确认；浮点区只核对到同族访问器。其余字段的业务含义不作推测。

## Rust 实现与边界

`snapshot::parse_records` 只遍历帧结构，不解释负载：未知标签、长度越界和截断均报错，不返回部分结果。
原版读取函数遇到未知标签会提前结束恢复；研究实现改为显式报错。输入超过原版 3 MiB 缓冲时同样拒绝。
`cmvs-save --records <存档>` 列出每条记录的偏移、标签、序号和负载长度。

`SaveImage` 区分两种状态：`Absent` 表示原版缓冲尚为空，`Unavailable` 表示原版此处会生成镜像但 Rust 没有构建。
`capture_unavailable` 只应用位变量 0 清零这一项实时效果，并记录脚本名和 PC，不伪造快照字节。
今后实现存档写入时，`Unavailable` 必须显式失败，不能按 `Absent` 静默跳过，也不能写出不完整镜像。
0x22b2 尚未处理：它额外修改 +14744，而研究模型没有这个字段。
