# M2 进展：调用、路径与逻辑内存

> 2026-11-01，有限离线试点完成。对应[规划](command-contracts.md) M2，建立在 [M1](command-contracts-m1.md) 之上。仍只产出离线报告，运行闸门、档案状态和 Rust 分派未变。

后续运行接入与旧推定策略变更见 [M3](command-contracts-m3.md)，以下保留 M2 阶段结果。

## 1. 本轮完成（M2a/M2b）

| 能力 | 内容 |
|---|---|
| 全局区域 | 导出标为 `writable`/`address-taken` 的 RIP 相对操作数成为 `image` 根，按 RVA 查字段映射（`base_object="image"`）；代码地址、立即数、其他未解析数据仍阻断 |
| 只读数据 | 导出 `data` 引用（只读项字节）作为常量读取；写入只读数据阻断 |
| 下标表 | 映射可声明 `count`（逻辑容量）与每侧 `stride`；`[对象+idx*stride+off]` 生成带 `index` 表达式的目标，被指向对象以槽下标区分实例 |
| 指针值 | 从带 `points_to` 字段读出的指针保留原始值（`read_state` 的引用）；可与0比较，可原样写回指针字段 |
| 未定义路径 | 解引用未经路径证明非空的指针、或下标未证明 `ult(idx, count)` 时，分出一个显式 `undefined` 叶；每个条件分支把条件值记为路径事实，代码自己的同一检查之后不重复分叉 |
| 栈保护 | 上下文登记 `/GS` cookie 全局与 `__security_check_cookie`（绑定函数体哈希）；只在能证明 `rcx` 等于 cookie 时把检查视为成功返回 |
| 证据绑定 | RIP 相对操作数同分支一样被导出清零；工具从原 exe 重新解码，核对全局目标 RVA 或只读项字节 |
| 反例搜索 | 在两边契约出现的常量 ±1 处为每个参数/状态单元取边界值；默认预算2048组 |
| 映射候选 | `--propose`：缺失字段以每侧临时名补齐，两边去掉名字后结构一致时按顺序配对字段，输出访问位置与冲突标记 |

### IR 扩展

- 目标可选 `index`（64位表达式）。重叠宽度仍按静态部分检查；规范化改写其中的引用；执行时状态单元按“静态目标#下标值”区分，初值取静态目标的种子。
- 叶出口新增 `undefined`：无事件、返回码固定为0，只按条件参与比较。它表示两边在同一条件下都超出建模域，不是“任意行为都等价”。若一侧检查而另一侧不检查，树形不同，结果为未知或差异。
- 校验上限由128节点/64叶调整为256/128；提取器仍按每侧64个叶路径的预算截止。

### 映射候选的地位

候选只说明“若这样配对，两边契约结构一致”，不是证据，规划 §5 明确禁止只凭布局建立映射。登记映射仍须人工引用写入者/读取者或已有复核结论；候选附带的访问位置用来加快这一步。

## 2. 首个构建对结果（M2a/M2b 校准）

见[游戏报告](../games/chronoclock/contract-m2.md)。要点：

- 登记32条映射（新增30条，均为 `pilot`），全部有文档小节或访问位置支撑。
- 712条中26条 `equivalent`，0条 `different`，0条证据错误。其中25条已因完整机器指纹 `inherited`，1条（`0x203f`）已 `reviewed`；**对 167 条推定和 65 条未复核命令没有新增接受**。
- 候选模式：177条命令在临时名下结构一致，产生289对候选，0冲突。

审计：26条等价全部与已有结论一致，没有发现误接受；这只是校准，样本未出现误接受不等于没有漏判。

### M2c：首次接受旧推定命令

核对全局时钟的重置/模式写入与查询角色，以及按钮布局标志的 setter/getter/消费者，新增6条有读写证据的映射，总计38条。完整报告为29条 `equivalent`、683条 `unknown`，0条差异或证据错误；新增 `0x2008`、`0x2009`、`0x2087` 均来自当前 `presumed`，档案状态未修改。两边 helper 直接内联，无需增加受信任摘要。

三条试点均逐指令人工核对，并对10,374组共享输入执行双边契约，与独立时刻/增量/布尔公式比较。六个故意修改条件、字段、计算和回收量的变体均判差异，原 exe 绑定同时拒绝；缺映射变体保持未知。原有26条接受及其契约哈希保持。范围、证据哈希和未知项审计见[游戏报告](../games/chronoclock/contract-m2.md#global-pilot)。

## 3. 测试

- 提取器测试17项：M2a/M2b 新增有界检查的下标表（等价、未检查负槽产生 `undefined`、容量变化被代码检查遮蔽时为未知、可观察时为差异）、空指针分叉、全局映射与只读常量、cookie 内建、候选模式不修改映射，以及 RIP 操作数的 exe 绑定；M2c 新增多全局时钟查询（含 `cmov` 无条件读、条件反转、回绕）及全局布尔 setter（含非零值、反转与缺映射）。
- 比较器测试14项、指纹回归25项不变通过。
- 解码器改动后再次对照 capstone：约21.6万条一致。

## 4. 后续模型扩展

M2c 缺映射首阻断由606降至603，其余类别不变。剩余能力按首个阻断原因排列（目标侧，每条命令一个）：

1. **脚本操作数解析**（VM +0x3990，95条）：`0x68580` 等按引用高2位选择帧局部、帧参数、全局字符串区或参数栈区，返回脚本内存指针；后续多为字符串循环。需要 `script` 区域模型和带循环的字符串 helper 摘要。
2. **设备与管理器指针**（+0x7b0、+0x1230、+0x1168、+0x1238 等）及场景对象内部指针（+0x1830）：可由候选加人工核对推进，需要写入者/读取者证据。
3. **窗口内部字段**（+0x9d8 等）：窗口构造的人工复核只说明“没有新增可见差异”，尚未逐字段登记。
4. **指令**：`movaps` 保存非易失 xmm 寄存器（29）、间接调用、`imul`/`cdq` 等。
5. 摘要仍限单路径；导入和 FLIRT 库函数（除 cookie 检查）没有模型。

M2 的退出条件是：对选定构建离线报告中出现推定/未复核命令的接受项，并完成人工核对、误接受及未知项审计。M2c 以三条旧推定命令满足该条件；上述模型扩展仍未实现，不能据此扩大接受范围。M3 的证明格式、失效规则和运行策略尚未接入。
