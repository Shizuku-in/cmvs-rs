# 脚本可见契约比较与兼容性放行规划

> 状态：草案，2026-10-31。本文规划工具与闸门演进，尚未实现，不改变当前档案状态、默认放行行为或游戏完成度。现状见[引擎档案设计](engine-profiles.md#15-指纹策略-v3-与-presumed)与[架构](../architecture.md#引擎档案与命令闸门)。

实施进展：2026-10-31 [M0 模型与样本分类](command-contracts-m0.md)已完成；[M1a IR 比较与片段提取](command-contracts-m1.md)已实现，完整命令契约提取、证据校验和运行接入尚未完成。

## 1. 目标与原则

跨构建接入时，不再要求每条机器码有差异的命令都逐条人工复核。优先比较命令对脚本及其可观察环境的影响：完整指纹一致则继承；指纹不同但脚本可见契约等价则自动接受；契约不同或无法判定则停下复核。

自动接受用于推进“可玩”，不升级为“已验证”。静态分析仍可能受解码、别名、摘要模型和规则错误影响；所谓“完整”仅指在明确版本的模型及信任边界内没有未解析项，不是任意程序等价性的数学证明。

本阶段不新增游戏语义、解码器或 C++ 运行核心。通过闸门只表示允许进入现有 Rust 分派；没有处理器、格式不支持或运行状态未知时，仍显式报错。

## 2. 当前基础与需要补上的能力

当前已有 `tools/ida_export_commands.py`、`tools/profile_compare.py` 以及合成测试 `tools/test_profile_compare.py`。完整依赖指纹用于 `Inherited`；v3 的形状比较用于 `Presumed`，允许部分可写数据、间接控制流、递归和截断依赖未被解释。

`Presumed` 目前默认放行，但只表示“可比较部分没有差异”，不满足本文的契约完整性要求。不能直接重命名为契约等价，也不能把旧形状哈希当作契约哈希。

新增能力是：从反汇编恢复有限的语义表达式与副作用，把有证据的对象字段映射到逻辑状态，再按条件路径比较契约。复用现有身份校验、只读导出、候选档案和 Registry 校验流程。

## 3. 三层判断

以下是机器比较流程；已有人工复核结论保留，不由自动生成器覆盖。

| 层级 | 必要条件 | 建议结果 | 运行处理 |
|---|---|---|---|
| 1：完整指纹一致 | 满足现有同架构、同策略及身份绑定要求 | `Inherited` | 沿用现有放行规则 |
| 2：契约等价 | 两边提取完整、前置条件一致、所有相关路径及效果等价 | 新增 `ContractEquivalent` | 允许进入 Rust 分派，单独记录 |
| 3：需要复核 | 已知契约差异，或提取/比较不完整 | 保留 `Unreviewed`，报告 `different` 或 `unknown` | 默认停下，人工复核 |

“指纹无法完整比较”也可以进入契约提取，但原指纹中的阻断项必须被契约模型实际解释，不能删除标记后宣布通过。已知反证不能被其他匹配结果覆盖。

比较器输出三值结论：`equivalent`、`different`、`unknown`。预算耗尽、未知指令、未解析调用、无法证明的字段映射等一律为 `unknown`；相同的未知标记不代表等价。只要发现确定差异，即使同时存在未知项，也必须突出显示该差异。

## 4. 契约内容

契约描述一个命令在相同逻辑初态、参数及外部输入下的行为关系，不只是读写集合或返回码集合。

| 维度 | 需要保留的内容 |
|---|---|
| 参数与栈 | 参数数量、顺序、宽度、类型、符号扩展、来源表达式、读取时机；每条退出或等待路径的回收字节数与时机 |
| 返回与控制流 | 返回码及触发条件，例如 `0x400c` 与 `0x4000`；跳转、调用、退出、挂起、恢复与重试行为 |
| VM 状态 | 状态位、错误标志、结果寄存器的读取与写入；掩码、写入值及保持不变的位 |
| 脚本数据 | 整数、位、字符串、浮点变量和脚本可变数据的索引、读写宽度、值表达式与边界处理 |
| 存档与持久状态 | 逻辑字段、序列化字段标识及宽度、写入条件；保存/恢复和配置持久化的影响 |
| 场景与后端效果 | 图像、文字、音频、资源与输入请求的语义参数、顺序、成功/失败分支；后续查询可见的对象状态 |
| 时序与失败 | 等待条件、回调登记、延迟效果及取消；失败前已提交的效果、错误输出与不返回路径 |

需要保留条件和值。例如，两边都写变量 A 且都返回 `{0x4000, 0x400c}`，但分支条件相反，必须判为不同。读取集合一致但一个写 `arg0`、另一个写 `arg0 + 1`，也不等价。

“脚本可见”包括跨命令、跨帧和保存/恢复后的间接可见性。一个字段即使本命令不返回它，只要后续查询、渲染、音频或存档会消费它，就不能当作无关内部状态删除。

## 5. 内部布局归一化

允许忽略机器寄存器分配、函数位置以及已证明对应同一逻辑字段的 C++ 对象偏移。栈参数偏移、脚本变量索引、磁盘格式偏移和语义常量不能一并屏蔽。

例如，以下仅为合成示例：

```text
基准：object + 0x180 → SceneObject.shown
目标：object + 0x250 → SceneObject.shown
共同效果：SceneObject.shown = (arg0 != 0)
```

只有两侧字段映射及对象身份有证据，才允许归一化为同一效果。不能仅凭相同读写宽度、相近指令位置或“忽略偏移后相同”建立映射，否则会把真正的字段替换误判为布局变化。

映射规则按构建及架构登记，附读写者、初始化、查询或序列化等关联证据；共享规则可批量服务多条命令，减少重复人工工作。首次缺少映射时输出待核对项。跨对象别名、指针逃逸或未知消费者使非可见性无法确定时，保留 `unknown`。

## 6. 提取和比较工具

建议保持 IDA 导出与离线比较两段结构：IDA 负责有身份绑定的解码和控制流信息，离线工具负责归一化、契约生成、比较与报告。比较部分优先使用 Python 标准库，Rust 核心只读取已登记证据，不依赖 IDA。

### 6.1 提取流程

1. 校验 exe SHA-256、架构、image base、case 入口与数据库身份；沿用拒绝补丁字节的约束。
2. 从 case 入口恢复可达 CFG，跟踪参数栈、常量、寄存器及已知逻辑内存区域。对支持的算术显式保留位宽、溢出、符号与比较规则。
3. 生成带条件的路径摘要，记录参数、状态转移、返回值和有序外部效果。无法完整解析的路径不丢弃。
4. 对调用递归提取摘要，或应用已登记且绑定身份的 helper/外部接口摘要。摘要须涵盖失败和副作用；函数名相同不能单独证明契约一致。
5. 应用字段映射，将原始对象偏移转成逻辑字段。记录每条映射和摘要的依赖。
6. 产出规范化契约、完整性检查结果和证据定位，再比较两边契约。

首版采用受限表达式规范化和结构比较：无法识别为相同即保留未知或报告确定差异，不尝试通用定理证明。未支持的循环、递归、浮点运算、间接调用及复杂别名不靠占位符放行。后续按实际阻断分布增加规则。

比较从同架构、同一编译器时代开始。x86 与 x64 独立生成结论，不直接比较原始 ABI；跨架构或跨时代的统一另行设计。其他架构如有确定反证，应暂停对应契约结论并复核，不能只选择较宽松的一侧。

### 6.2 证据与输出

每条结果至少绑定以下信息：

- 基准/目标档案、exe SHA-256、架构、image base、opcode 和 case RVA。
- 导出格式、提取器版本、工具源码版本、规则集版本及摘要/字段映射依赖哈希。
- 输入导出哈希、两侧规范化契约哈希、完整性标记及比较结论。
- 差异字段、路径条件、对应证据地址；未知原因及预算限制。

报告应同时给出总数、各阻断原因分布和逐命令说明，支持按 opcode 追溯第一处差异及全部未知项。契约哈希只用于复现和身份校验，不代替契约提取的正确性。

原始指令字节、完整反汇编、IDA 数据库、真实样本与探针输出保留在仓库外或忽略的 `local/`。Git 只保存必要哈希、元数据、规则及文字证据；游戏专属结果放 `docs/games/<游戏标识>/`。新增第三方来源先按[参考约定](../references.md)登记提交与许可。

## 7. 档案、闸门与旧状态迁移

建议新增独立的 `ContractEquivalent` 状态及证明结构，不复用 `Inherited` 或 `Presumed` 的证明字段。具体文本格式在首版契约模型稳定后确定。

Registry 应校验基准与目标身份、家族、架构、opcode、证据版本及依赖哈希，拒绝缺失证明、过期版本和未知规则。第一版直接对已有语义基准比较，不通过连续的契约等价构建无限传递结论。`Base` 只是语义来源，不能据此宣称基准所有命令均已实现或已验证。

迁移分为两步：

1. **只报告阶段**：保留当前默认行为；离线对现有命令重新分类，输出迁移差异，不修改已登记档案。旧 `Presumed` 仍明确标注为旧推定。
2. **启用阶段**：完整迁移报告及测试通过后，默认放行 `Base`、`Inherited`、`Reviewed`、`ContractEquivalent`；旧 `Presumed` 未取得新证据时默认停下，只允许经明确记录的研究策略运行。此默认收紧需要在运行指南和发布说明中说明，不能静默发生。

`Absent`、`NoOp` 和未实现处理器沿用现有错误策略。`Unreviewed` 的研究放行不会产生契约等价证据。人工复核若发现真实语义差异，进入现有差异实现流程，不能为了通过闸门强行标为等价。

runner、trace、桌面应共用同一闸门。新增契约来源的分派尝试计数及已执行 opcode 列表；等待重试仍算分派尝试，不能称作完成数或覆盖率。已知反证应能撤销证明；规则或摘要发生变化时，使依赖它们的结果失效并重新生成。

## 8. “可玩”与“已验证”的报告边界

命令层记录证据来源，游戏层记录实际运行范围，两者分开。

- **命令契约等价**：在记录的模型和身份范围内自动接受，可以用于推进可玩性，不等于 Rust 实现正确或游戏可运行。
- **游戏可玩**：需要真实运行支持；明确构建、平台、路线、启动至结束范围、显示/音频及存读档测试结果。只进入标题或跑通 demo，记录为相应路径通过，不标整部游戏可玩。
- **游戏已验证**：仍按现有人工复核和游戏验证流程，逐项保留证据与范围。契约通过不能替代人工复核；人工复核通过也不能替代原生输出、路线及存档验证。

游戏报告应列出实际执行的 `ContractEquivalent` 和研究放行命令，附未测试范围与失败停点。只要结论仍依赖未经人工复核的契约推断，就不能将相应范围写成“已验证”。

## 9. 实施阶段与交付物

| 阶段 | 工作 | 交付与退出条件 |
|---|---|---|
| M0：模型与样本分类 | 固定首版契约字段、完整性规则、字段映射和摘要格式；统计当前差异类型 | 合成正反例、待支持形态清单和模型边界；不改闸门 |
| M1：受限原型 | 支持简单参数读取、栈回收、常量返回、位操作和有证据的字段映射 | 同架构双边提取与三值报告；偏移变化可接受，行为变化与未知依赖不放行 |
| M2：调用与路径 | 增加常见 helper 摘要、条件路径及必要的逻辑内存访问 | 对选定真实构建离线生成报告；人工核对试点接受项，审计误接受及未知项 |
| M3：运行接入 | 状态、证明解析、Registry、闸门、统计与失效机制；迁移旧推定 | runner/trace/桌面策略一致；旧证据不自动升级；基准回归通过 |
| M4：游戏验证 | 在独立用户目录进行实际路径重放、原生输出与存读档测试 | 在游戏档案记录可玩范围、使用的证据来源和剩余停点 |

“1–2 天”仅作为 M1 受限原型的试做预算，不作为 M0–M4 总工期承诺。完成 M1 后按已接受数量、未知原因、公共规则复用率和审计结果重新估算。优先支持能够批量消除布局差异的共享规则，不追求第一版覆盖所有命令。

人工主要投入共享字段映射、helper 摘要、工具验收抽查及真正的行为差异。试点阶段核对接受项是校准工具，不是长期恢复每条命令都要人工批准的流程。

## 10. 验收与回归

合成测试至少包括：

| 输入变化 | 预期 |
|---|---|
| 仅有已登记的对象偏移变化，逻辑效果一致 | `equivalent` |
| 偏移变化但没有字段映射证据 | `unknown` |
| 参数顺序、宽度或任一分支栈回收变化 | `different` |
| `0x400c` 改为 `0x4000`，或返回条件互换 | `different` |
| 状态位掩码、变量索引、写入表达式或存档字段变化 | `different` |
| 外部效果顺序、失败前提交效果或等待条件变化 | `different` |
| 两边均存在未解析间接调用、别名或截断路径 | `unknown`，不得因未知项相同而接受 |
| helper 摘要遗漏副作用或出现未支持指令 | 完整性校验失败，不接受 |
| 哈希、架构、规则版本不匹配或证明已撤销 | 拒绝证据 |

真实样本仅用于仓库外验证：按差异类别选择布局变化、行为变化、复杂依赖样本，人工与工具结论对照，记录身份和范围。任何误接受都先修复规则并撤销依赖结论，再扩大批量放行；样本未发现误接受不能表述为“零漏判”。

运行接入时执行 `cargo fmt --check`、`cargo test --offline`、`cargo clippy --offline --all-targets -- -D warnings`，并运行比较器的合成测试；涉及后端或 feature 时追加 [Workspace](../workspace.md) 的检查。对现有语义基准做同参数 trace 回归，行为日志应一致，新增诊断单独核对。派生构建分别验证接受、差异、未知、旧推定及未实现处理器的停点。

本规划不修改解码算法；将来若涉及解码，仍须执行真实样本与独立 Python 对照要求。

## 11. 首轮实施顺序

先完成 M0/M1，只产出报告。确认有限模型能稳定识别“布局变、契约不变”，并能拒绝相似的行为变化后，再增加摘要与运行接入。批量收益以实际报告为准，不预设某个游戏可以自动放行多少命令。

该路线保留明确的退出点：超出模型能力的命令继续复核，不必为了覆盖它们先建成通用反编译器；当同类阻断反复出现时，再把人工知识沉淀为有版本、有证据的共享规则。
