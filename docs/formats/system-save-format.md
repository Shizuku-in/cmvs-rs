# CSS1 系统存档

> 本文描述已核对的实现分支，真实样本与历史验证来自[《アマツツミ》](../games/amatsutsumi/README.md)。其他游戏或引擎版本需单独验证；下文历史停点不代表最新完成度。

证据绑定 research.md 中 cmvs64.exe 的哈希。写入 0x1400179e0、读取 0x140018da0、解压 0x14008d760。
格式与 CSV2 剧情存档不同；当前支持 CSS1 编码模式 1 读取及显式的新文件导出，不覆盖原游戏文件，不实现完整引擎快照恢复。

|---|---|---|
| 0 / 4 | 4 字节 / u32 | CSS1 / 头长 104 |
| 68 | u32 | 游戏标识，非零时应与 0x201d 配置一致 |
| 76 | u16 | 编码模式，当前只支持 1 |
| 78 / 80 / 82 | 三个 u16 | 变换参数；前两个参数参与字节运算时取低字节 |
| 84 / 88 | 两个 u32 | 对象 +12024 / +12016 两组名称计数；负载中 +12016 在先 |
| 92 / 96 | 两个 u32 | 解压长度 / 压缩长度 |
| 100 | u32 | 校验和偏移，等于 360 + 压缩长度 |
| 104..360 | 256 字节 | 额外区域，本版本 0x2128 的读取函数未应用；不推测含义 |
| 360 起 | 变长 | 经过字节变换的压缩负载 |
| 文件末尾 -2 | u16 | 变换后压缩字节累加和模 65536；不保护头部 |

所有整数小端。旋转量为 `((word82 >> ((word78 >> 1) & 7)) & 3) + 2`，范围 2..5。
循环密钥为 YUKO_KAWAI_PURPLE_SYSTEM_SAVE_CHECK。
逆变换按 u8 截断：`((ROR8(byte, shift) - byte78) XOR (byte80 + key[i % key.len()])) - 64`。

CSS1 LZSS 使用 1024 字节环形窗口，写指针从 976 开始，标志位低位优先；1 为字面字节。
引用两字节：位置 `lo | ((hi & 0xc0) << 2)`，长度 `(hi & 0x3f) + 2`，允许重叠复制。
研究实现将整个窗口初始化为零，不依赖原程序全局缓冲区尾部或上次调用留下的字节。
始终验证实际输出长度；截断、超量和声明长度不符时失败。

解压后的固定区与恢复范围：

| 负载范围 | 长度 | 恢复到 State |
|---|---:|---|
| 0..32512 | 32512 | 位索引 2048..262144，字节内低位先行 |
| 32512..40704 | 8192 | 2048 个 i32，索引 2048..4096 |
| 40704..44800 | 4096 | 1024 个浮点原始 u32 位，索引 1024..2048 |
| 44800 起 | 64 个 NUL 串 | 字符串索引 64..128，单项最多 1023 字节 |
| 字符串之后 | 变长 | +12016 名称列表，再 +12024 名称列表，各按头部计数 |

范围右端均不包含。数据区域来自读取函数实际调用参数：
0x140085f20 的起始字节 0x100、长度 0x7f00；0x140085f80 的起始整数 0x800、数量 0x800；
0x140085ff0 的起始浮点 0x400、数量 0x400。字节指针与变量索引不可混淆。
其他变量、整数 4096、表达式结果、条件和系统结果寄存器保持原值。
原读取器仅在名称计数非零时替换对应列表；零计数保留既有列表，不能解释为清空。

研究策略：文件与解压负载分别上限 64 MiB，每组名称上限 4096；拒绝额外文件尾字节、负载尾字节、
长度矛盾、缺失 NUL、超长目标字符串及校验失败。元数据先验证，再分配解压缓冲区。
游戏标识不匹配或目标 State 容量不足时，候选状态不会提交；非零标识也不允许与未知配置盲目匹配。
原程序对畸形文件的错误标志、镜像区变化追踪和未定义行为没有照搬。

CLI `cmvs-system-save <system.dat>` 只检查元数据并解码。
`--payload <新文件>` 可导出解压负载，使用 create_new 拒绝覆盖原文件。
`cmvs-trace --system-save <明确路径>` 才处理 0x2128；未给该选项时仍停下。
显式来源文件不存在时遵循原版的无修改返回；其他读取错误不当作首次启动。

## 模式 1 编码与可选新文件导出（2026-10-28）

`Css1Save::encode_state` 只序列化完整已知的上述持久区，任一缺失值即报错；64 个字符串必须满足现有 State 的 1023 字节/NUL 约束。名称列表的序列化顺序与读取一致，研究上限每组 4096 项，整体负载不超过原版 1 MiB scratch buffer。头部 8..68 的不解释注释从已经加载的来源保留，不把游戏内固定字符串复制到源码；游戏标识由当前配置提供。头部 +72 和额外区当前输出 0：原版配置 0x212c 尚未实现，仍保留未知命令。

编码器 `0x14008db90` 使用 1024 字节字典、48 字节 lookahead、起点 976、阈值 2。与解码器允许的长度上限 65 区分，原版编码最多选择 48。按首字节选根的二叉搜索树中，只有严格更长的匹配替换结果；48 字节完全匹配时替换节点。插入 0x14008d870、移除 0x14008da30 的顺序及尾部耗尽逻辑按本作核对，实现不含外部源码。压缩字节经读取逆变换的逆运算编码，再累加为 u16 校验。

四个 CRT rand 依次生成 word78 = r0 & 255，word80 = (r1 & 127) + 128，word82 = (r2*r3 - 26797) mod 65536。`SystemSaveHost::try_write` 对 RNG 作候选克隆；完整状态编码和 sink 写入都成功后才完成无参数 0x2129（0x4000，不写系统结果）并提交四次 draw。当前 0x212a/b 列表启用配置未实现，运行入口对应标志维持构造的 0，所以写出两个空列表，不能把读取时保留的列表直接当作已启用。

`Startup::set_system_save_output` / 桌面 `--system-save-output <新文件>` 是可选研究导出：必须在 tick 前选择，父目录须存在且 canonical 路径在原游戏根之外，创建时使用 create_new 拒绝已有文件与竞争创建；成功后后续 0x2128 读取导出路径。默认仍在 0x2129 停下。输出需要已有合法 CSS1 模板，不支持无模板首次创建；一次运行的固定新路径不能再次覆盖写出。不创建原版 system.bak，不支持独立用户目录内反复保存或完整剧情存档。

失败策略有意区别于原版：原写入函数忽略底层 WriteFile/CopyFile 的失败结果，仍返回；Rust 对编码/输出失败保留 VM PC/SP、系统结果和 RNG，显式报错。文件副作用不整体回滚；create_new 之后的短写/同步失败会保留部分文件，不能在原路径静默重试覆盖，须在新运行中选新输出位置。

真实原 system.dat 2541 字节以同参数复编码后逐字节相同；独立标准库 Python 检查其 44864 字节负载。路线结尾的鼠标/Ctrl 生成相同的 2707 字节 CSS1，独立 Python 解码与写出时持久状态逐字节相同。原游戏文件未改；完整数值、哈希、标题验证与限制见 research.md。

## 独立用户目录（2026-10-29）

`ProfileSystemSave` / `Startup::set_user_data_directory` / 桌面 `--user-data-dir <目录>` 提供重复保存策略，与单次新文件导出互斥，均须在 tick 前配置。目录可递归创建，但在创建前以已有祖先的 canonical 路径检查其位于原游戏根之外；原有目录再 canonical 检查。用户 system.dat 优先；初次缺失才读取原游戏 save/system.dat 的模板，成功写入后及下次启动均从用户主文件读取，剧情槽扫描同样转到用户目录。CSS1 编码、未知变量拒绝和已加载模板要求未变。

会话持有空文件 .cmvs-system.lock 的标准库排他锁，第二个会话非阻塞报错。锁文件留存，锁由句柄关闭/进程退出释放，无需删除锁文件；进程异常退出也不会形成持久死锁。此 API 自 Rust 1.89 稳定，workspace 已声明对应最低版本；当前验证编译器为 1.96。

每次保存先验证新 CSS1、读取并校验旧用户主文件，再在同目录以 create_new 建立唯一临时文件，写完 sync_all。已有主文件时，先将其完整字节写入另一临时文件并同步、重命名为 system.bak；最后将新临时文件重命名提交为 system.dat。首次用户保存不备份原游戏文件，之后备份对应上一个用户版本。备份更新/主文件替换失败保持旧主文件；最终重命名成功后不再执行可能导致 VM 重试的 I/O。普通失败清理自建临时文件；异常终止可能遗留未提交临时文件，读取不会采用它们。

这是一项本项目的独立存储策略，并非原版 CopyFile/覆盖写入行为。已在 Windows 验证同目录替换与主文件被占用时的失败边界；未进行断电持久性或其他平台构建验证，不承诺目录元数据已持久化。主文件/备份/锁入口拒绝符号链接和目录；既有坏主文件禁止覆盖或回退到原游戏，备份保留。若只剩备份，会显式报错；需关闭会话后明确恢复备份，不能悄悄当作新用户。没有自动恢复按钮或剧情存档恢复。

测试使用合成 CSS1；Windows 沙箱虚拟 Temp 允许创建/删除却拒绝 rename，已由最小探针对照定位，因此存储替换测试在仓库 target 下的唯一测试目录执行。真实 CSS1/探针和用户目录样本仅在 local；进程锁、强制结束后释放、通关保存→退出→重启的证据见 research.md。
