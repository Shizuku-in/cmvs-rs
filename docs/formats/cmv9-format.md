# 场景影片：CMV9 静态底图、CMV6/CMV8 创建与段播放

> 本文描述已核对的实现分支，真实样本与历史验证来自[《アマツツミ》](../games/amatsutsumi/README.md)。其他游戏或引擎版本需单独验证；下文历史停点不代表最新完成度。

证据仅绑定 `cmvs64.exe` SHA-256 `dc74d2001387ae1aefbdc4204216de5ebb9d3896009280720c4e7a91b42d84f5`。
当前实现无实际音轨的 24 位 CMV6、32 位带 alpha 的 CMV8（JBPE 帧）、静音 24 位 CMV9 的独立帧解码、`0x2308` 创建绑定、`0x2309` 默认模式的段播放/循环与 `0x231a` 活动查询；其他槽控制、播放模式和音轨仍未实现。CMV5/7、16 位设备路径、带音轨 CMV9 与其他创建变体仍显式报错/未处理。全屏 OP 保留独立的 CMV6 播放生命周期。

## 容器

前 44 字节沿用 CMV 字段：签名、资源偏移、文件长度、保留字、最大序号、帧率分子/分母、宽、高、位深、音频标志。`max_sequence + 1` 个 20 字节索引项紧随其后，结构为序号、存储长度、解码长度、类型、资源区内偏移。只解码序号小于 max_sequence 的类型 2 项，不能把最后的保留项当作视频帧。

索引之后、资源区之前是静态数据块：u32 总长（含自身）、u16 MCU 列数/行数、`ceil(列×行/8)` 字节位图，再接底图 JBPD。位图按 256×256 纹理块、块内 MCU 行/列的顺序读取，每字节从最高位开始。位为 1 的 16×16 MCU 由底图解码，位为 0 的 MCU 由目标视频帧解码；后者以底图为背景合成。末端 MCU 可以越过名义宽高，输出裁到名义尺寸。

底图 JBPD 的表起点是 +4 字段本身，普通帧则是字段 + 4；普通帧 +44 是纹理块更新位图，独立解码不使用它跳过输出。两者沿用已有频率树、DC 差分、AC 游程、量化、整数 IDCT 与颜色转换。+36 是实际 DC 数量，必须等于本次存在的 MCU 数×6。带 bit 12 的普通帧布局表后有 u16 字节长度及复用位图；独立帧路径跨过它并解码所有动态块，不依赖前一视频帧。

所有文件/像素受既有 64 MiB 研究上限约束，索引另限最多 2^20 项；边界、掩码、网格、DC 数量或位流不符均报错。这不是整个进程的峰值内存保证。`cmv9::Cmv9Index` 为核心入口；当前 `cmvs-cmv` CLI 仍仅接受 CMV6。

## 0x2308 创建与所有权

`0x14007ef20` 读取 SP-4 影片槽、SP-8 场景槽、SP-12 文件名及 SP-20 初始帧，完全不读 SP-16；返回 `0x4014`，不写系统结果寄存器。

- 三个影片槽位于引擎 +4480，场景槽仍在 +1976。原版销毁目标影片槽和目标场景槽，分别创建播放器和场景对象。
- `0x1400390b0` 以模式 2 经 +4824 的四项资源列表打开文件；该列表由 `0x201a / 0x140071c40` 注册，读取见 `0x1400380d0`。Rust 新增独立 SceneMovie 资源族，复用目录/CPZ6 校验与路径约束。
- 播放器构造 `0x1400383c0` 令活动状态 +48 为 0；打开设置 +64=-1，`0x140038f70` 解码指定初始帧，将其绑定为普通不透明图像，并建立全图矩形的默认 DrawState。创建不自动播放。
- `0x230a` 仅销毁播放器，留下场景对象及最后的图像；更换同一播放器的场景绑定也不删除先前绑定的其他场景槽。

原版缺失文件仍留下部分对象，越界影片槽仅写引擎错误位；Rust 对这些分支报错并保留 PC/SP、结果寄存器与旧对象。资源与解码全部成功后才提交。场景槽限 0..255，名称额外限 63 字节（研究工具策略，原版 +300 的 lstrcpy 未检查边界）；跨影片槽覆盖同一对象的悬空绑定风险显式报错。其他命令销毁/重建绑定对象时的完整播放生命周期尚未建模，播放控制仍未接入。

## 0x2309 段播放与默认帧更新（2026-10-28）

`0x14007f2c0` 读取 SP-4 影片槽、SP-8 段号、SP-12 起始帧、SP-16 结束帧、SP-20 循环标志，返回 0x4014，不写结果。空影片槽只回收参数（不读取循环值）；越界槽的原版错误位仍以显式错误代替。段号限 0..15，来自 +60 起 208 字节状态中的 16 字节头部与 16×12 字节记录。

`0x1400385a0` 写三字段段记录，结束帧 -1 映射为 max_sequence−1。未活动时设置 current、重置 elapsed、保存当前时钟、清 pending、置 active；活动时仅设置 pending。它既不立即跳到起始帧，也不清除 paused；自然完成之后的再次启动仍需尚未接入的恢复控制。

`0x140039330` 默认模式 0：暂停或不活动时返回。取无符号时差并钳到 1000ms，累加 u32 elapsed；计算 `steps=(elapsed*rate)/1000/rate_time`，再减去 `1000*steps*rate_time/rate`，每个乘积均为 u32 回绕。到段尾时优先切 pending（start=-1 或等于当前帧则递增一帧），其次循环回 start，否则 active=false、paused=true 并保留末帧图像。每次仅解码最终变化目标，不逐帧解码跳过的中间帧。研究工具另限制单次最多 65536 个逻辑帧步；非法目标、解码失败或绑定对象已被删除/替换时显式报错，保留该槽旧图像、帧和播放计时。

主循环 `0x14000e400` 在 VM/场景效果前更新三槽；Rust 两个帧入口同样在序列与场景前推进槽。MovieHost 独立 u32 毫秒时钟供脚本启动和帧更新共用，不使用回调 tick。静态底图在创建时解码并保留，动态帧复用同一底图，不从上一动态帧累积；原始数据不变，目标帧重新构造新图像后再提交。

当前只接入新建播放器默认的模式 0、无实际音轨的 CMV6、静音 CMV9 与 0x2309；暂停/恢复、其他控制命令、模式 10/15、音轨仍未接入。移动或替换绑定对象的完整身份生命周期未建模，检测到失效绑定时不会静默覆写别的图像。

新增合成测试覆盖时间余数、末帧停留、循环/延迟换段、无立即跳转、保留暂停状态、空槽、越界/短栈、绑定失效/解码失败重试，以及 u32 时钟回绕和单次时差钳位。实际 bg620a.cmv 的循环参数是 [slot=0,key=0,start=0,end=-1,loop=1]；700 项帧号/elapsed 与独立 Python 完全一致，覆盖两次 75 帧循环。运行时第 0/1/37/74 帧与原独立 Python RGBA 一致。鼠标/Enter 各 384 次点击后到 `sn1001.ps3 / 0x16f1c / 0x2171`，2673865/2673905 步、SP=16。


新增路径呈现验证完成：鼠标重放累计 27,821 个让出帧；本轮对旧停点之后的 8,640 个让出帧逐帧调用核心呈现，并在每次新增消息等待处调用真实桌面 FontRenderer，均无提前错误，到达同一 0x2171。第 37 帧含文字的动态场景已导出目视检查，仍不作为原生窗口实测。

## CMV6 场景槽创建（2026-10-28）

仍绑定本文开头的二进制 SHA-256。`0x1400390b0` 按签名末字节把 CMV6 映射为内部类型 2，CMV9 为 5；CMV6 不执行静态底图初始化。`0x14003c020` / `0x140034f60` 创建无 alpha 图像，`0x140038f70` / `0x140038ba0` 的类型 2 在 32 位目标和不透明对象下调用既有 `0x1400ab650`，支持现有 JBPD 独立目标帧解码。创建仍为停止状态，默认段时钟和绑定对象所有权与 CMV9 共用；不套用全屏播放器的自动播放或结束销毁。

`0x140039c90` 在头部 +40 非零时读取最终索引项的存储长度，仅非零时分配音频数据；`0x1400397b0` 取走该数据，`0x1400390b0` 仅在指针非空时装载到设备通道 `slot+2`。`0x140038b30` 析构流和清空引用，不等价于全屏影片停止。当前 CMV6 创建拒绝实际存在的音轨，避免静默丢弃声音；音频标志非零但最终音频条目为零长的分支可正常创建。

真实 `video.cpz / mv_ic01.cmv` 经资源校验和只读读取：4030312 字节，CMV6，1280×720，135 帧，15/1 fps，24 位，音频标志 2，最后 kind=0 条目长度为 0。视频索引 decoded_size 为 `width*height*3+54`，包含 BMP 头长度的元数据；原版帧解码使用 JBPD 自身布局。CMV6 帧检查现在接受纯 RGB 长度或加 54 的长度，其他长度仍拒绝，输出仍为 RGBA。未修改 JBPD 数学或复用掩码算法。

新建 `SceneMovieIndex::Cmv6/Cmv9` 区分索引及解码路径；CMV6 不缓存静态底图。默认段播放沿用同一计时和事务逻辑。两个新增合成测试覆盖两种 decoded_size、空音轨标志、带复用掩码的初始帧、循环及销毁保留图像，并验证坏尺寸/元数据、越界帧和真实非空音轨拒绝时保留先前 CMV9 播放器、场景、PC/SP 和结果。

第 0、1、67、134 帧与独立 Python/NumPy 参考逐字节相同；第 0 帧 SHA-256 为 `771fa16b358e3195e00973cb8baa582a84f3c38d9ab2218742169515211b9889`，第 67 帧为 `6d5ff926555978547f066a7cc03ab256674e7a638434b324c84f7d4b4a06f3e7`。真实 VM 创建后的对象图像亦与第 0 帧一致，active=false。鼠标/Enter 各 1458 次点击后在 10320569/10320609 步到 `sn1002.ps3 / PC=0x4e64 / 0x231a`、SP=20，比旧屏障各多 58 步；case 794 → `0x14007f610` 仅定位。真实脚本尚未开始播放该影片，黑屏停点的 FontRenderer 呈现成功，未新增原生窗口实测。默认 514 项、全功能 544 项测试及严格检查通过（另 1 项硬件检查忽略）。

## CMV8 场景影片与 JBPE alpha 帧（2026-10-28）

仍绑定本文开头的二进制 SHA-256。`0x1400390b0` 按签名末字节把 CMV5..CMV9 映射为内部类型 1..5；CMV7/CMV8（类型 3/4）以 `0x14003c020` 第五参数 1 创建**带 alpha** 的图像，且不执行 CMV9 静态底图初始化。容器字段与 CMV6 相同；`0x140038ba0` 对类型 4 在 32 位设备上调用 `0x1400af100`（16 位设备为 `0x1400b01b0`，未建模）。原版不检查帧签名，真实帧为 `JBPE`。

`0x1400af100` 与 CMV6 的 `0x1400ab650` 共用频率树、DC 差分、AC 游程、量化排列、整数 IDCT `0x1400b51c0` 与颜色转换 `0x1400a2300`，差别为：

- 标志 bit 27 时读取**三张**量化表（192 字节），表头共 336 字节；第三张用于 alpha 块。
- 表后先是 u32 DC 总数（`v44`），再是瓦片布局字；CMV6 的 DC 数由 MCU×6 推算。
- 每个 MCU 依次解码 4 个亮度、Cb、Cr 和 4 个 alpha 块，共享同一 DC 序列和 AC 位流，DC 数 = MCU×10。
- 帧模式（标志 bit 28..29 = 1）下 `0x1400a0ad0` 把宽高向上取整到 16，bit 12 复用位图按该 MCU 网格的 `ceil(MCU/8)` 字节并对齐 4 字节。
- `0x1400a3850` 把 alpha IDCT 样本 v 写入像素字节 3：取 `0x1400e3b30[4·v + 512]` 的第 0 列。该表长 3072 字节，v ∈ −128..383 时等于 clamp(v,0,255)，无 +128 电平偏移；384..639 为其他用途的数据，−128 以下越过表头。

Rust：`jbpd::decode_alpha` 只接受 `JBPE`、32 位、上述标志，DC 总数必须等于 MCU×10，alpha 样本超出 −128..383 显式报错；非 16 倍数尺寸裁到名义宽高。`CmvIndex::read_scene` 额外接受 CMV8（`alpha=true`，位深 32，decoded_size 为 w·h·4 或加 54 字节 BMP 头），全屏 OP 的 `CmvIndex::read` 仍只接受 CMV6。`SceneMovieIndex::Cmv8` 复用 CMV6 的段播放、计时与所有权，绑定对象 `ObjectImage::alpha=true`，播放只替换像素。非零音轨仍拒绝。新增四项合成测试覆盖 alpha 块顺序与第三量化表、复用位图、17 像素宽裁边、alpha 表范围、DC 总数/签名/位深/截断错误、CMV8 容器与 OP 读取器区分，以及创建/播放保持 alpha 图像。

真实 `video.cpz / st-snow.cmv`（只读提取，SHA-256 `4b796d38848cf62a56e1c1abb765ee591ce8507690cdbb8d92bf909263e47b53`）：294460 字节，CMV8，572×720，30 帧，15/1 fps，32 位，音频标志 2 而最后条目长度为 0；帧标志 0x58c01002，DC 总数 16200 = 36×45×10，3×3 瓦片。全部 30 帧解码成功；`local/cmv8_reference.py` 复用既有 SSE IDCT 仿真并直接从可执行文件读取 alpha 表，第 0/1/2/15/22/23/29 帧 RGBA 逐字节一致（第 15 帧 SHA-256 `7a50949a8b37773792fe03a6ff992d591b372c75297c5d2c7edceb6ebb45b7cb`）。第 0 帧与第 24..29 帧全透明，中间为粉色光环特效，alpha 最高 229。

## 场景影片暂停与恢复（2026-10-31）

0x230c只设置场景播放器paused，保留active、分段、帧、对象图像和已累计的小数帧时间。0x230b清除paused；若active，按当前场景时钟重设last_tick并清小数时间，即使此前已在播放也重设；若不活动，仅清paused，不隐式启动。空槽两者均为空操作，参数槽越界明确报错。快照现有paused/active字段保持原有序列化。

真实bg340a.cmv通过资源归档读取，100ms推进到帧1，暂停后推进120×16ms仍保留帧1和相同RGBA，恢复后100ms到帧2。这里使用显式虚拟帧时钟，不是原生窗口实时播放检查。没有修改影片解码算法，未重新声明既有Python解码对照范围；指令证据见[游戏VM语义](../games/amatsutsumi/vm-semantics.md#背景动画设置与窗口透明度2026-10-31)。
