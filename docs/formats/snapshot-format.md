# 引擎存档快照

> 本文描述已核对的实现分支，真实样本与历史验证来自[《アマツツミ》](../games/amatsutsumi/README.md)。其他游戏或引擎版本需单独验证；下文历史停点不代表最新完成度。

证据限于 research.md 中 SHA-256 标识的 cmvs64.exe。写入函数 0x140069270，读取恢复函数 0x140069fd0。

## 何时生成、由谁消费

- 0x2080 / `0x1400810f0`：先由 `0x140080530` 装载主脚本，再调用 0x140069270，返回 0（不前进 PC、不回收参数）。
- 0x22b2 / `0x14007c9a0`：+14740 临时加 2、+14744 置 0 后调用 0x140069270，再把 +14740 减回，返回 0x4000。
- 快照写入引擎 +11176 的 3 MiB（0x300000）缓冲，长度存 +11184；同时填写 +11204 起的 600 字节 CSV2 头。
- 读取缓冲的只有存档写入 `0x140080b20`：0x22b6 / `0x1400812f0`（槽号 ≤999）及 `0x1400818e0`（槽 998）。
  缓冲为空时写入函数直接返回 0、不写文件；否则把这块缓冲作为 CSV2 第 0 段压缩写出。
- 0x2003 / `0x140080700` 及析构函数释放缓冲；读档 `0x140081960` 用存档第 0 段替换缓冲，再交给 0x140069fd0 恢复。
- 以上基于直接位移引用扫描与调用关系，不是动态执行对照。

## 对实时状态的影响

拷贝浮点区之后，0x140069270 调用 `0x140085ce0(0, 1)` 把位变量 0 置 1，拷贝位变量区，再 `0x140085ce0(0, 0)` 清除。
因此快照里的位变量 0 为 1，而实时位变量 0 结束时为 0。三份真实存档的 0x282 记录首字节 bit0 均为 1，与此一致。
`0x140085ce0` 是赋值 `0x1400657b0` 使用的位变量写入函数；它在值与镜像区不同时给变更标志置位 2，Rust 未建模该追踪。
其余写入只涉及快照缓冲和 +11204 头部字段；常驻序列化函数（如 0x1400142b0、0x14004e7f0、0x1400501d0、0x140086b50）只拷贝数据。
对象存在时才调用的序列化函数没有逐个核对，研究模型也没有这些对象。

## 记录帧

记录按顺序拼接，每条以 u16 标签开头，所有整数小端。帧格式由标签决定，读取函数对同一标签使用相同布局：

| 帧 | 标签 | 布局 |
|---|---|---|
| Short | 0x100–0x10b、0x112–0x115、0x200–0x203、0x240、0x241、0x248 | u16 长度，负载 |
| Long | 0x242、0x243、0x280–0x283、0x310、0x318、0x540、0x600、0x610、0x620、0x630、0x6e0、0x880–0x883、0x900 | u32 长度，负载 |
| Indexed | 0x380、0x400、0x6a0、0x700、0x800、0x8c0、0x8c8、0x8e8 | u16 对象序号，u32 长度，负载 |
| StringPair | 0x304 | 两段 u16 长度加字符串 |

写入顺序及已核对来源：

| 标签 | 来源 |
|---|---|
| 0x100–0x105 | +11840 存档标题（0x2162）、+14336 场景标题（0x2161）；+14592 主脚本名；+14624/+14656/+14688 公共脚本名 |
| 0x112–0x115 | +14720..+14732；0x112 等于 CSV2 第 2 段（脚本内存图像）长度 |
| 0x106–0x10b | +14736、+14740、+14744、+14748 起 40 字节、+16584、+14788 起 1796 字节 |
| 0x200–0x203 | CD3DDevice +84 清屏色（0x22cb）、+11144、+12092、CD3DDevice +80 深度清除标志（0x2250） |
| 0x240–0x243 | +82544、+82804、+82548 起 256 字节、+16740 起 64 KiB |
| 0x248 | +82816..+82856的11个原始32位字；当前执行器只解释前7个整数系统结果，后4字不据此推断类型 |
| 0x280–0x283 | 整数变量0..2047（8192字节）、浮点0..1023（4096字节）、位变量0..2047（256字节）；字符串变量0..63在内存各占1024字节，磁盘负载为64个紧邻的NUL结尾串，非固定64KiB |

| 0x6e0、0x880–0x883、0x900、0x304、0x310、0x318 | 每次都写；0x900 拷贝 +16592 当前脚本内存图像的“未知段”（PS2A 头第 6 个 u32 给出长度） |

整数、位、字符串变量区经 VM 读写函数的引用确认；浮点区只核对到同族访问器。其余字段的业务含义不作推测。

## Rust 实现与边界

`snapshot::parse_records` 只遍历帧结构，不解释负载：未知标签、长度越界和截断均报错，不返回部分结果。
原版读取函数遇到未知标签会提前结束恢复；研究实现改为显式报错。输入超过原版 3 MiB 缓冲时同样拒绝。
`cmvs-save --records <存档>` 列出每条记录的偏移、标签、序号和负载长度。

`VmSnapshot::decode` 在帧检查之上读取主/公共脚本名称和内存长度、活动槽/PC/重复计数、SP/帧深度、完整64项帧表/64KiB栈/11字结果和局部变量。要求这些单例记录存在且不重复，校验已核对的固定长度、槽/栈/活动帧范围和名称终止；不会将SP外的原版栈残留误称为活跃参数。第2段经 `Script::from_memory_image` 读取，第0段0x900覆盖主脚本的可变数据段，长度须与头部一致。主脚本活动时进一步检查完整指令布局和保存PC边界；活动公共脚本没有随此API输入，明确标记PC尚未验证。其余记录保留为 `uninterpreted`，不作引擎恢复成功处理。

`LocalVariables` 仅覆盖0x280..0x283四条记录，可捕获全部已知的局部银行、编码和解码，以及通过 `apply_to_state` 原子安装到独立State。浮点保留原始位、位变量按低位优先解包，64个字符串须各有不超过1023字节的内容和NUL，最后不得有额外字节。缺失、重复、长度错误、未知变量或目标容量不足均报错；安装失败不改变旧State。高位/持久变量、表达式/系统结果、字符串累加器和所有宿主保持不变。该组件只做分域往返：捕获副本 bit0 由 `set_bit0` 单独设置，实时 bit0 由快照点清除，完整记录流由 `EngineSnapshot` 生成。

以上是离线VM负载检查及局部变量组件往返，不是Machine恢复。`cmvs-save --vm-state <存档>` 输出VM摘要与未安装记录；该模型解释真实样本每份45条中的21条，另24条留给独立宿主模型。下述视觉模型另解释其中8条，两者合计29条；这不表示29条已经安装到运行中的引擎。运行时完整读档在全部宿主重建后才继续，见下文“从宿主捕获、写入与读档”。

## 完整记录流模型（2026-10-30）

`EngineSnapshot::decode` / `encode` 覆盖写入函数输出的全部记录，按其固定顺序：29 条固定头部记录（0x100..0x105、0x112..0x115、0x106..0x10b、0x200..0x203、0x240..0x243、0x248、0x280..0x283），对象表（0x6a0×2、0x380×12、0x400×8、0x700×256、0x800×4、0x8c0×6、0x8c8×8、0x540、0x8e8×3），效果 0x600/0x610/0x620/0x630，尾部 0x6e0、0x880..0x883、0x900、0x304、0x310、0x318。解码只接受这一顺序；对象表内序号须严格递增且不超过表长，缺失、乱序、重复或 0x318 之后的多余记录均报错。编码按同一顺序重建。

文字、窗口、场景（含图像、绘制、帧动画）使用类型化编解码；其余子系统暂存原始负载。为了逐字节往返，视觉解码现在保留存档原值：绘制 +84 渐变系数、文字笔位置 +156/+160、文字 +324 字形纹理容量（新增 `TextObject::glyph_capacity`，0x2100 取 SP-12，0x215d 为 196）、禁用滤镜时残留的 +1204..+1212 参数。读取函数对前两项的复位（+84 = 256、笔位置回到区域原点）改在预览和恢复时执行，残留滤镜参数仍不应用。文字行规则关闭时要求 +332..+527 为零，开启时字符串之后不得有残留字节，否则显式报错。

读取函数 0x140069fd0 的已确认用途：0x113..0x115 读取时跳过；0x112 恢复 +14720；0x201/0x202 恢复 +11144/+12092；0x304 第一名非空时以 +4464 的 BGM 对象重新播放；0x310 为 6 个 52 字节音效通道，按名称重新播放循环音效；0x318 交给 +4456 声音设备；0x540 为 +4320 历史；0x880..0x883 交给设备的两台相机及其附属状态。全部恢复后按 +340 游戏名、分隔符和 +14336 场景标题重设窗口标题。

真实样本：4 份原版存档（save000/001/002/870）的第 0 段经 `EngineSnapshot` 解码再编码后逐字节相同，由默认忽略的 `external_snapshots_reencode_byte_identically` 以 `CMVS_SAVE_TEST_INPUTS` 显式执行。这证明记录流模型无损；从宿主捕获与安装见下文。

所有块必须恰好消费其长度，截断、尾随字节、错误终止符和不支持分支均返回错误。整体沿用3MiB快照限制，场景树最多2048节点、根深度0且子深度最多32；原版部分嵌套长度只读低16位，Rust使用有界u32，不模拟越界读取。已检查的真实嵌套块均小于64KiB。

`VisualSnapshot::preview(&mut dyn ImageSource)` 用调用者登记的只读资源路径加载图像，复用已有PB3/参考图链和mode2过滤器；原始/解码尺寸必须一致，单图和累计RGBA像素上限64MiB。全部资源成功后才返回新的 `VisualPreview { scene, messages }`，失败不会替换任何运行中的宿主。新宿主可供已有渲染器读取及推进帧动画；文字对象在该分支没有字形，字体后端由调用者显式选择。

这是组件预览API。它不重建Machine、相机/设备、计时/回调、音频、辅助文字或全局效果；窗口按钮+72/切换状态字仅供检查，不能据此宣称交互恢复。构造的字体存在标记只覆盖保存的文字槽，不代表恢复原字体缓存。未知效果、已显示字形和命名字体仍报错；预览不经过运行时读档。`cmvs-save --visual-state` 仅执行上述解析并报告摘要，不加载任何图像。

`SaveImage` 区分三种状态：`Absent` 表示原版缓冲尚为空，`Captured` 持有已构建或读入的镜像，`Unavailable` 表示原版此处会生成镜像但按 `--continue-without-snapshot` 没有构建。
`capture_unavailable` 只应用位变量 0 清零这一项实时效果，并记录脚本名和 PC，不伪造快照字节；此后写槽显式失败，不按 `Absent` 静默跳过，也不写出不完整镜像。
默认 `SnapshotPolicy::Capture` 在 0x2080/0x22b2 构建镜像；`Barrier` 停在首个快照点，`ContinueWithoutImage` 只用于研究。+14744 已确认是 Machine::repeat_count，旧说明所称缺失字段已更正。

## 剧情快照 0x22b2（2026-10-27）

本轮再次核对 IDA 输入 SHA-256 `dc74d2001387ae1aefbdc4204216de5ebb9d3896009280720c4e7a91b42d84f5`。
`0x140067930` 在 0x140067d1e–0x140067d28 根据系统返回标志 0x2000 增加或清零 +14744，0x0414 还从跨脚本栈恢复它；它就是已有的重复计数器。+14740 是 PC。
`0x14007c9a0` 临时将 PC 加 2、重复计数清零后序列化，再把 PC 减回并返回 0x4000；VM 随后前进到下一条指令。因此不建镜像时由 complete_system(0x4000) 完成最终 PC/计数变化，位变量 0 清零，SaveImage::Unavailable 记录下一条 PC，而非快照命令本身。参数栈和系统整数结果不变。
已补查当前场景涉及的文字、窗口、场景对象、图像、绘制状态、动画/不透明度轨道、覆盖层及历史文本序列化：0x14005c790、0x14005d050、0x14003a4a0、0x140030030、0x14001eef0、0x140026090、0x1400267f0、0x140026a00、0x14005eb60，所读路径把状态复制到输出，不推进动画或改写源对象。这不等于已核对所有未支持对象的序列化分支。
Startup 和 cmvs-trace 共用 SaveImage::try_handle；不开显式继续选项时不修改状态。位变量容量错误保留待处理命令、PC、重复计数与旧的不可用镜像记录。未生成 CSV2、未开放存档写入或恢复，变量变更追踪仍未建模。
真实鼠标重放第 38854 次 tick 停于 sn1001.ps3 / PC=0xf062 / 0x20ec，SP=164；键盘重放也到达同一 PC/命令。本轮没有原生窗口检查，未修改解码算法。

### 效果记录

0x610（`0x140050ec0`，40 字节）：方向、颜色、时长、层次四字供读取函数构造（`0x140050da0`），随后为对象 +0..+24 的完成标志、方向、颜色、层次、时长、已过时间；+24 的覆盖层对象不保存。读取函数 `0x140050f00` 重建覆盖层后拷回状态字并设置不透明度；未完成且时长为 0 时原版会除零，Rust 拒绝。0x620（`0x140051170`）：槽、时长、边宽、模式四字，NUL 结尾遮罩名，再拷贝对象 +0..+1064；读取函数 `0x140051450` 只用前几项与名称重新建立转场，对象字节交给空函数。Rust 按着色器路径写对象字节（无 CPU 阈值表）。0x630（`0x140052c40`，56 字节）：模式、颜色、条宽、时长、层次五字，再为对象 +0..+36；读取函数 `0x140052700` 不建条带，`0x140052c90` 按模式转为覆盖或释放。

### 绘制轨道与场景影片

写入函数 `0x14001eef0` 在 0x780 字段后按 +112..+152 的顺序写轨道，每个负载为 u16 版本 1 加对象内存：0x790 缩放（0xb8 字节：播放、基准 XY、起始/当前键、已过时间，8 个 20 字节键）、0x791 旋转（0x94字节，与0x792共用原版序列化函数；现已支持，见下节）、0x792 不透明度（0x94 字节：播放、基准、起始/当前键、已过时间，8 个 16 字节键）、0x793 帧动画、0x794 XY 移动（0x114 字节：播放、i16 基准 XY、起始/当前键、已过时间，16 个 16 字节键）、0x795 XYZ 移动（0xdc 字节：播放、基准 XYZ、起始/当前键、已过时间，8 个 24 字节键）。读取函数 `0x14001f080` 直接拷回内存而不检查；Rust 在解码时检查设置命令保证的条件（键号、播放中的当前键、已实现的插值模式、XY 时长 ≤ i32::MAX、不透明度 0..255）。未开始的轨道头部在原版未初始化，Rust 写零。

场景影片绑定对象的图像是种类 3 空白表面（`0x140034f60`，图像 +1224 = 3、+1232 alpha），图像记录只写尺寸与 alpha 标志、两段空名称；读取函数 `0x140035590` 重新建立空白表面并忽略滤镜字。0x8e8（`0x140038420`，298 字节）依次为 u16 版本 4、+268 播放器槽、+272 对象槽、+300 起 64 字节名称、+60..+268 的 208 字节播放块（当前段、待切换段、播放中、暂停、16 个循环/起点/终点段）、+280 当前帧、+48、+52 装载模式、+56。读取函数 `0x140039630` 用名称重开影片（`0x1400390b0`）、解码保存的帧到绑定对象，再拷回播放块，并把 +284 设为当前时刻、+288 已过时间清零。+48/+56 只由未实现的命令改变，Rust 要求为 0；装载模式要求 2。

### 失败边界

快照点存在下列状态时捕获报错，镜像、PC、位变量和待处理命令保持不变：超出已支持字号范围的文字字形等未支持分支。匿名内存图像现按原版仅保存尺寸、读档重建不透明黑图（见下节）。换图进行中可捕获：只保存当前新图和绘制状态，不保存旧图、公共区域和换图时钟；捕获不改变运行中的转场，读档后新图的绘制 fade 恢复为 256。五条结局路线的固定快进重放未覆盖混合输入下的活动换图快照；后续混合 Ctrl/点击回归已覆盖，见[研究记录](../games/amatsutsumi/research.md#混合快进与点击下的换图快照2026-10-31)。跨脚本返回帧（含自动回调调度的帧）是普通栈字，随栈保存；读档后的返回帧没有 Rust 侧的调用记录，按栈中内容返回。写槽后存档回调 30 已启用时写槽显式报错（读档前的 998 备份除外，其上下文随即被替换）。+4648 第二遮罩通道不在记录流中，读档时销毁。读档在修改宿主前完成全部解码、资源加载、脚本布局、窗口/历史/序列/相机/回调与标题检查；音频与窗口标题请求随后才发给后端，后端失败不回滚已提交的宿主。

## 显示中字形与离屏目标记录（2026-10-31）

0x380现支持最多4096个、字号1..128的44字节字形记录：原生子对象编号、40字节描述（u16长度40/u16字符码、图集索引、渐变、逻辑XY、字号、两色、描边和参数）。保存只读当前字形描述，显现的延迟/时间/透明度不进入存档；读档使用文字对象的字体与粗体重绘，每个字形立即完整显示，文字笔仍复位到区域原点。描述中的原生子对象/图集编号用于无损重编码，不作为宿主资源句柄；当前运行产生的字形用顺序编号。字体名支持1..31字节及空名缺省，原有不支持命名字体的限制已移除。这里不保存逐字字体变更前的旧字形外观，遵循原版重绘行为。

此前误称“覆盖层”的0x6a0实为两个可选D3D离屏目标的分配描述：u16版本0、u32宽高，共10字节，无像素。原版读取忽略保存的尺寸，按当前视口建立1024或2048方形资源；软件呈现没有同类D3D资源，所以验证版本和长度后不分配或恢复图像，不生成场景覆盖层。EngineSnapshot离线编解码仍保留原始记录；软件宿主捕获不生成这类设备资源记录。未知版本、损坏记录与未建模图像种类仍显式报错；旋转及匿名内存图像已由后续章节补齐。证据见[本作语义](../games/amatsutsumi/vm-semantics.md#显示中字形与离屏渲染目标快照2026-10-31)。

## 旋转轨道0x791（2026-10-31）

绘制状态+120的旋转轨道与不透明度轨道共用0x1400267f0/0x140026840序列化函数：负载为u16版本1加0x94字节对象（150字节），5个头字为播放标志、基准角、起始键、当前键、已过毫秒；8个16字节键为next、目标角、模式、时长。角为有符号百分之一度；构造/设键存100×(输入度数%360)，保留C的负数余数。读档保留当前角、轨道基准与进度，不重启或完成轨道。

Rust模型为RotationTrack/RotationKey，支持低字节0线性、1四分之一正弦缓动、0x80周期正弦，位15在0/1模式下反向。逐帧顺序为缩放、旋转、不透明度、帧动画、XY、XYZ；最大消费200ms，角度乘法按u32回绕。结束释放轨道，next=-2另销毁对象；换图将轨道所有权转移至新对象。未知模式、无效键号、损坏版本/长度、0x80零周期显式报错。零时长键循环限制每帧最多64次，避免复刻原版死循环。创建未播放轨道的未初始化头在Rust中写零；已解码的停止轨道保留其头字。

轨道读写和恢复后的推进已通过合成回归；另在原版save000的真实图像上注入合成活动轨道，通过CSV2正常加载与Python独立布局/角度对照。这不等于已有真实剧情旋转指令或原生窗口实测证据。详见[本作语义](../games/amatsutsumi/vm-semantics.md#旋转轨道与快照0x7912026-10-31)。

## 匿名内存图像（2026-10-31）

普通kind=0图像可以没有文件名，例如0x22bd从CSV2辅助段解码的缩略图/空槽占位图，或0x203c接收的屏幕截图。原版0x140030030只保存元数据、空名称和尺寸，不保存CPU/GPU像素；0x140035590在kind=0且主名称为空时忽略滤镜，调用0x140032b10(width,height,1)创建不透明黑图，alpha元数据变为true。保存不改变当前图像；恢复不承诺保留原截图或缩略图的内容。这与kind=3空白表面（可带alpha、随后由影片记录填帧）不同。

SavedImage现允许这类空名普通图像，无需ImageSource；保持54字节单图记录和既有尺寸/总像素预算。过滤参数及禁用时的残留字仍供离线无损往返，匿名图像安装时不应用它们。次级图像和递归子对象共用同一路径；复合名称、未知种类、特殊图像仍保留错误。合成屏幕捕获写槽/读回与真实存读档菜单中的5个匿名图像恢复检查通过，见[本作记录](../games/amatsutsumi/research.md#匿名内存图像快照2026-10-31)。
