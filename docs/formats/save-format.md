# CSV2 容器读取

> 本文描述已核对的实现分支，真实样本与历史验证来自[《アマツツミ》](../games/amatsutsumi/README.md)。其他游戏或引擎版本需单独验证；下文历史停点不代表最新完成度。

证据限于 research.md 中 SHA-256 标识的 cmvs64.exe，写入函数 0x140080b20、读取函数 0x140081960。
以三份用户生成的原版存档交叉核对。当前读取器只接受 CSV2、600 字节头、偏移 546 的 u16 为 1，
不从菜单接受 CSV2..9 推断其他版本的负载兼容。未知头字段保留在原始输入，不推测含义。

| 偏移 | 类型 | 已确认用途 |
|---|---|---|
| 0 | 4 字节 | CSV2 |
| 4 | u32 | 头长 600 |
| 16 | NUL 字节串 | 时间与剧情标签，保留原始编码 |
| 540 | u32 | 尾部校验和偏移；文件总长为该值 +2 |
| 546 | u16 | 当前写入器设置为 1 的编码字段；只支持这一取值 |
| 560 / 564 / 568 | 三个 u32 | 三段压缩长度 |
| 580 / 584 / 588 | 三个 u32 | 三段解压长度 |
| 600 起 | 变长 | 快照、辅助图像数据、脚本内存图像的压缩段，顺序拼接 |
| 文件末尾 -2 | u16 | 第一段磁盘字节累加和，模 65536 |

所有整数小端。只对第一段压缩数据使用循环密钥 DAME_SAVE_IMAGE：
密钥长15字节，逆变换为 `(byte XOR key[i % 15]).wrapping_add(128)`；第二、第三段没有此变换。
三段复用既有 2048 字节环形缓冲 CMVS LZSS。
校验和验证在第一段逆变换之前完成；它不覆盖头部、辅助数据或脚本图像，不是全文件真实性保证。

研究错误策略：

- 先用 u64 核对三个压缩长度之和、校验和偏移和文件总长，拒绝截断、额外尾字节或未覆盖的间隙。
- 文件长度和三个解压段的总长度分别不得超过 64 MiB。这是研究工具策略，并非原版容量声明或整个进程的内存峰值限制。
- 每段的压缩/解压长度必须同时为零或同时非零；支持缺失的辅助段。
- LZSS 发生截断、过量输出或最终长度不符则报错，不返回部分 `Csv2Save`。
- 标签另使用有界的 `SaveHeader` 校验，详情见 VM 语义；原版对异常输入的未定义行为不予模拟。

`Csv2Save` 返回三个字节数组，不安装 VM 状态。第 0 段的记录帧结构见 [snapshot-format](snapshot-format.md)，
`cmvs-save --records` 只遍历记录边界，不解释负载。
第三段是原程序保存的已解码 PS2A 内存图像，包含保留的原始头字段，不能再作为加密 PS2A 文件解码。
`Script::from_memory_image` 为此提供独立入口：严格核对48字节头、分段总长、decoded_size、入口和标签范围，不再使用保留的key/compressed_size做第二次变换或解压。内存图像拒绝截断及多余尾字节，与磁盘PS2A的尾部报告策略分开。
真实样本的第三段头后 payload 与独立从 script.cpz 解码的 sn1001.ps3 payload 一致。
完整恢复仍需记录负载解释、对象重建、脚本布局校验、计时与回调恢复。

`cmvs-save --vm-state <存档>` 已可校验VM元数据、局部变量及主脚本指令边界，并列出未安装的记录。它不安装Machine或引擎状态；公共脚本不在第2段中，活动槽非0时明确报告PC未验证。局部变量的分域编解码及原子安装边界见[快照](snapshot-format.md)。

## 编码（2026-10-30）

`Csv2Save::encode(header, snapshot, auxiliary, script_image)` 按写入函数 0x140080b20 组装文件：600 字节头由调用者提供（原版在快照时于 +11204 预先构建，写文件时再把 16..34 改写为当前时间），编码器只填写 540 校验和偏移、546 编码模式 1、560..568 三段压缩长度和 580..588 解压长度。三段各自用 0x140068210 压缩，空的辅助段直接省略；第 0 段再按 `(byte + 0x80) XOR key[i % 15]` 变换，并在文件尾写入变换后字节的 u16 累加和。

压缩器 0x140068210（插入 0x140067ef0、删除 0x1400680b0）是二叉搜索树 LZSS：2048 字节窗口，比较 33 字节，起点 2015，窗口初值为零；匹配长度至少 2 时输出引用 `位置低 8 位, ((位置 >> 3) & 0xe0) | (长度 - 2)`，否则输出字面字节并置标志位 1；只有严格更长的匹配才替换当前结果。它与 CSS1 编码器 0x14008db90 同属一族，只是窗口/前视长度和引用位分配不同，Rust 中两者共用 `lzss::encode_tree`。原版全局缓冲区的尾部残留只在输入短于 33 字节时参与比较，真实段远大于此。

验证：4 份原版存档（save000/001/002/870）解码后用各自的头部重新编码，与原文件逐字节相同（190273/138916/190277/190043 字节），由默认忽略的 `external_csv2_reencodes_byte_identically` 测试以 `CMVS_SAVE_TEST_INPUTS` 显式执行。CSS1 编码器改为共用实现后，与旧实现对真实 system.dat 负载（44864 字节）及 15015 个随机输入的输出完全相同。

CLI 默认只输出标签与段尺寸。`--section <0|1|2> <输入> <新输出>` 只在全部段解码成功后创建输出，
使用 create_new 拒绝覆盖，也不会按存档中的名称写入文件。CLI 本身没有游戏存档写入或格式转换功能。

0x22bb 的签名查询与本页的 CSV2 容器解码独立：它接受槽号 0..999，只检查 CSV2..9 四字节签名，不要求有效标签或正文；这不扩大 `Csv2Save` 的版本支持范围。目录源仍有界只读，菜单扫描继续最多 256 槽。当前原样启动对 save870.dat 返回 1 后停于 0x22b5 完整恢复请求，尚未安装存档状态。指令证据与边界见 vm-semantics.md。
