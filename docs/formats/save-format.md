# 剧情存档容器

## CMVS `CSV2`

布局依据为《Amatsutsumi》的写入函数 `0x140080b20` 和读取函数 `0x140081960`。其他构建按档案选择快照布局。 [样本身份](../games/amatsutsumi/README.md#样本身份)

| 偏移 | 类型 | 已确认用途 |
|---|---|---|
| 0 | 4 字节 | CSV2 |
| 4 | u32 | 头长 600 |
| 16 | NUL 字节串 | 时间与剧情标签，保留原始编码 |
| 540 | u32 | 尾部校验和偏移；文件总长为该值 +2 |
| 546 | u16 | 当前写入器设置为 1 的编码字段；只支持这一取值 |
| 560 / 564 / 568 | 三个 u32 | 三段压缩长度 |
| 580 / 584 / 588 | 三个 u32 | 三段解压长度 |
| 600 起 | 变长 | 快照、辅助图像数据、脚本内存图像的压缩段，顺序拼接 |
| 文件末尾 -2 | u16 | 第一段磁盘字节累加和，模 65536 |

所有整数小端。三段均用 2048 字节窗口的 LZSS。首段先校验磁盘字节，再按 `(byte XOR key[i % 15]).wrapping_add(128)` 逆变换，密钥为 `DAME_SAVE_IMAGE`。校验和仅覆盖首段。

`Csv2Save` 校验标签、段长、解压长度及校验和偏移。文件及解压段总长分别限于 64 MiB，空辅助段合法。签名查询 `0x22bb` 接受槽号 0..999，仅查 `CSV2..CSV9`，完整解码要求 `CSV2`。

第 0 段是[快照记录](snapshot-format.md)。第 2 段是已解码的 PS2A 内存图像，`Script::from_memory_image` 检查 48 字节头、段长、入口及标签，不重复解压。真实样本的内存图像负载与从 `script.cpz` 解码的 `sn1001.ps3` 一致。离线检查命令见 [CLI 指南](../guides/cli.md#存档)。

### 编码

`Csv2Save::encode(header, snapshot, auxiliary, script_image)` 按写入函数 0x140080b20 组装文件：600 字节头由调用者提供（原版在快照时于 +11204 预先构建，写文件时再把 16..34 改写为当前时间），编码器只填写 540 校验和偏移、546 编码模式 1、560..568 三段压缩长度和 580..588 解压长度。三段各自用 0x140068210 压缩，空的辅助段直接省略；第 0 段再按 `(byte + 0x80) XOR key[i % 15]` 变换，并在文件尾写入变换后字节的 u16 累加和。

压缩器 0x140068210（插入 0x140067ef0、删除 0x1400680b0）是二叉搜索树 LZSS：2048 字节窗口，比较 33 字节，起点 2015，窗口初值为零；匹配长度至少 2 时输出引用 `位置低 8 位, ((位置 >> 3) & 0xe0) | (长度 - 2)`，否则输出字面字节并置标志位 1；只有严格更长的匹配才替换当前结果。它与 CSS1 编码器 0x14008db90 同属一族，只是窗口/前视长度和引用位分配不同，Rust 中两者共用 `lzss::encode_tree`。原版全局缓冲区的尾部残留只在输入短于 33 字节时参与比较，真实段远大于此。

4 份原版存档重新编码后逐字节一致。回归 `external_csv2_reencodes_byte_identically` 通过 `CMVS_SAVE_TEST_INPUTS` 加载样本。

### 写入与读档

运行时写槽 `Runtime::save_slot`（0x22b6）只写 `--user-data-dir` 目录，原游戏目录保持只读：

1. 没有镜像（原版缓冲为空）时返回且不写文件；以 `--continue-without-snapshot` 跳过快照后写槽明确报错。
2. 头部取快照时预先构建的 600 字节，用宿主时钟改写 16..34 的时间（桌面为 UTC）；头部 548 启用缩略图且有 0x22b8 缩略图时写入辅助段。
3. 0..949 号槽已存在时先把旧文件写为 `save999.dat`（`0x140068b50`），再写系统存档（`0x1400179e0`），最后写槽文件。每个文件经同目录临时文件替换。

读档 `Runtime::load_slot`（0x22b5）：解码 CSV2 与记录流；0..949 号槽且已有镜像时先把当前镜像写为 `save998.dat`（`0x1400818e0`）；随后安装全部宿主并把读入的文件作为新的持有镜像，第 1 段缩略图作为当前缩略图。读入的头部 528/536 恢复 0x22b9/0x22ba，532 清零。记录安装顺序、失败边界与回调见[引擎快照](snapshot-format.md#从宿主捕获写入与读档)。

验证：写出的槽文件经 `Csv2Save::decode` 与 `EngineSnapshot::decode` 读回，与持有镜像逐字节一致（合成测试 `scenario_snapshot_writes_a_slot_that_loads_back_with_backups` 与外部路线重放）。

## CVNS `CSP1`

复用 600 字节头、三段 LZSS 和 2 字节校验和。容器接受 `CSP1..CSP9`，首段密钥为 14 字节的 `SAVE_IMAGE_ARC`。运行时写出 `CSP1`，偏移 544 为头部版本 3，偏移 546 为编码模式 1。

原版快照导入限于 `cvns-20090203` 的 `CSP1` v3。未知记录和活动场景特效会报错。新捕获的快照采用 `CvnsSnapshot` 记录 `0xa00..=0xa09`，首条记录以 `u32` 模式版本 1 开头。 [《みはる》验证](../games/miharu/README.md#当前验证)
