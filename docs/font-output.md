# OpenType 字体与首句文字预览

2026-10-27：首句可以由脚本布局后合成到研究画面中；尚未完成剧情播放器。

## 使用

```powershell
cargo run --offline --release --features desktop --bin cmvs-desktop -- "E:/Download/AMATSUTSUMI" --encoding shift-jis --continue-without-snapshot --font "C:/Windows/Fonts/msgothic.ttc" --font-face 0
```

字体必须显式给路径，face 默认为 0。支持 OpenType 文件和 TTC 集合的指定 face，不自动寻找字体或读取注册表。原游戏、字体均只读，不把系统字体分发到项目。`--font-face` 单独使用、字体无效或超过 32 MiB、字形不存在、编码无效均报错。`--font` 当前要求 shift-jis，与 `--record-text` 互斥。

启用字体会使用当前已核对的单行 0x2152 字形记录/计时分支，随后真正光栅化并合成字形；默认没有字体时仍保留 0x2152 断点。`--record-text` 保留纯记录行为。消息输出协议及受限设置见 vm-semantics.md。

## 架构与呈现边界

字体文件加载、Shift-JIS 转换、OpenType 解析、字形 mask 和缓存全部在 cmvs-desktop::font。cmvs-core 无新增依赖；它只接收外部 SceneObject，再将普通槽对象、字形、可见消息窗口对象和 fade 放入同一个稳定图层队列。两条路径不修改 VM 或素材。

本轮再次核对同一 SHA-256 二进制的 0x140015da0：先遍历 +1976 的 256 个槽，再遍历 +4128 的 12 项文字对象，随后 +4064 的 8 项消息窗口对象，+4616 覆盖层在其后入队；新入口保留这一相对次序，等层仍按原队列的稳定顺序处理。其他未建模队列族不宣称兼容。

当前支持 1280×720 文字逻辑坐标、单位缩放、字号 1..128、纯色/两端同色的渐变，以及 0/1/2 对应的无描边/一像素/两像素描边。只绘制 text.visible 且字形 shown、opacity 非零的项目；继承脚本层次、位置与逐字不透明度，消息窗口沿现有对象/子对象路径绘制，fade 仍按层次参与合成。实际原生字形与导出 PNG 使用同一后端入口。

缓存上限 128 种字形，单帧上限 512 个可见字形；非法轮廓范围、未知描边、异色渐变、非单位缩放及其他逻辑视口显式报错。换行、注音组及其他输出指令仍受前一阶段的消息分支限制，不能把第一句预览当成完整剧情。

字形 mask 使用 ab_glyph 的覆盖率与 ascent 基线，按逻辑字号生成有两像素留边的单元格，再做描边和 straight-alpha 合成。原版使用 GDI；字体选择、hinting、基线与边缘像素可能不同，本实现不承诺逐像素复刻 GDI。输入等待与逐字计时仍由核心记录模型处理，设备后端只读显示状态。
