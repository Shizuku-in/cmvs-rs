# VM 表达式、参数与控制流证据

适用二进制 SHA-256：`dc74d2001387ae1aefbdc4204216de5ebb9d3896009280720c4e7a91b42d84f5`。
本轮结论来自 IDA 静态反编译；未与原程序动态执行轨迹对照。

## 表达式编码

前缀：0x0200 整数，0x0201 字符串引用，0x0202 浮点。结束词均为 0x020f。
多数普通操作数由 16 位 tag 和 32 位数据构成；嵌套、索引与运算符有不同长度，不能固定步长扫描。

整数入口 `0x140066200`：

- 0x0100：32 位立即数；运算以有符号 32 位整数解释。
- 0x0101 / 0x0102：后接整数子表达式，分别用结果索引整数变量或位变量。
- 0x0105 / 0x0109 / 0x0110 / 0x0112 / 0x012d / 0x012f：base 后跟一个子表达式，元素步长为 4。
- 0x0107 / 0x010b：base、16 位 stride、一个子表达式。
- 0x0111 / 0x0113：base、16 位 stride、两个子表达式。
- 0x0160..0x0169：乘、除、余、加、减、与、或、异或、左移、有符号右移。
- 0x016a..0x016f：大于、大于等于、小于、小于等于、逻辑与、逻辑或。
- 0x0170：赋值；0x0171/0x0172：相等/不等。
- 0x0173..0x017e：递增、递减及复合赋值。全局整数/位变量已支持这些修改。

读取器 `0x1400652e0` 和写入器 `0x1400657b0` 证明这些操作数有左值/右值之分。
整数全局读写辅助函数 `0x140085e00/0x140085dc0`，位变量辅助函数 `0x140085d60/0x140085ce0`。
后两者通过字节索引与位掩码访问，不能用普通整数数组代替。
读取还会涉及变更追踪；后续 VM 不能只根据函数名忽略这些副作用。

Rust 已支持整数常量、全局整数/位变量与赋值求值。整数加减乘使用 wrapping，移位计数按低五位处理。
除零和有符号除法溢出报错，不模拟原 CPU 异常。非法表达式栈形状和未知状态显式报错。

## 字符串引用

`0x140066b00` 生成引用；`0x14006b850` 根据高两位选择区域，低 30 位为偏移或索引：

| 高两位 | 区域 |
|---|---|
| 00 | 当前脚本文本段 |
| 01 | 当前脚本可变数据段 |
| 10 | 全局字符串槽 |
| 11 | 当前调用帧数据 |

本版字符串槽解析器按 1024 字节步长，索引大于 127 时回退到第 0 槽。
Rust 目前保留槽编号，没有在没有运行上下文时伪造指针或复制此回退行为。
浮点表达式见下文“浮点表达式与帧变量”；字符串表达式见下文“字符串表达式”。

## 参数栈和系统返回值

主循环 `0x140067930`：0x0430 将 32 位结果寄存器压栈，SP 增加 4。
系统命令返回 16 位状态，主循环解释如下：

| 位 | 效果 |
|---|---|
| 0x8000 | 本次主循环让出执行 |
| 0x4000 | PC 前进 2，并按低 8 位的**字节数**回收栈 |
| 0x2000 | 增加重试/重复计数，否则清零该计数 |

示例：0x2000 返回 0xc000，让出执行且前进 PC，不回收参数。
0x2010、0x2011、0x2014 对应处理函数 `0x140071710/0x1400717c0/0x140071b30`：
SP-4 读取槽号，SP-8 读取字符串引用，返回 0x4008，即回收 8 字节。
0x201d/0x201e/0x201f 读取栈顶 32 位数并返回 0x4004。
0x2080 的处理函数 `0x1400810f0` 从栈顶解析脚本名，切换脚本后返回 0；不能套用普通命令的 PC/栈回收逻辑。
底层路径注册时还有当前根目录和包配置参数，覆盖优先级尚未验证。

## 控制流

- 0x0400：长度 6，后接目标 PC，绝非 NOP。
- 0x0401 / 0x0402：长度 6，依据条件标志最低位跳转。
- 0x0403：长度 10，比较立即数后决定跳转。
- 0x0407：长度 10，目标取 PC+6；PC+2 的 32 位字段在当前主循环中没有用于比较。
- 0x0405 / 0x0410：16 位标签索引；0x0410 额外压返回 PC。
- 0x0411 / 0x0412：16 位栈调整字节数，具体返回语义仍需完整执行器验证。
- 0x0440 / 0x0442：长度 8，16 位栈调整数及 32 位立即数，不等同于普通 push。

## 验证与边界

本作 start.ps3 全部代码通过 Rust 结构解码，并校验入口、标签与直接跳转目标。
完整反汇编输出只保存在仓库外 scratch 目录；合成测试覆盖类型、嵌套、后缀顺序、移位、异常算术与截断。
`cmvs-disasm` 保持线性结构工具。`cmvs-trace` 使用部分单步执行器，系统后端和完整浮点语义尚未实现。

## 有状态求值与单步执行

`State` 以稀疏已知值保存整数和位变量；不存在的槽是未知值，不能自动读取为 0。
位变量的逻辑读写按布尔值规范化；尚未实现原版位打包存档布局和变更追踪。
整数索引限制 8192、参数栈 65536 字节和调用深度 256 为研究策略。
默认位索引容量现为 262144，覆盖本版本已静态核对的 CSS1 持久位区；不推广为全部 CMVS 版本的容量。

0x140066200 在每次整数表达式结束时调用 `0x140085dc0(4096, result)`，
因此嵌套求值也会更新全局整数槽 4096、结果寄存器和条件标志。
左值保存变量引用，执行运算时再读取当前值；不能在解析左值时提早缓存数值，否则嵌套副作用会导致错误。
赋值不先读取目标旧值，所以未知槽可以通过赋值初始化。

研究实现的错误策略：完整整数表达式成功才提交包含嵌套表达式的所有修改；
读未知槽、超出策略限制、除零或非左值赋值时返回明确错误，保留之前的状态。
这是便于研究的事务性错误处理，不声称模拟原程序对无效脚本的未定义行为。

单步执行器支持经过核对的 0x0400/01/02/03/05/07/10/11/12/30 控制流与参数操作，
以及 0x2000 WAIT。其他系统命令产生待处理请求；重复 step 返回同一请求，不会重复消费参数。
`complete_system` 是显式宿主接口，只允许已完成效果的普通命令前进 PC；
0x2080/81 必须通过专门的多脚本 API 处理，不能通过提交普通返回标志跳过。
0x0440/42 在栈步长恰为 4 时已支持；其他步长仍明确报错。
0x0414 的跨脚本返回已支持。字符串表达式可读取帧参数（tag 0x122），整数/浮点表达式支持帧变量 0x103/0x108/0x129/0x12c；仍不支持 0x0413/16、脚本数据读写、数组形式操作数或完整存档状态。

## 可选启动处理模块

`bootstrap::Bootstrap` 处理已静态核对的配置字段、变量区域填充和资源路径注册。
严格单步模式仍将它们作为待处理命令；CLI 只有加 `--bootstrap` 才启用这个处理模块。
路径以原始字节按命令类别/槽号保存，没有解包、打开资源、写存档或创建窗口。
这部分只记录配置，不宣称实现了后续平台效果或原程序的存档变更追踪。
0x22b3 涉及存档扫描和 Windows 菜单；仅在另行启用 `save_menu` 宿主时处理数据层，详见 `research.md`。

浮点和字符串槽已支持范围初始化与只读查询；这不等于浮点算术和动态字符串表达式已完整实现。
字符串槽索引 >127 的读取按当前版本解析器回退到第 0 槽；第 0 槽仍未知时明确报错。

## 多脚本槽、公共初始化与返回

`0x140071e10` 实现 0x2081，取 SP-4 的公共槽号和 SP-8 的脚本名。
`0x1400689e0` 对外部槽号 0..2 映射到内部脚本槽 1..3；主脚本占内部槽 0。
成功时先回收 8 字节参数，依次压入 repeat、调用方 PC+2、调用方内部脚本槽，
进入新公共脚本头部指定的入口；它不是只缓存脚本。主循环收到返回标志 0，因此不能再套用普通参数回收。

0x0414 按槽号、PC、repeat 的逆序弹出三字上下文，切回调用方，不弹出普通函数的调用帧。
原 VM 主循环不读取该指令的后续保留字；真实 intproc/intcode 文件和标签边界表明其文件编码宽度为 4 字节。
Rust 将这个额外字保留为不解释的字段，而不是把后面的 0 当成未知指令或 NOP 跳过。

`State::evaluate_integer_with_labels` 为 0x010e 提供当前脚本标签表，标签位置是相对当前代码段的偏移。
不同脚本不能共用主脚本的标签表。变量状态、结果和普通参数栈跨初始化执行保留。
加载失败或非法目标不安装半成品脚本，不消费待处理参数；替换仍活跃的公共脚本属于研究策略禁用项。

## 回调与主脚本切换

0x2088 / `0x140071ed0` 从 SP-4 起读取槽号、目标 PC 和三个字段，登记来源脚本槽，返回 0x4014。
时间戳来自 `0x140008bc0`。研究处理器要求明确的虚拟 tick（CLI 默认 0），并不模拟真实时钟或自动调度。
0x2089 写对象 +14788 的布尔标志；0x208c 写 +12240，均回收 4 字节。
0x2083 将两个参数打包为版本字段。上述设置目前按命令 ID 保存。

0x208a / `0x140071f70` 按回调槽号低六位查找目标，回收 4 字节后保存三字跨脚本上下文，进入已登记脚本/PC。
0x208b / `0x140072020` 将回调目标置 -1；Rust 保留登记字段并标记禁用。没有实现定时回调自动触发。

0x2080 的主脚本装载路径 `0x140080530` 重置参数栈、普通/跨脚本调用状态和 repeat，
保留公共脚本及全局变量；主脚本来源的回调失效，公共脚本回调保留。
其后 `0x1400810f0` 还会调用 `0x140069270` 创建引擎级存档快照，涉及时间、画面、音频和其他状态。
研究 API 只完成核心切换并返回 `MainPreparedNeedsSnapshot`；默认在此停止，不把快照当作空操作略过。
快照缓冲只供存档写入使用；对 VM 唯一可见的实时影响是位变量 0 最终被清零，详见 `snapshot-format.md`。
`--continue-without-snapshot` 或 `SnapshotPolicy::ContinueWithoutImage` 只应用这一项影响，并把存档镜像记为不可用，然后进入主脚本。

## 存档菜单数据层

0x22b3 / `0x14007c9e0` 读取 SP-4 的有符号槽数，负数取 10，大于 256 取 256；零不扫描。
`0x1400931a0` 只读每个 `save%z3.dat` 的前 512 字节，接受 CSV2..CSV9，取偏移 16 的 NUL 标签。
`0x140093070` 从标签前缀 `YYYY-MM-DD HH:MM:SS` 计算排序键：
`YY<<25 | (MM&15)<<21 | (DD&31)<<16 | (hh&31)<<11 | (mm&63)<<5 | (ss/2&31)`，按 u32 截断。
原版不使用文件 mtime，只看年份末两位及两秒精度；严格大于初始键 0 才更新最新槽，平局保留首个。
`0x140092f50` 对识别的槽启用对应读取菜单项，最新槽在两组中勾选；写入菜单项始终可用。
这是菜单层识别，不代表版本 2..9 的完整快照均可恢复。

0x22b4 / `0x14007caa0` 将 SP-4 规范为布尔值，调用 `0x140092ea0`，
无条件启用子菜单位置 0，按该值设置位置 1；同时写引擎 +1644、+16584 字段。
研究模型以 `second_group_enabled: Option<bool>` 表示该状态，未执行前保持未知。
两条指令均返回 0x4004，回收 4 字节、PC 前进 2，不覆盖表达式结果寄存器。

Rust 对截断头、缺少 NUL 和非数字/分隔符异常的时间前缀显式标记 Invalid；
不做日历有效性判断，数字字段仍遵循原来的位掩码。
原程序只要求读取结果非零，再读取固定位置，可能涉及未初始化缓冲区；研究实现不模拟此异常行为。
除 NotFound 外的文件错误中止命令，不将权限错误静默当作空槽，且保留 VM 参数与之前的菜单。

## 光标登记与整数系统结果

0x2098 / `0x1400722a0` 解析 SP-4 的字符串引用，调用 `0x14008d560` 登记名称，
把从 1 开始的编号写入对象 +82816，返回 0x4004。重复名称也追加；不会在此调用 LoadImage。
Rust `Bootstrap::cursor_names` 保留原始字节，以注册顺序对应编号，不推测资源根目录。
原节点大小 0x88，其中前 8 字节为链指针；研究实现限制名称小于 128 字节，并限制登记数 1024。
过长名称、无效引用或缺少参数时，不修改登记表、系统寄存器或待处理栈。

整数表达式标记 0x010f 的槽号是立即 u32；`0x1400652e0` 对槽 0..6 读取
对象 +82816..+82840，槽 7..10 从后续四个浮点字段转整数，超出 0..10 返回 0。
Rust 现支持 0..6 的只读整数值，缺失值明确报错；7..10 的浮点转换仍报未实现，超范围按原版返回 0。
系统结果不会直接覆盖表达式结果 +82812 或条件标志，只有后续整数表达式求值才更新结果和整数 4096。

0x2099 / `0x1400722e0` 调用 `0x14008d5f0` 选用登记项，涉及 LoadImageA、SetClassLongPtrA、DestroyCursor。
默认保留为宿主请求；显式记录模式现可读取并解析登记 CUR、记录选择结果，但没有原生光标显示。
当前真实启动没有在登记后立即调用 0x2099，而是执行变量赋值后进入 0x2128。

## 系统持久数据读取

0x2128 在 `0x1400823a0` 的 case 296 调用 `0x140018da0`，随后返回 0x4000，不回收参数。
CSS1 变量区和两组名称列表的范围、字节转换及读取策略见 `system-save-format.md`。
游戏标识字段非零时，与引擎 +1648（0x201d 配置）比较；未知或不匹配时研究宿主报错，不继续应用。
原版使用 +12056 的错误标志及镜像变量区跟踪变化；这些追踪字段尚未建模，不声称已支持存档写回。
文件缺失时保持当前状态并继续；权限错误、损坏或不支持的格式显式失败且保留待处理请求。

0x2160 / `0x140075260` 读取一个字符串引用，调用 `0x140009480` 复制窗口标题并执行 SetWindowTextA，返回 0x4004。
默认仍保留为断点。新增的 `PlatformHost` 在显式记录模式下可提交标题请求，原生平台窗口仍未实现。
后端接口与额外启动命令见 `platform-host.md`，不能把记录请求描述为窗口或画面已经启动。

## 清屏状态

0x22cb / `0x14007b950` 读取 SP-4 的 u32，经 `0x14001c020` 写入引擎 +1968 指向的 CD3DDevice +84，返回 0x4004。
0x2250 / `0x14007ecb0` 把 SP-4 规范为布尔值写入 +80，同样返回 0x4004。两者都不修改 VM 变量或结果寄存器。
每帧 `0x14001c3d0` 把 +84、+80 交给当前 surface 对象（CBackSurface/CBestSurface 槽 6）调用 IDirect3DDevice9::Clear：
颜色为 `0xFF000000 | (+84 & 0xFFFFFF)`，即不透明 0xRRGGBB；+80 非零时连同深度清为 1.0，否则只清目标。
构造函数 `0x14001d5d0` 与 0x2003 重置 `0x140080700` 都把两者置 0；快照记录 0x200/0x203 分别保存这两个字段。

Rust `scene::SceneHost` 只保存 `ClearState`（原始 u32 与深度标志），`rgba()` 给出渲染器使用的不透明颜色，本身不绘制。
`Startup` 总是处理这两条命令；`cmvs-trace` 仅在 `--record-platform` 记录模式下处理并输出状态。
原生桌面目前仍显示诊断棋盘格，没有使用清屏色。

## 字符串表达式

0x0201 / `0x140066b00` 是累加器模型。每次求值先把 +82864 的 1024 字节缓冲清空，再逐项压入：
tag 0x121 对嵌套整数表达式求值（由 `0x140066200` 完成，同样更新结果、条件和整数 4096），记为结果加 0x80000000；
其他标量按 tag 与 u32 原样压入。运算符只在弹出操作数时经 `0x1400652e0` 读取字符串，读取即追加到缓冲：

| tag | 读取时追加 | 作为赋值目标（`0x1400657b0`） |
|---|---|---|
| 0x120 | 文本段偏移处字符串 | 无效果 |
| 0x121 | 字符串变量 0..127；越界不追加 | 缓冲写入字符串变量 0..127；越界不写 |
| 0x122 | 帧表 +82548[+82804] 减偏移处的 u32，按高两位解析为文本、脚本数据、字符串变量或帧内字符串 | 无效果 |
| 0x125 | 脚本数据（未知段）偏移处字符串 | 写入脚本数据 |
| 0x127 | 帧基址加偏移处字符串 | 写入栈帧内存 |

0x170 先读右侧再把缓冲写入左侧；0x160–0x16f、0x171、0x172 依次读两侧，所以字符串相加即拼接。
运算后两项合并为 tag 0 的占位项。表达式结束时只按栈底一项设置 +82812：
0x120 取偏移，0x121 取带 0x80000000 的引用，0x122 取帧中原始 u32，0x125/0x127 分别加 0x40000000/0xC0000000；
栈底是占位项时结果保持不变，因此赋值表达式结束后结果仍是嵌套索引值。该求值器本身不修改条件标志。

`0x0410` 压入返回地址后执行 `frame[++depth] = SP`。帧表只有 64 项，表项 0 为基址，因此最多嵌套 63 层；
Rust 帧栈上限由 256 改为 63。0x0411 弹出返回地址、深度减一并回收指定字节，与原有实现一致。

Rust 研究边界：缓冲超过 1023 字节、读取未知字符串变量、帧外访问、帧内字符串（0xC0000000 / tag 0x127）、
0x125/0x127 写入及其他赋值目标均显式报错，且整条表达式不提交任何写入。原版对这些情况不检查边界，研究实现不模拟溢出。

## 存档标题与场景标题

0x2162 / `0x140075360` 解析 SP-4 的字符串引用；长度小于 128 时复制到 +11840，否则不复制并给 +12056 置位 8，均返回 0x4004。
+11840 由构造函数 `0x140016e20` 设为空串，是快照记录 0x100，并由快照写入函数接在日期后面组成存档标签。
Rust `snapshot::SaveTitle` 保存该字节串；≥128 字节的分支涉及未建模的错误标志，研究实现报错且不消费参数。

0x2161 / `0x1400752a0` 把字符串复制到 +14336（快照记录 0x101），并以 `+340 + 81 40 + 字符串` 调用 SetWindowTextA。
它由 `PlatformHost` 作为标题请求处理，见 platform-host.md。main.ps3 标签 186 用同一字符串依次调用 0x2162 和 0x2161。
`Startup` 总是处理两者；`cmvs-trace` 仅在 `--record-platform` 记录模式下处理。

## 指针手势配置

引擎 +4664 是 `0x1400533d0` 构造的 0x134 字节对象。每帧更新（`0x140019430`）从 +4656 鼠标对象取坐标，
在最多 6 个矩形（+188 起，每项 20 字节）内识别拖拽/轻扫：+0 与 +8/+12/+16/+20 都非零才开始跟踪，
位移阈值 4 像素、计时 100 ms（`0x1400541a0`、`0x1400537a0`）。各配置字段的具体业务含义尚未逐一核对，按偏移命名。

| 命令 | 处理函数 | 效果 | 返回 |
|---|---|---|---|
| 0x2350 | `0x14007fb60` → `0x1400548e0` | +0 = bool(SP-4) | 0x4004 |
| 0x2351 | `0x14007fba0` → `0x140054920` | +24 = bool(SP-4)，+28 = bool(SP-8) | 0x4008 |
| 0x2352 / 0x2356 / 0x2357 / 0x2358 | `0x14007fbe0` / `fc20` / `fc60` / `fca0` | +8 / +12 / +16 / +20 = bool(SP-4) | 0x4004 |
| 0x2364 | `0x14007fe60` → `0x140053630` | +4 = 原始 SP-4 | 0x4004 |
| 0x235a | `0x14007fd80` → `0x1400535f0` | SP-4 在 1..=90 时写 +36，否则不变 | 0x4004 |
| 0x235b | `0x14007fdb0` → `0x1400535e0` | SP-4 为非负有符号数时写 +32，否则不变 | 0x4004 |

除 0x235a/0x235b 外，各 setter 同时重置跟踪字段：+44/+88/+172 = -1，+48/+52/+72/+76/+80/+84/+92/+108/+120/+180/+184 = 0。
构造函数初值：+0..+28 为 0，+32 = 64，+36 = 90，跟踪字段同上。Rust `gesture::PointerGesture` 以这些初值起步，
只保存配置与重置结果；由于没有接入输入，跟踪字段不会被其他途径修改。`Startup` 总是处理，`cmvs-trace` 在 `--record-platform` 下处理。

## 浮点表达式与帧变量

0x0202 / `0x140066e60` 与整数求值器结构相同，栈项为（tag、原始值、浮点槽）。读取 `0x1400659b0` 与写入 `0x140065f00`
的浮点参数经 xmm3 传递（反编译遗漏，已由反汇编确认）：0x12a 字面量与运算结果保存在浮点槽中。

| tag | 读取 | 写入 |
|---|---|---|
| 0x100 / 0x101 / 0x102 | 整数字面量 / 整数变量 / 位变量转 float | — / `(int)v` / `(int)v != 0` |
| 0x103 / 0x108 | 帧基址减 / 加偏移处的 int 转 float | `(int)v` |
| 0x129 / 0x12c | 帧基址减 / 加偏移处的 float | v |
| 0x12a | 字面量 | — |
| 0x12b | 浮点变量（0..2047，`0x140085e40/e30`，无变更追踪） | v |

`(int)v` 为 cvttss2si 截断，NaN 和超出 i32 范围时得到 0x80000000。+、−、×、÷ 按 float 计算；
%、&、|、^、<<、>> 先截断两侧再按整数计算，结果转回 float；比较和逻辑运算得到 0.0/1.0。
0x170 赋值、0x173/0x174 自增减、0x175–0x17e 复合赋值与整数版对应（复合赋值先读右侧）。
结束时结果的位模式写 +82812，条件位为 `result != 0.0`；只有嵌套整数表达式会写整数 4096。
研究实现对涉及 NaN 的比较显式报错（原版分支对无序比较的处理尚未逐条核对），对整数除零报错。

帧变量：`0x0410` 令 `frame[++depth] = SP`，装载主脚本时 `0x140080530` 以一次 8 字节写入同时清零 SP 与 frame[0]，
因此深度 0 的基址恒为 0，main.ps3 入口压入的 6 个字即是其局部变量。0x103/0x129 访问 `基址 − 偏移`（参数），
0x108/0x12c 访问 `基址 + 偏移`（局部变量）。Rust 通过执行环境把参数栈交给求值器；栈写入同样记入撤销日志，
越出当前栈内容的访问显式报错。字符串表达式的 0x122 也改为在深度 0 使用基址 0。

## 弹出菜单开关

0x22cd 在分发器内联处理：+12092 = (SP-4 != 0)，返回 0x4004。主循环每帧调用 `0x140018850`，
鼠标按键条件成立、+12092 非零且 +12240 为零时经 `0x140090ab0` 以 TrackPopupMenu 打开 +4728 菜单（与存档菜单同一 HMENU）。
构造函数 `0x140016e20`、0x2003 重置和读档都把 +12092 设为 1；它是快照记录 0x202。
0x22ce 把 +12092 复制到系统结果槽 0 并返回 0x4000（不回收参数）。0x22cf 写 +12096 = 1，未找到直接读取者，仍保留为未处理。
Rust `SaveMenuHost::try_handle_popup` 处理 0x22cd/0x22ce，不需要存档目录，也不创建原生菜单。

## 随机数 0x20d4

0x20d4 / `0x140074b10`：系统结果槽 0 = `rand() % SP-4`，返回 0x4004；除数为 0 时原版 idiv 异常。
`rand` 为静态链接的 MSVC CRT（`0x1400c77b4`）：`state = state * 214013 + 2531011`，返回 `(state >> 16) & 0x7fff`。
原版在构造函数中以 `srand(timeGetTime())` 播种，主循环（`0x14000e400`）每帧还调用一次 `rand()`，因此具体数值不可复现。
Rust `random::CrtRandom` 实现同一生成器，种子必须显式给出：`Startup` 与 `cmvs-desktop` 默认 0（`--rand-seed` 可改），
`cmvs-trace` 只有加 `--rand-seed` 才处理 0x20d4。研究实现不模拟每帧额外抽取；除数为 0 时报错且不推进生成器。

## 效果音通道 0x20b0

0x20b0 / `0x140070b70`：SP-4 通道 0..5，SP-8 文件名，SP-12 音量（int），SP-16 循环标志，SP-20 第五参数标志，返回 0x4014。
通道越界时只给 +12056 置位 0x200。+1608（`SE_USE`）非零时，有效音量为 `(+1612 × +1620) >> 8`，
脚本音量为正时再 `(音量 × 有效音量) >> 8`（均为 32 位无符号运算），调用 `0x140088390` 在设备通道 `通道 + 9` 播放，
并把是否成功写系统结果槽 0；+1608 为零时既不播放也不写结果。无论是否播放，都把通道记录写入 +1656 + 52 × 通道：
名称（32 字节）、+1688 循环、+1692 音量、+1696 = 256、+1700 = 0、+1704 标志。菜单切换 SE（`0x140017580`）关闭时停止通道 9..14，
打开时按这些记录重新播放。+1608/+1612/+1620 由构造函数设为 1/256/256，启动时 `0x14000a3c0` 再从注册表 `param` 键
（`SO_SeUse`、`SO_MasterVolume`、`SO_SeVolume`）或 INI `[SOUND_INFO]`（`SE_USE`=1、`MASTER_VOLUME`=100、`SE_VOLUME`=100 等默认值）覆盖，
0..100 到 256 刻度的换算经菜单辅助函数完成，尚未核对。

Rust `audio::AudioHost` 以构造函数值为默认 `AudioSettings`（宿主可显式提供），通过 `AudioBackend::play` 请求播放：
Ok(true)/Ok(false) 对应原版成功/返回 0，Err 时不提交任何状态。默认 `RecordingAudio` 只记录请求并返回 false（确实没有播放）。
通道越界（未建模标志）与名称超过 31 字节显式报错。`Startup` 默认使用记录后端，可经 `set_audio_backend` 替换；
`cmvs-trace` 在 `--record-platform` 下处理。

## 场景对象槽 0x2020/0x2021

引擎 +1976 是 256 个对象指针（快照记录 0x700，序列化函数 `0x14003a4a0`）。
0x2020 / `0x14006bb00` 取 SP-4 槽号：先销毁已有对象（`0x14003c590`），再新建 0x38c8 字节对象（构造函数 `0x14003a3c0`），
0x2021 / `0x14006bbc0` 只销毁。两者均返回 0x4004。槽号与 256 作有符号比较：≥256 只给 +12056 置位 0x10，
负数会越过检查索引到表前，原版不防护。构造后的对象含父指针、96 个清零的 64 字节子项和若干计数字段（+6244 = 1、+6248 = 0x7fffffff），
字段含义需由后续属性命令确定。Rust `SceneHost` 只记录槽是否存在及“刚构造”的空 `SceneObject`；越界槽号显式报错。

## 字符串长度 0x20f8 与图像加载路径

0x20f8 / `0x1400747c0`：系统结果槽 0 = `lstrlenA(解析 SP-4 字符串引用)`，返回 0x4004。它属于 0x20f0–0x20ff 字符串工具组，
Rust `text::try_handle` 目前只处理已核对的 0x20f8，同组其他命令仍保持未处理。

0x2030 / `0x14006c220`（实现见下节）：SP-4 对象槽、SP-8 文件名；槽有效且对象存在时调用 `0x14003bb10` 重建对象的图像（+6176），
经 `0x1400325a0` → `0x140036e60` 在 +4760 图像管理器中查找并解析，再由 `0x1400301d0` 创建最多 128 块纹理，
成功与否写系统结果槽 0；槽无效或对象不存在时给 +12056 置位 0x10。返回 0x4008。
图像管理器有 10 个条目（+4232 起，每项 2048 字节路径加归档对象指针），由 0x2011 / `0x1400717c0` 经 `0x140035b00` 按槽号（<10）填写：
路径以 `\` 结尾为目录，否则按格式打开归档。查找 `0x140036820` 按条目 0..9 顺序取第一个命中，均未命中时弹出 MessageBox 并失败。
本作 0x2011 注册顺序为 chip、bg、event、stand、up、balloon；后台预读缓存（+24848 起）命中同名图像时直接取用，不改变结果。

## 对象图像加载 0x2030

0x2030 / `0x14006c220`：SP-4 对象槽、SP-8 文件名，返回 0x4008。槽 < 256（有符号比较）且对象存在时，
`0x14003bb10` 先销毁对象 +6176 的旧图像对象，再新建一个（`0x14002fd00`）并经 `0x1400325a0` 加载；
系统结果槽 0 = 加载是否成功。+12032 非零时还会调用 `0x140018bc0`；该字段只由 0x212a 置 1（构造/复位时清零），
0x212a 仍未处理，因此这条分支不会执行。槽无效或对象不存在时只给 +12056 置位 0x10。

查找（`0x140036e60` → `0x140036820`，子目录参数为空）：按 0x2011 条目 0..9 顺序，跳过空路径；
路径以 `\` 结尾时读取“游戏根目录 + 路径 + 文件名”（`0x1400087c0`，打不开即未命中），
否则调用归档对象 vtable +24。本作 0x201f = 10，归档类为 `0x140001fb0`（CPZ6），其查找 `0x140002090`：
把查询名复制进 64 字节缓冲，ASCII A–Z 转小写、Shift-JIS 前导字节（0x81–0x9f、0xe0–0xfc）连同后随字节跳过，
再在所有目录中按索引顺序与存储名逐字节比较，取第一个命中。归档打不开（`0x1400029a0` 读头失败）也视为未命中，
头部格式错误则弹窗退出。全部条目未命中时弹出 MessageBox，返回 0。后台预读缓存（+24848 起）只在同名时提前给出相同结果；
+24792 的一次性标志只在 PB3 type 6/8 引用基础图时置位。

数据校验：0x2011 把 +16728/+16732 传给归档（vtable +40 写入 +64/+68）。它们分别来自启动时的 `PACK_HEADER_CHECK`
（默认 1）与 `PACK_DATA_CHECK`（默认 0），先读注册表 `SI_PackHeaderCheck`/`SI_PackDataCheck`，缺失时读 INI `[SYSTEM_INFO]` 并回写；
本作 `cmvs.cfg` 两者均为 1。数据校验开启时，资源读出后、解密前用 `0x140062fc0` 求和：从 0x5a902b7c 起
按小端 u32 累加，再逐字节累加尾部，必须等于文件记录 +16 的值，否则弹窗并 `exit(1)`。头部校验和（偏移 60）
与 +64 控制的索引摘要比较尚未在 Rust 中实现。

解码（`0x140036700`）按魔数选择：`\x89PNG`、`BM`、`PB3B`、`MSK0`、`PB2A`；其他魔数返回 0（不弹窗）。
PB3B 由 `0x140036ae0` 按头部 type 分派：1 → `0x1400a0230`；2/3/4/5/7 各有解码器；6/8 先以 `.pb3` 基础图递归查找；
type 不在 1–8 时同样静默返回 0。成功时信息结构给出像素、宽高与“32 bpp”标志，`0x1400325a0` 记录
+1040 = 1、+1044 文件名（64 字节）、+1144/+1148 宽高、+1152 alpha 标志、+1160 像素，并创建最多 128 块纹理（`0x1400301d0`），
纹理创建失败时弹窗。

Rust：`image::ImageArchives` 按上述顺序只读查找，归档按槽惰性打开、路径变化时重开，资源一律按 `PACK_DATA_CHECK=1`
校验（`Cpz6Index::read_entry_verified`）；`cpz::lookup_key` 与 `Cpz6Index::lookup` 实现大小写折叠与首个命中。
`image::decode` 只解码 PB3 type 1，其他已知格式与 type 2–8 显式报错；未知魔数与 type 不在 1–8 按原版静默失败，
结果槽 0 = 0、对象图像为空。`SceneHost::try_handle_image` 在完成命令前完成全部读取和解码，失败时不提交任何状态。
以下情况显式报错：未命中（原版弹模态框）、槽无效或无对象（未建模标志）、文件名 ≥ 64 字节（超出原版缓冲）。
纹理创建属于渲染后端，核心只保存解码后的 RGBA。
