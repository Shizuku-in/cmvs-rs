# 研究与验证约定

研究必须区分格式事实、某个二进制的指令语义和宿主预览策略。当前有完整证据档案的游戏只有[《アマツツミ》PC 样本](games/amatsutsumi/README.md)，[《クロノクロック》](games/chronoclock/README.md)只做了接入摸底；其[研究记录](games/amatsutsumi/research.md)与[VM 语义](games/amatsutsumi/vm-semantics.md)保留原始阶段说明。

## 证据与实现

- 每个地址绑定可执行文件 SHA-256、架构和 image base；不同游戏或不同更新版本重新确认，不能只因 opcode 相同就沿用结论。
- 指令记录包含参数来源、栈回收、返回标志、状态影响、失败行为和已验证范围。尚未确认或实现的指令显式报错。
- 平台无关语义留在 Rust 核心，原生系统接口留在后端。参考项目须记录固定提交与许可，不直接复制未明确授权的源码，见[参考与许可](references.md)。
- 测试仓库仅含合成数据。解码算法修改后，用仓库外真实样本与独立 Python 对照，并记录输入/输出哈希、对照范围与结果。
- 原游戏保持只读；保存实验使用游戏目录外的新文件或独立用户目录。原始素材、解包剧本、真实存档和 IDA 数据库不进入 Git。

## 新游戏接入

1. 在 `docs/games/<游戏标识>/` 建立档案，参考[模板](games/TEMPLATE.md)，在[游戏目录](games/README.md)登记。游戏标识使用稳定的小写 ASCII 名称。
2. 记录作品、版本/补丁、平台、架构、编码、二进制与关键输入哈希；不知道的字段写“未确认”。同款不同版本先在档案内分节，证据较多时再按版本建子目录。用 `cmvs-profile identify` 获取哈希、PE 时间戳、链接器版本与 switch 信息；共用已登记构建时只需添加游戏记录，新构建则用 `cmvs-profile table --base` 生成派生档案（命令默认 `unreviewed`），登记到 `crates/cmvs-core/profiles/`。见[引擎档案层](design/engine-profiles.md)。
3. 先核对容器签名、格式分支与脚本结构，再测试启动、标题、剧情、选择、片尾和保存/恢复。现有工具支持的格式之外保留明确错误，不跳过未知指令。
4. 分开报告结构检查、VM 记录重放、画面检查、原生窗口/音轨、存档和平台验证。记录运行参数、种子、帧时钟、输入存档身份及失败停点。
5. 把通用实现说明更新到架构、格式或后端文档；游戏专属差异和验证留在档案中。更新游戏当前状态后再同步项目首页的简要矩阵。

结构解码通过不等于运行通过；执行地址覆盖不等于条件边覆盖，也不等于游戏完成度。当前审计方法与可复用外部样本检查命令见[《アマツツミ》脚本审计](games/amatsutsumi/script-audit.md)。

## 检查

提交前执行 `cargo fmt --check`、`cargo test --offline`、`cargo clippy --offline --all-targets -- -D warnings`。涉及后端或 feature 时增加 [Workspace](workspace.md) 的全功能检查；默认忽略的外部样本和硬件测试需按验证目的显式执行，不能计为默认通过。
