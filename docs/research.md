## VM 行为，已由当前反编译交叉核对

- `0x0400`：跳转到后续 32 位立即数，**不是 NOP**。RxCMVS 旧笔记的标注不能直接采用。
- `0x0405`：取后续 16 位标签索引，再从标签表取目标 PC。
- `0x0410`：压入返回地址 PC+4，再调用指定标签。
- `0x0430`：将 32 位结果寄存器压栈，PC 增加 2。
- `0x0440/0x0442`：写入 PC+4 的立即值，按 PC+2 的 16 位数调整栈位置，PC 增加 8。
- `0x2000..0x27ff`：系统命令，传 opcode & 0x7ff；返回标志控制让出执行、前进 PC 和参数回收。
- 系统命令 0 返回 0xc000；主循环据其最高位让出执行，并按 0x4000 标志推进 PC。

以上是静态证据，尚无动态执行对照，不能声称 VM 已兼容。

## 正常入口启动配置进展

`cmvs-trace --bootstrap` 从原始入口执行，处理 25 次已确认的启动命令后，停在
PC=0x025a、系统命令 0x22b3，保留栈顶参数 10 和 SP=4。
到此执行了 117 条此前指令，待处理命令是第 118 次 step；16 条原始资源路径已注册。
此模式初始化了 65536 个位变量、2048 个整数槽、1024 个浮点槽和 64 个字符串槽，
整数表达式结果槽 4096 单独存在，因此已知整数数为 2049。

启动处理模块支持：

- 0x201d/e/f：保存原始配置值，分别对应原程序对象偏移 +1648、+12236，以及全局 setter 0x140008040。
- 0x2090：原对象 +12084 标志置 1；0x234d：子对象 +1532 标志置 1，setter 0x140055230。
  用命令 ID 记录这些字段，不推测所有业务名称，也不宣称渲染器已实现。
- 0x2091/92/93/94：位、整数、浮点、字符串区域填充。先验证完整范围与参数再修改；浮点保存原始位。
- 0x2010/11/12/13/14/19/1a：字符串引用 + 槽号，共 8 字节参数；注册原始相对路径。
- 0x2015/16：视频路径和存档路径后缀，仅一个字符串引用，回收 4 字节。

路径注册辅助函数 `0x1400285b0/0x140035b00/0x140037e90` 配置路径与读取器，
普通槽上界 4、图像槽上界 9；读取顺序和包内文件访问尚未接入。
研究模块保留游戏相对路径字节，不进行 Windows 根路径拼接，不访问或写入存档。

停止点 0x22b3 已核对处理函数 `0x14007c9e0` 及其调用的 `0x1400931a0/0x140092f50`：
它扫描存档头并更新 Windows 菜单状态，旧笔记命名为 sys_save_menu_create。
不能直接按无副作用命令跳过；后续需拆分存档数据与平台菜单显示。
