# 平台宿主与记录模式

> 本文描述已核对的实现分支，真实样本与历史验证来自[《アマツツミ》](../games/amatsutsumi/README.md)。其他游戏或引擎版本需单独验证；下文历史停点不代表最新完成度。

默认研究工具实现接口和记录后端；可选原生桌面实现见 `desktop.md`，不改变记录模式的含义。
只有显式传入 `cmvs-trace --record-platform <游戏根目录>` 才启用记录后端；默认仍停在平台请求处。
游戏文本保持原始字节，标题尚未进行 Shift-JIS/GBK 到平台字符串的编码选择。

| 命令 | 已核对地址及效果 | 研究实现 |
|---|---|---|
| 0x2160 | 0x140075260 → 0x140009480，复制标题、SetWindowTextA | 标题字节请求，回收 4 字节 |
| 0x2161 | 0x1400752a0，场景标题复制到 +14336，窗口文字为 +340 + `81 40` + 场景标题 | 组合标题请求，后端成功后才更新场景标题；回收 4 字节 |
| 0x2099 | 0x1400722e0 → 0x14008d5f0，选择/加载光标、替换窗口类光标 | 读取并解析登记 CUR，提交编号与位图；0 恢复默认 |
| 0x208f | 0x140072060 → 0x1400940b0，游戏根目录 + 文件名，LoadImageA/WM_SETICON | 校验 ICO 目录和条目范围，提交原始文件；像素及尺寸选择仍不解释 |
| 0x22b0 | 0x14007c950，SP-4 写 +11812，SP-8 写 +11816，两者非零则 +11808=1 | 保存缩略图宽/高及启用标志，不截图；回收 8 字节 |

除 0x22b0 外均返回 0x4004。0x2350 原先在此处理，现与 0x2351–0x2364 一起迁到平台无关的 `gesture` 模块（见 vm-semantics.md）。0x2099 初始化选择 0 来自 0x14008d540；
再次选择相同编号不重复读取文件或调用后端。原版对无效编号返回失败但调用方忽略，
研究实现选择明确报错、不消费参数，避免把错误资源当作成功。
标题上限 255 字节为研究策略；没有断言原程序的无界 lstrcpy 具有安全边界。
0x2161 在 128 字节栈缓冲中拼接，组合结果 ≥128 字节时研究实现报错；+340 未知（0x2160 尚未执行）时同样报错。
分隔符 `81 40` 是二进制里写死的字节，按 Shift-JIS 为全角空格；选用其他标题编码时按该编码解释，与原版依赖系统代码页的行为相同。
+14336 由构造函数 `0x140068580` 清零，因此场景标题初始为空。

`PlatformBackend::apply` 的 Ok 表示后端已应用请求，Err 要保持后端状态不变，供 VM 重试。
先验证参数、字符串引用及资源，再调用后端；后端拒绝时 PC、参数栈和宿主状态保持原值。
记录后端的应用效果是保留请求历史，**并非原生窗口操作的成功确认**。
历史最多 4096 条，保守计费的资源字节合计最多 64 MiB；即使共享 Arc 也按每次请求计费。

资源文件来源只读。当前适配器仅接受有限长 ASCII 相对路径，统一处理正/反斜杠；
拒绝空路径成分、`.`、`..`、盘符和解析到明确根目录外的路径，不使用包内名称自动写文件。
单个文件上限 4 MiB。文件错误或不支持的 CUR/ICO 结构中止命令；不模拟原版缺失图像的宽松失败。
其他编码路径、覆盖搜索顺序、运行时多分辨率选择尚未实现。

CUR 解码范围：一个目录条目、40 字节 BITMAPINFOHEADER、正高度、1 plane、8 bpp、BI_RGB，
1..256 项调色板，目录尺寸与 DIB 双倍高度一致。PNG、动画、多条目及其他位深明确报未支持。
两个平面按 DWORD 行对齐，磁盘自底向上，解码后自顶向下。
保留热点及每像素 AND 位和 RGB XOR 色值；合成公式为 `(背景 AND mask) XOR color`。
这保留了反色像素；不能直接把所有结果视为带透明度的 RGBA。
依据为 Microsoft [彩色图标格式说明](https://devblogs.microsoft.com/oldnewthing/20101019-00/?p=12503)
及 [Cursor 概述](https://learn.microsoft.com/en-us/windows/win32/menurc/about-cursors)，与本地真实文件核对。

本机记录模式使用已有 CSS1 数据，整数 2190 为 0，因此启动分支没有选择自定义光标。
四份 CUR 通过独立解码实验验证，0x2099 的读取/切换/失败重试用合成 VM 测试覆盖。
上述记录实验不能证明原生效果。随后加入的原生窗口、编码和输入观察已单独验证，见 `desktop.md`；CMVS 输入指令和场景渲染仍待实现。


## 窗口/全屏切换（2026-10-31）

0x2164 将SP-4的非零值解释为全屏，提交Fullscreen请求，后端成功后以0xc004完成命令（回收4字节、前进PC并让出）；不写结果寄存器。查询0x2163继续读取后端当前状态。记录后端保存实际模拟模式，重复请求仍被记录并让出。后端失败保留挂起命令、参数与结果。

桌面通过winit切换当前显示器的无边框全屏，退出后恢复窗口状态。此实现复用现有1280×720逻辑场景、比例适配和软件缓冲，不重建原版D3D设备，也不更改显示器独占分辨率。原生窗口系统可能异步落实请求，0x2163读取winit当时状态；不能把记录回归当成物理显示器验证。运行编排与trace均保留命令让出的帧边界。真实设置页的全屏/窗口点击经记录后端通过，原生切换仍待验证，见[游戏记录](../games/amatsutsumi/research.md#系统页窗口全屏切换2026-10-31)。


## 全屏比例模式（2026-10-31）

0x22fd 读取一个u32参数：0原尺寸（放不下则内接）、1等比内接、2等比外接裁切、3拉伸；大于3归1。与后端当前值相同时不发请求；否则发AspectMode请求，成功后0x4004完成，不让出且不写结果。0x22fc读取后端已选模式；记录后端也保存它。当前只有单显示器策略，没有原版按适配器保存的五组配置或配置落盘。

核心viewport模块按原版13位定点缩放生成目标矩形，正常居中使用非负偏移，外接使用有符号偏移和向零截断。软件绘制只遍历屏幕内的裁切区；鼠标输入和导航坐标变换复用这个矩形。极端尺寸、空尺寸或零宽高缩放结果显式报错，避免不受限循环。桌面只在全屏时应用选择模式，窗口模式保持内接；独立素材预览仍用既有draw_fit。普通游戏窗口也采用同一13位映射，与此前纯整数比例预览可能有一像素差异。

呈现默认最近邻采样与既有straight-alpha合成；绘制模式1改用软件双线性，见下节。不宣称复刻原版D3D纹理过滤。四种模式已通过合成像素/输入映射对照及真实设置页按钮重放；原生多显示器和物理全屏切换仍待验证。


## 窗口大小初始化（2026-10-31）

0x216e无参数：后端报告可调整且窗口尺寸偏离当前1280×720研究基准时请求恢复，成功返回0xc000并让出；尺寸已相同或不可调整时0x4000不让出，不写系统结果。记录窗口初始960×540与桌面初始预览一致。桌面用winit请求1280×720物理客户区，OS落实可能异步，未验证原生窗口尺寸和DPI表现。

原版全屏分支修改未来窗口尺寸而不立即调整屏幕；当前后端尚未建模该独立尺寸，全屏且需要重置时明确报错，保留挂起命令。此项不等同于整套设置重置或丢弃设置。


## 绘制模式与缩放滤镜（2026-10-31）

0x216d读取一个u32参数，按有符号解释，负数或≥4取0。平台无关核心的 `supported_render_mode` 复现原版能力回退：模式1要求后端报告线性放大（D3DCAPS9.StretchRectFilterCaps 的 MAGFLINEAR，独立于0x22c8的“点或线性”查询），模式2/3要求像素着色器主版本≥2/≥3，不满足即为0。着色器模式还依赖未建模的设备标志，能力足够的后端显式报错而非猜测。结果与后端当前值不同时提交RenderMode请求；成功后0x4004完成，不让出、不写结果；失败保留挂起命令、参数与结果。0x216c读取后端已选模式。

记录后端构造为0并保存请求；桌面后端将模式保存在窗口宿主，呈现时模式1使用 `RgbaImage::draw_scaled` 的双线性路径：按纹素中心映射、边缘夹取、8位权重，在预乘alpha上插值后与背景合成；模式0保持最近邻。窗口和全屏都经过同一缩放（原版 `0x14001db60` 对后处理对象传入同一设备字段，未按全屏区分）。这是软件滤镜，不宣称与D3D线性采样逐像素一致；两种后端都不报告像素着色器，模式2/3不可达。

启动时读取用户或游戏 `GRAPHIC_CONFIG/ASPECT_RATIO_FILTER`，原版保存字对0/1互换（0为线性），负数或≥4为点采样；桌面创建窗口后用同一能力回退得到实际模式，正常退出按同一互换写回用户配置。证据见[VM语义](../games/amatsutsumi/vm-semantics.md#系统页绘制模式2026-10-31)。


## 字体对话框（2026-10-31）

`PlatformBackend::choose_font(current)` 对应0x213d的模态对话框：参数与结果均为游戏编码的字体名，Ok(None)表示取消。默认实现报错。记录后端按 `answer_font_dialog` 预置的答案依次作答并记录每次初值，没有答案时报错。桌面后端把名称解码后以winit窗口的原始句柄调用 `cmvs_native::choose_font`，再转回游戏编码，并要求字体库能解析该面。Windows实现为 `ChooseFontW`（Shift-JIS脚本、无竖排、仅TrueType）；其他平台由 `cmvs-native` 返回 Unsupported，桌面代码不含平台条件。模态对话框在事件循环回调内运行，期间不推进VM。
