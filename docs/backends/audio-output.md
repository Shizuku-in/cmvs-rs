# 音频输出

`cmvs-audio` 提供流式解码、播放控制和可选原生设备输出。核心的 `AudioBackend` 定义契约；默认记录后端不打开设备。桌面启用 `audio-output` 并传入 `--audio native` 才实际发声，命令见[运行指南](../guides/running.md#音频与图形)。设备或解码失败会报错。

依赖与 feature 见 [`cmvs-audio`](../../crates/cmvs-audio/README.md) 和各包 `Cargo.toml`；浏览器输出见 [Web 后端](web.md#浏览器音频)。

## 通道与资源

| 类别 | 行为 |
|---|---|
| SE | 六个逻辑通道，分别准备、启动、停止和淡出；与剧情 SE 记录分开 |
| 语音 | 四个逻辑通道，可准备、播放、停止及淡出，不循环 |
| BGM | 两个通道处理切换和淡变；双文件循环先播放前奏一次，再循环第二段；不循环时只播第一段 |
| 影片 | 独立音轨通道，读取容器指定的音频范围；结束或销毁播放器时释放 |
| 独立设备槽 15 | 提供单独停止接口，不影响 SE、语音、BGM 或影片 |

资源按脚本登记的目录和归档查找，并验证归档校验值；不任意扫描备用目录。Vorbis 支持单 / 双声道和 8..192 kHz，拒绝中途改变格式的串联流。其他编码支持以解码器为准，未实现分支明确报错。

压缩输入合计最多 64 MiB，单个 PCM 包最多 65536 个样本。播放器保留压缩字节和当前包，不缓冲整段 PCM；循环时重建解码器。初次解码失败不替换活动通道，后续解码及设备错误由 `update` 报告。原生输出在增益前量化为饱和 i16 精度，检查工具可保留 f32 解码值。

## 设置与后端契约

启动时读取 `cmvs.cfg` 或 `cvns.cfg` 的 `SOUND_INFO`。运行时音量、声音开关及语音压低 BGM 立即作用于后端，持久化规则见[设置保存](desktop.md#设置保存)。

- 整组增益更新必须全部接受或保留旧状态，不重置播放位置、暂停状态或淡变包络。

- BGM 关闭时停止，重新开启后从记录的名称开始循环；SE 关闭释放设备，重开时重新准备命名音源，只启动仍标记播放中的循环声音。语音开关只限制后续请求。

- `configure_se` 先加载全部候选，成功后再替换；资源解码失败保留旧设备状态。

- `VoiceDucking` 独立维护压低、保持、等待和恢复系数，叠加到 BGM 基础增益及淡变包络。参数在空闲时生效，查询返回最新排队值；`VOICE_FADE_USE` 决定是否计入淡出中的语音。

- 切换音频后端前同步当前配置，失败保留旧后端。

语音速率在单声道且 1.1..=3.0 时通过 `VoiceCompressor` 压缩。解码和压缩按 `VoiceMixer::mono_request` 的块大小运行；块大小不代表设备缓冲或延迟。需要压缩但 `SOUND_BUFFER` 超出 0..3 时会报错。

## 时钟

`AudioBackend::movie_clock` 区分虚拟时钟、正在播放的绝对毫秒位置和结束。记录后端使用帧增量；原生后端使用源消费位置，不额外累加墙钟。时钟短暂滞后不回退画面，同一目标帧不重复解码，音轨结束后结束影片。

`se_position` / `voice_position` 返回播放中音源的毫秒位置；空槽、仅准备或已结束返回 `None`。`NativeAudio::bgm_position` 是两个 BGM 通道的只读诊断接口，不推进 VM、淡变或帧时间。

源消费位置不是声卡硬件时间戳，设备队列和重采样会引入误差；没有采样级同步或听感一致性的保证。淡变由宿主 `update` 推进，停止后已排队的短缓冲仍可能需要排空。

## 检查

`cmvs-audio` CLI 可在不打开设备的情况下检查音频并导出 PCM，见[CLI 指南](../guides/cli.md#归档与资源)。真实资源对照与设备消费的范围见[游戏档案](../games/README.md)。

有音频设备时，可显式执行合成播放检查：

```sh
cargo test --offline -p cmvs-audio --test audio_output native_device_smoke -- --ignored --exact --nocapture
```

Windows 受限沙箱曾触发原生无效句柄异常，相同构建在普通桌面权限下通过。该环境差异不表示解码失败；只检查画面时可显式选 `--audio record`。设备消费检查不替代人工听音或延迟测量。
