# PB3B type 1 无损图像与 type 3 JBP1

当前实现 type 1（24/32 位）与 type 3（JBP1，见文末“type 3”一节）；其他 codec 明确报未支持。差分底图（type 5/6）、type 2 和动画等不在本阶段范围。
参考固定 MIT 提交 a6bc9501d82264e228943f894af1b969ab98bee5 的 PB3B.cpp、CPB.cpp，
结合 research.md 指定哈希版本的 0x140036ae0、0x1400a0230 进行核对。

签名为 PB3B。头部 8..52 共 44 字节先与文件末尾 -3/-2 的两个字节交替 XOR，
再逐字节减去文件长度 -47 起的 44 字节（u8 wrapping）。
密钥取样区可以属于实际压缩数据，不把最后 47 字节另行剥离或当作校验和。
研究实现要求文件至少 99 字节，确保取样区不与变换头部重叠，输入最多 64 MiB。

| 解码后头部偏移 | 类型 | 用途 |
|---|---|---|
| 8 | u32 | 原始 field08，保留值，不推测业务含义 |
| 24 | u32 | type 1 方块边长，必须非零 |
| 28 | u16 | codec 类型 |
| 30 / 32 | u16 / u16 | 宽 / 高 |
| 34 | u16 | 位深 24 或 32 |
| 44 / 48 | u32 / u32 | 标记块区域 / 压缩字节区域的起点 |

图像尺寸必须非零，最终 RGBA 最多 64 MiB。两区域起点不得指入变换头部。
每区域首先是每通道一个 u32 长度的表，其后按 B、G、R、可选 A 顺序连接各通道块。
长度加法检查溢出，所有块必须落在输入内，标记区域不得重叠压缩区域。

每个标记块有三个 u32：分块标记字节数、常量块数量、LZSS 解压后字节数。
接着是分块标记、每个常量块的一个值、LZSS 标记流。
LZSS 数据流来自另一区域的对应通道块。标记按高位先行：1 为引用、0 为字面字节。
使用 2048 字节零初始化窗口，写入位置从 2014 开始；引用为小端 u16，
位置 `word >> 5`，长度 `(word & 31) + 3`，支持重叠与环绕。
不能复用 PS2A 的标记位序、写入起点或长度规则。

图像按块行优先、自顶向下处理，右/下边缘按实际剩余尺寸截取。
分块标记 1 表示以一个值填充整块，0 表示逐像素读取 LZSS 输出。
24 位补 alpha=255，最终把 BGR(A) 转为顶向下 RGBA。

研究实现明确拒绝：引用越过声明输出、标记或字节流截断、块值耗尽、未消费的块值、
多余的 LZSS 流字节、分块标记数与尺寸不符、单通道解压长度超过像素数量。
原版对坏数据的无界指针行为和全局字典旧内容不予模拟；这些限制不是对所有历史 PB3 变体的兼容承诺。
没有核对 PB3 校验和，也不把 CPZ6 解密后的结构解析描述为真实性校验。

`cmvs-pb3 <文件>` 输出结构元数据，可识别但不会假装解码未支持类型。
`--rgba <新文件>` 只在完整解码成功后创建输出并拒绝覆盖，不按图像内字段拼接写入路径。
默认核心不增加第三方依赖。

`raster::RgbaImage` 检查尺寸和字节长度，预览合成保留目标 letterbox，最近邻比例适配，
每通道按 `(src*a + dst*(255-a) + 127)/255` 计算。它只定义资源预览，不声明已匹配 CMVS 图层混合。

2026-10-27：开始游戏的真实路径首次需要 type 3——`bg.cpz` 的 `white.pb3`（1280×720、24 位）由 intcode.ps3 / 0x1a5a2 的 0x2030 载入；抽查同包 bg000a/bg010a/bg100a 亦为 type 3（1820×1024、24 位）。type 3 仍未实现。

## type 3：JBP1（2026-10-27）

证据绑定 research.md 所列 `cmvs64.exe` SHA-256，只读 IDA 静态核对；参考 MIT 固定提交 a6bc9501 的 PB3B.cpp（type 2/3 共用 Decode3）与 JBP1.cpp 作格式定位，未复制源码，常数与运算宽度以本作二进制为准。

- 分发：`0x140036ae0` 对 type 2/3 调用 `0x1400a0700`。它以 `0x1400b4020` 解码文件偏移 52 起的 JBP1 流，得到宽高各向上对齐到 16 的 32 位缓冲；宽度不是 16 的倍数时按行把 BGR 裁回 PB3 宽度；24 位 alpha 全部置 255，32 位从 PB3 头 +44 偏移读取 alpha 游程：0x00/0xff 后跟 1 字节重复次数，其他字节为单个值，原版不在最后一个像素处截断游程。type 2 与 type 3 走同一路径，但全包只有 1 个 type 2（32 位）且未验证，仍报未支持。
- JBP1 头（`0x1400a0ad0`）：`JBP1`；+4 表偏移（真实样本 44，PB3 内直接使用，不像 CMV6 再加 4）；+8 flags，bit 28–29 为子采样模式，模式 1（4:2:0，16×16 MCU）时宽高按 16 对齐；+16/+18 宽高（未对齐，须等于 PB3 头）；+20 位深 24；+28/+32 DC/AC 流字节数。本作 188 个样本 flags 均为 `0x58c00002`（另含 bit 27 显式量化表），Rust 只接受这一取值。
- 表区：16×u32 DC 频率、16×u32 AC 频率、16 字节零游程表（使用时 +1）、64 字节亮度与 64 字节色度量化表（自然序），其后紧接 DC 流与 AC 流；没有 JBPD 的纹理块布局与复用掩码。真实样本中 52 + 44 + 272 + DC + AC 恰为文件长度。
- 熵解码与 JBPD 相同（共用 `jbpd::Bits`/`Tree`）：位按 32 位字低位先取；频率树（`0x1400b3b40`）每次合并权重最小的两节点、序号小者优先并作 0 分支，排除 ≥ 2099999999 的权重；先解出全部 6 × MCU 数个 DC 差分并在整幅图累积（只用低 16 位）；每个 MCU 依次 4 个 Y、Cb、Cr 块，AC 符号 15 结束、0 读一元零游程选择器，其余按 `0x1400e4730`（即 JBPD zigzag 的第 1–63 项）写入未反量化的系数。
- IDCT（`0x1400b3c80`，以反汇编为准；反编译输出的若干 `__int16` 类型有误）：先按列，系数与量化值做 32 位乘积；某列第 1–7 行全零时整列填入第 0 行乘积的低 16 位；否则以常数 35467、50159、-121094、77062、-25570、-128553、-167963、-58980、98390、201373、134553、19571 做 `imul r32` 与 `sar 16`，全部 32 位回绕，仅写回截断为 16 位。再按行做同样的蝶形，结果 `sar 3` 后截断为 16 位。没有舍入偏置与电平偏移。
- 色彩：与 JBPD 相同的 91888、22544、46784、116112（32 位 `imul` 后 `sar 16`），亮度 + 384 加色度项作为 `0x1400e47b0` 768 字节表的下标：[0,256) → 0、[256,512) → 下标 - 256、[512,768) → 255，即 +128 后截断。下标越界时原版读取相邻数据，Rust 报错。色度 2×2 最近邻，输出 B、G、R。

Rust：`jbp1::decode` 输出对齐后的 BGR，`pb3::decode` 对 type 3 裁剪、补 alpha 并转为顶向下 RGBA；`image::decode` 现接受 type 1 与 3。研究上限、流范围、频率溢出、零游程越界、截断表越界、JBP1 与 PB3 尺寸不符、alpha 游程越过最后像素均显式报错。

验证：
- 全部 13 个 CPZ 包的 PB3 统计：type 1 24 位 1092、32 位 91，type 2 32 位 1，**type 3 24 位 188**，type 5 32 位 643，type 6 32 位 11786。188 个 type 3 全部由 Rust 解码成功（release 约 8 秒），没有 32 位 type 3，故 alpha 游程只有合成测试。
- 仓库外独立 Python 实现（`work/jbp1_reference.py`，按原版结构：32 位字位读取、最小值选择建树、反编译变量流的 IDCT、实际 768 字节截断表、带填充缓冲后裁剪）与 Rust 对 13 个真实样本的完整 RGBA 逐字节一致，覆盖 1820×1024（宽度裁剪）、1536×1820（高度填充）、1280×720：bg.cpz 的 bg000a/bg000b/bg100a/bg260a/bg270b/bg320a/bg402a/bg402b/bg600b/bg940e/white 与 chip.cpz 的 mask001a/mask001c。部分 SHA-256：white `c1a278749cec50862b38ddd306291242df759ab458eaf3ba194604ac2756128a`、bg100a `1b3077d98b404654dd2c948d27883ed9795d52c08799d42a1ccc5689e3708b08`、bg402a `71a88365e9585401a13e2b6f29366856cf1ce4729a0e0051f450002a51840d0d`、mask001c `1751d87b95d99771765401702fd615207768666619a9c52f9cacb349185bbce7`。两个实现同出一人，R/B 顺序等共同假设另经导出 PNG 目视检查（bg100a 街景、bg402a 草地，颜色与边缘正常）。
- 合成测试：只含 DC 的四象限电平、单个水平系数（手算 IDCT 行 `[11, 9, 6, 2, -3, -7, -10, -11]`）、零游程选择位、20×10 的裁剪与填充、24 位 alpha 与 32 位 alpha 游程、flags/尺寸不符、截断表越界、流截断与零游程越界。
- 共用熵解码后，JBPD 回归：op.cmv 第 1000 帧 RGBA SHA-256 仍为 `ece6dcbe6d8365ef6356a69b83e8a76c9b437a191c248d15c9dba357cb289da0`。
