# Switch Homebrew（开发中）

实验性播放器，默认 deko3d GPU 合成，可切回软件渲染；支持游戏加载、文字、Vorbis 音频、手柄与触摸输入及核心存档路径。
未知游戏及未实现指令会报错。

## 构建

在仓库根目录执行（需要 Docker）：

```sh
docker build -t cmvs-switch-build platforms/switch
docker run --rm -v "$PWD:/src" -w /src cmvs-switch-build sh platforms/switch/scripts/build-player.sh
```

## 部署

将 `platforms/switch/build/cmvs-switch.nro` 放到 SD 卡 `switch/cmvs-rs/`，每个原始游戏目录放在同目录的
`games/<任意名称>/` 下；旧的单游戏目录 `game/` 仍然可用，列在最前。只有一个游戏时直接启动；多个时显示选择列表，
名称即目录名，选中后才识别游戏（识别需要读取并校验脚本与可执行文件）。上次启动的游戏记录在 `last-game.txt`，下次默认选中。
在游戏内长按 + 或游戏自身退出后回到列表；从 HOME 关闭则直接退出程序。
可选放入日文字体 `font.ttf`（字体索引 0）；缺省时使用系统共享字体（日/美/欧标准字库）。
通过 hbmenu 的应用接管模式启动。

可选 `renderer.txt` 选择渲染器：`gpu`（缺省）或 `cpu`（软件合成，旧路径）；其他内容报错。GPU 初始化或运行失败
直接报错写入 `error.log`，不自动换回 CPU。

用户数据位于 `users/<游戏标识>/`，运行错误（含脚本名、PC 与步数）写入 `error.log`，并显示错误页：
有游戏列表时 A 回到列表，+ 退出；只有一个游戏时 A / + 退出。窗口打开前、GPU 失败或字体不可用等无法绘制错误页时，
改用系统错误对话框（应用接管模式用应用版，其他模式用系统版；Ryujinx 只实现应用版），完整内容在“详情”中。
Rust panic 仍直接中止，但消息会写入 `error.log`。
存档时间与桌面、Android 一致按 UTC 记录。

## 操作

游戏动作仍由 `key.cfg` 决定；宿主只把按键映射到引擎输入码：

| 输入 | 引擎输入 |
|---|---|
| 左摇杆 | 移动指针（死区外二次曲线，满偏约 1.2 秒横穿画面） |
| 触摸 | 在画面内按下即为左键并移动指针；黑边起手、第二指不生效 |
| A / B | 鼠标左 / 右键 |
| 方向键 | 方向键（引擎按钮导航，可移动指针） |
| Y / X | Enter / Esc |
| ZR / ZL | Ctrl / Shift |
| L、R、右摇杆上下 | 滚轮上 / 下，按住 400 ms 后每 100 ms 重复 |
| 长按 + 1 秒 | 保存设置并退出（有多个游戏时回到列表） |

选择列表：方向键或摇杆上下移动（按住 400 ms 后连续移动），L / R 翻页，A 启动，+ 退出程序；
触摸点选一行，再点已选中的行启动。进入列表或游戏时仍按住的按键需先松开。

从 HOME 菜单关闭软件时，程序先保存设置再退出；若系统拒绝锁定退出（例如相册小程序模式），仍可能被直接终止。
切到 HOME 或覆盖层时输入取消、音频静音，引擎按游戏的后台绘制设置暂停。

## 实现说明

- 画面（GPU）：`runtime/gpu.c` 用 deko3d 执行与 cmvs-wgpu 相同的共享绘制队列，参数布局见
  `cmvs_core::scene_render::shader`；`runtime/shaders/*.glsl` 是 `scene.wgsl`/`present.wgsl` 的 GLSL 移植，
  构建时由 `uam` 编译嵌入 NRO。逻辑画布为 RGBA8，按显示设置缩放到 1280×720 交换链（双缓冲、垂直同步），
  主机十字光标画在交换链上，不进入设备读回。纹理按像素 SHA-256 与尺寸缓存，留存上限 128 MiB、LRU 淘汰，
  当前帧用到的纹理不淘汰；影片帧每帧直接上传，不进缓存。字形光栅化与影片解码仍在 CPU。
  每帧开始时等待上一帧 GPU 完成后回收命令与暂存内存，GPU 工作与下一段 VM 执行重叠；
  释放的纹理在 GPU 空闲后才回收内存。设备截图只在引擎请求时读回最近一次呈现的逻辑画布。
- 画面（CPU）：1280×720 RGBA 线性帧缓冲，核心 CPU 合成后按显示设置缩放。
- 加载提频：启动加载期间及 VM 连续运行 50 ms 未产出画面时请求 CPU 提频（FastLoad，CPU 1785 MHz；系统同时把 GPU
  降到最低频率），画面连续 500 ms 正常产出后恢复。只计 VM 时间，渲染、呈现、软键盘与后台空闲不计入，
  因此 GPU 降频不会让提频持续；失焦时不提频，退出时恢复常规频率。应用接管模式以外或 7.0.0 以前系统拒绝时不再尝试。
- 音频：`cmvs-audio` 的 `mixer` 模式（与桌面同一套声道逻辑，不含 cpal），专用线程在 CPU 核心 1
  上以 48 kHz 立体声、4×1024 帧缓冲写入 audout，最多约 85 ms 排队。
- `runtime/libc.c` 补上 libnx newlib 缺少、而 Rust std 线程与 `HashMap` 需要的 `sysconf`/`getrandom`。
- 输入策略位于 `player/src/controls.rs`，软键盘的编码转换位于 `player/src/text_input.rs`，
  均可在开发机上 `cargo test -p cmvs-switch`。

存档注释等文本输入使用系统软键盘，游戏标题与提示显示在键盘上方；上限沿用桌面宿主（字节上限折算为全角字数，最多 127 字）。
文字按 Shift-JIS 保存（cmvs-font 目前只渲染 Shift-JIS）：无法表示的字符会在键盘内提示并要求修改；
与原版一致，引擎只保留全角字符，全为半角时沿用原注释。键盘关闭时仍按住的按键在松开前不生效。

暂未接入字体选择对话框。

`scripts/build-smoke.sh` 另生成诊断程序 `cmvs-switch-smoke.nro`，可检查文件读取、
核心 SHA-256，并按 A 检查游戏初始化；保持原名放在同一 SD 卡目录。

## 测试状态

2026-11-06 在 Ryujinx 1.3.3（固件 22.5.0，主机模式）运行《アマツツミ》PC 版：启动、系统共享字体文字、
BGM、手柄操作、存档（含同槽覆盖、移动与特殊槽）及长按 + 退出保存设置通过，可正常游玩。
未验证：真机、触摸（需掌机模式）、软键盘（该作无存档注释）、HOME 关闭保存（Ryujinx 退出锁为空实现）。

2026-11-06 同环境以 GPU 渲染器（缺省）运行同作：画面方向、背景、立绘、半透明消息窗与文字正确，60 FPS 流畅游玩，
游玩中存档写入正常、日志无错误。未逐像素对比 CPU 输出；影片、遮罩过渡与世界公告板路径未专门检查，真机未验证。
